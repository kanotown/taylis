# Times フィードと `is:times` (L8、M61〜M62)

ROADMAP の L8 (LAB.md §B の「(L8)」の 2 行)。研究室の times (作業ログ、M24) が 20〜30 本になると、1 本ずつ開いて読むのは
つらい。参加している times のトップレベルの投稿を、新しい順に 1 本の流れで読めるようにする。あわせて、検索で times だけに
絞る `is:times` を足し、卒業した人の times も「引き継ぎの資料」として探せるようにする。

**状態**: §8 は全部推奨の案に決まった (2026-10-02)。M61 (サーバ、移行 0055、Desktop / Web §10) と M62 (iOS build 62 §11、Android §12) は完了 (2026-10-02)。

## 1. 方針

- **フィードは読むための画面**。投稿は今までどおり各 times で行う (フィードに入力欄は置かない)。返信 (スレッド)、
  リアクション、「チャンネルで開く」はフィードの行から行える。
- **対象**は自分が参加している times (`channels.times_owner_id` が入っているチャンネル) のタイムラインの行。
  times の「フォロー」は今までどおり参加 (join) のこと。新しいフォローの仕組みは作らない。
- **静かな未読 (SYNC_PROTOCOL §10.5) は変えない**。フィードを開いても既読位置は動かさない (§4)。
- **新しいイベントは足さない**。フィードの最初のページは REST で取り、その後は既存の `message.*` イベントで保つ
  (会話の最後のメッセージ M49 と同じ考え)。
- **プッシュは変えない**。

## 2. フィードに出すもの

1 件 = 1 つのメッセージ (`MessageOut` そのまま)。次の全部を満たすもの:

| 条件 | 理由 |
|---|---|
| 自分が会員のチャンネルで、`times_owner_id IS NOT NULL` | 参加 = フォロー。ゲストも同じ規則 (会員のチャンネルだけ) |
| ミュートしていない (`muted(c)` が偽、§10.5 の定義) | ミュートは「見なくてよい」の意思表示。フィードから外す手段を別に作らない (§8 の 2) |
| タイムラインの行 (`parent_id IS NULL OR also_in_channel`) | チャンネルで見えるものと同じ。スレッドだけの返信は親の「返信 N 件」で見せる |
| 消されていない、`type = user` | 参加・退出などの system の行は出さない。ボット (定期投稿) は `type = user` なので出る |
| アーカイブされた times も含む | 卒業した人の times (L7 でアーカイブ) に会員のまま残っている人は、古い投稿を遡れる。新着は来ないので邪魔にならない |

自分の times の投稿も出す (研究室全体の流れとして読むため。決めてほしいこと 1)。

並びは `(created_at DESC, id DESC)`。seq はチャンネルごとの番号なので、チャンネルをまたぐ並びには使えない
(`id` は UUIDv7 で、同じ時刻の行の順を決める)。

## 3. API (`/api/v1`)

### `GET /times/feed?cursor=&limit=50`

- `limit` は 1〜100 (既定 50)。
- 応答 `TimesFeedOut = {items: MessageOut[], next_cursor: string | null}`。`next_cursor` は最後の行の
  `(created_at, id)` を表す不透明な文字列 (`<ISO 8601>_<uuid>`)。null は終わり。他の一覧 (`/bookmarks`、`/activity`) は
  時刻だけのカーソルだが、フィードは取り込み (Mattermost) で同じ時刻の行が並びうるので id も入れる。
- 返すのは §2 の行。`MessageOut` は会話の履歴と同じもの (リアクション、返信数、添付、回収 `collection` …) なので、
  クライアントは行をそのまま描ける。チャンネルと人は bootstrap で持っているもの (会員のチャンネルなので必ずある)。
- times に 1 本も参加していなければ `items = []`。

**クエリ** (LAB.md §5 の計測どおり): 会員の times の id を先に取り、**チャンネルごとに LATERAL で上位 `limit` 件**を取って
から混ぜ、上位 `limit` 件を返す。素直な `channel_id IN (...) ORDER BY created_at DESC LIMIT 50` は履歴に比例して遅い
(465k 件で 43 ms 対 0.95 ms)。

```sql
SELECT m.* FROM unnest(:channel_ids) AS c(id)
CROSS JOIN LATERAL (
  SELECT * FROM messages
  WHERE channel_id = c.id AND deleted_at IS NULL AND type = 'user'
    AND (parent_id IS NULL OR also_in_channel)
    AND (created_at, id) < (:cursor_at, :cursor_id)      -- 2 ページ目から
  ORDER BY created_at DESC, id DESC
  LIMIT :limit
) m
ORDER BY m.created_at DESC, m.id DESC
LIMIT :limit;
```

- 索引: 部分索引 `messages_timeline_created_idx ON messages (channel_id, created_at DESC, id DESC) WHERE deleted_at IS NULL
  AND (parent_id IS NULL OR also_in_channel)` (移行 0055)。無いと各チャンネルの読み取りが `messages_created_idx` を新しい側から
  辿って他のチャンネルの行を飛ばすので遅い。計測 (M61、19 万件のうち times 30 本 × 3,000 件、他 10 本 × 1 万件): 索引なし
  最初のページ 238 ms・深いページ 6.8 ms、索引あり 0.5 ms・0.6 ms。

## 4. 未読と既読

- フィードを開いても、スクロールしても、各 times の既読位置は**動かさない**。他人の times は静かな未読なので、残っていても
  太字にもバッジにもならない。自分の times に付いた他人のコメントは普通の未読のまま (会話を開いて読む)。
- 行の左に、その times の既読位置より新しい行 (`seq > last_read_seq`) だけ小さな点を付ける (「新しい」の目印)。
  クライアントが持っている既読位置から決める (サーバは何も足さない)。
- ホームのタイル「Times」(iOS / Android、Desktop の狭い画面) は、フィードの times (§2) のどれかに未読 (サーバの `unread_count`
  が 1 以上) があるときだけふつうに出し、無いときは 0 件のタイルと同じく薄くする (数は出さない。押せるのは同じ)。テスターの声
  「未読フィードがなくなったら明るくしておかなくてもよいかも」(2026-10-09)。Desktop のサイドバーの「フィード」の行は前から既読の
  チャンネルの行と同じ見た目なので変えない。
- フィードの見出しに「すべて既読にする」を置く (§8 の 3)。既存の `POST /channels/read-all` (M12a) に
  本文 `{"scope": "times"}` を足し、フィードの対象 (§2 の会員でミュートしていない times) だけを末尾まで既読にする。
  本文が無ければ今までどおり全部。応答とイベント (`read.updated`、reason = advance) は今と同じ。

## 5. クライアントでの保ち方 (3 端末共通)

```
開いたとき / 再接続のあと / 引っ張って更新:
    GET /times/feed (cursor なし) で置き換える
下端に近づいたら:
    next_cursor があれば次のページを足す (同じ id は足さない)
on message.created (m):
    if feedVisible and isFeedRow(m): 先頭側の並びの位置に入れる (created_at, id の順)
on message.updated / message.deleted (m):
    同じ id の行があれば置き換える。消されたら外す
on channel の変化 (退出、ミュート、times の解除、参加):
    退出・ミュート・解除: その channel_id の行を外す。参加・ミュート解除: 次に開いたときの取り直しで入る

isFeedRow(m) = m.type == user and not deleted and (m.parent_id == null or m.also_in_channel)
               and channel(m).times_owner_id != null and 会員 and not muted(channel(m))
```

- フィードの行は会話の履歴 (500 件の上限、§7.7) とは別に持つ。端末のローカルストアには保存しない (開いたら取り直す。
  オフラインでは「オフラインです」と、最後に開いたときの行をメモリにあれば出す)。
- 見ていない間 (`feedVisible` でない) はイベントで行を足さない。次に開いたときに取り直す。

## 6. 検索の `is:times`

- `is:times` (別名 `is:time`) を `is:thread` と同じ並びで受け付ける (`search/query.py` の `IS_ALIASES`)。ほかの条件と
  組み合わせられる (`is:times from:@sato 実験`、`is:times is:thread`)。
- 範囲は **times のチャンネル**に絞る:
  - 会員の times (アーカイブ済みも)。
  - **会員でない公開の times も入れる** (§8 の 4)。今の検索は会員のチャンネルだけだが、`is:times` のときだけ
    広げる。新しく入った学生が、参加していない先輩・卒業生の作業ログを「引き継ぎの資料」として探せるようにするため。
    ゲストは広げない (M13e: 会員でない公開チャンネルは見えない)。非公開の times は会員のときだけ。
  - `in:#times-sato` と一緒なら、そのチャンネルが上の範囲にあれば絞り込み、無ければ今までどおり解決できない修飾子
    (`unresolved`) として何も返さない。
- 応答 `SearchFilters.is_times: bool` を足し、クエリのパラメータ `is_times` (チップ用、`is_thread` と同じ形) も受ける。
- 応答 `SearchOut.channels: ChannelOut[]` に、結果のうち会員でないチャンネル (`membership = null`) を入れる。アーカイブ済みの
  公開 times は bootstrap に無いので、クライアントはここから名前を出し、開くときに使う。
- `is:times` と `channel_id` (チャンネルの中の検索) を一緒に使い、そのチャンネルが範囲外 (times でない) なら何も返さない。
- キャンバスの検索では `is:times` は使えない (`is:thread` と同じく `unresolved` で返す)。
- 会員でない公開チャンネルの検索結果を開くと、参加前のプレビュー (M27) になる。
- クライアント: 検索のチップに「Times」を足す (今の「スレッド内」の隣)。入力が空のときの候補に「is:times」を足す。
  iOS の説明文 (SearchView.swift の「語の中で from:@名前 …」) に `is:times` を足す。

## 7. 画面

| 場所 | Desktop / Web | iOS / Android |
|---|---|---|
| 入口 | サイドバーの「Times」節の最初の行「フィード」(節を畳んでいても見出しの右にアイコン)。狭い画面 (ホームの画面) はタイルの「Times」 | ホームのタイルに「Times」(スレッドの次)。「Times」節の見出しの右にも「フィード」 |
| フィード | 中央に一覧。行 = アバター・名前・**times の名前** (押すとそのチャンネル)・時刻・本文・添付・リアクション・「返信 N 件」。押すとスレッド (返信があれば) かチャンネルのその行へ | 同じ行を縦に。行を押すとチャンネルのその行へ、「返信 N 件」でスレッドへ |
| 見出し | 「Times フィード」、「すべて既読にする」、「自分の times に書く」(無ければ「自分の times を作る」) | 同じ (⋯ の中) |

- 行の見た目は会話の行に合わせる (「連続した投稿をまとめる」M47 はフィードでは使わず、毎行に名前と times の名前を出す)。
  times の名前は、その人の表示名と同じなら「times」とだけ出すと短いが、今は `times-<username>` をそのまま出す。
- 行の長押し / ホバーの操作は、会話の行と同じもの (リアクション、スレッドで返信、保存、リンクをコピー …) から、
  その場で使えないもの (編集は自分の行だけ、など) を除く。
- 並びはサーバの順 (新しいものが上)。会話の画面と違い、上下を反転しない (読み物として上から読む)。

## 10. 実装で決めたこと (M61 Desktop / Web)

- **持ち方**: フィードの行はエンジンの `TimesFeedHub` (`apps/desktop/src/sync/timesFeed.ts`) がメモリにだけ持つ (ストアにも
  SQLite にも入れない)。規則 (並び・isFeedRow・ページの継ぎ足し・イベントの反映・外す) は純粋な関数にしてテストした。画面が開くと
  1 ページ目を読み直し (読み込み中にすぐ閉じて開き直したとき (StrictMode) は 1 回だけ)、再接続でも開いていれば読み直す。下端に
  近づくと `next_cursor` で次を足す (同じ id は新しい方の `updated_seq` を残す)。見えていない間は新しい行を足さないが、持っている行の
  編集・削除・リアクション・返信数は反映し続ける (オフラインで開いたときに古い内容を出さないため)。
- **イベント**: `message.*` はタイムラインの扱い (同期済みか、穴があるか) と関係なく、エンジンが先にフィードへ渡す。自分の
  リアクション・ピン・削除の応答もストアの `upsertMessage` からフィードへ届く (`Store.onMessageStored`)。返信の `parent_thread` で
  親の「N 件の返信」を更新する。手元より古い行は、まだ次のページがあるときは差し込まない (そのページが持ってくる)。
- **外す**: 退出・削除されたチャンネルはエンジンの `removeChannel` で、ミュート・times でなくなった・会員でなくなったものは開いて
  いる間ストアの変化ごとに見直して外す。ミュート解除・参加は次に開いたときの取り直しで入る (§5 のとおり)。
- **行**: 会話の行 (`MessageRow`) をそのまま使い、`feed` で名前の後に `#times-xxx` (押すとそのチャンネル)、時刻を「今日 14:05」
  のように日付付きで、既読位置より後の他人の行に小さな点を出す。行を押す (マウスでも) とそのチャンネルのその行へ (`revealFromList`)、
  「N 件の返信」と「スレッドで返信」はフィードの横 (狭い画面は上) にスレッドを開く。フィードの中では「編集」(その場の編集は会話の
  入力欄が要る) と「ここから未読にする」を出さない。リアクション・保存・リンクをコピー・共有・リマインド・ピン・削除は会話と同じ。
  スレッドの親がストアに無いときは、スレッドの欄がフィードの行を親に使う。
- **見出し**: 「Times フィード」、再読み込み、「すべて既読にする」(`read-all` の `scope: times`、確認なし。フィードの times に未読も
  点も無いときは押せない)、「自分の times に書く」(無ければ「自分の times を作る」= `ensureTimes` して開く。ゲストには出さない)。
  狭い画面ではボタンをアイコンだけにする。
- **入口**: サイドバーの Times 節の最初の行「フィード」(節を畳むと隠れる。フィードを開いている間は残す) と、見出しの右のアイコン
  (畳んでいても使える)。狭い画面はホームのタイル「Times」(「スレッド」の次)。
- **検索**: チップ「Times」(「スレッド内」の隣、`is_times`)、空の入力欄の候補の最後に「is:times」、入力欄の説明に `is:times`。
  会員でないチャンネルの結果は `SearchOut.channels` から名前を出し、「未参加」(アーカイブ済みなら「未参加・アーカイブ済み」) の印を
  付ける。開くときにそのチャンネルをストアに (非会員として) 入れてから開くので、M27 のプレビューになる。
- **v0.1.15 レビューの修正 (Desktop / Web)**:
  - #2: 最初のページも次のページも、当てる直前に今の会員・times・ミュートの状態で絞り直す (持っている行も一緒に)。読み込み中に
    `removeChannel` したチャンネルは、そのとき飛んでいる読み込みの行を当てない。
  - #3: ページの読み込み中に届いたイベント (作成・編集・削除・親の `parent_thread`) は退避し、ページを当てた後に `updated_seq`
    順に当て直す。削除した id は削除の `updated_seq` と一緒に覚え (サインアウトまで)、それ以下の版をページや遅れたイベントから
    戻さない。最初のページの読み直しでも、持っている行のほうが新しければそれを残す。
  - #4: ストアに入るメッセージ (差分で回復した行、自分の投稿・編集・リアクション等の応答) は `Store.onMessageStored` の 1 本の
    経路でフィードに届く。ストアが持っていなかった行は `created` として扱うので、穴の差分で回復した新着もフィードの並びに入る。
  - #10: フィードのマージでも本人用の poll の値 (`mine` / `my_answers` / `my_comment`) を会話のストアと同じ規則 (SYNC_PROTOCOL §8)
    で残し、自分の投票・回答の応答は `Store.onMyVotes` (setMyVotes) で版に関係なくフィードの行にも入れる。
  - #13: チャンネルにも送った返信の行を押すと、スレッドではなくチャンネルのその行へ (`feedRevealTarget` で parent を外す)。
    「N 件の返信」「スレッドに返信」はスレッドを開く。あわせて、フィードから開いたスレッドの欄が裏で開いていた会話のチャンネルを
    使っていた不具合を直した (返信の送り先も行のチャンネルになる)。
  - #14: 並びは created_at をマイクロ秒まで比べる (UTC に直した秒 + 9 桁の小数の固定長の文字列キー `feedTimeKey`)。サーバの
    `(created_at DESC, id DESC)` と同じで、ページ境界の判定も同じ比較を使う。

## 11. 実装で決めたこと (M62 iOS)

- **入口**: ホームのタイル「Times」(スレッドの次、数字なし) と、「Times」節の見出しの右の「フィード」(節を畳んでいても出す)。
  どちらもホームのスタックに `TimesFeedView` を積む。
- **行**: 会話の行 (`MessageRow`) をそのまま使い、上に times の名前 (押すとその times) を付ける。まとめ (M47) はしない。
  行を押すとチャンネルのその行へ (チャンネルにも送った返信はスレッドではなくチャンネルの行へ)、「N 件の返信」と長押しの
  「スレッドで返信」はフィードの上にスレッドを積む。長押しの操作は会話と同じシート (「ここから未読にする」だけ無い)。
  `MessageRow` に `onTap` (行のタップをスレッドの代わりにする) を足した。
- **新しい点**: `seq > last_read_seq` の行の左に小さな点。自分の投稿には付けない (他の端末から送った直後、`read.updated` が届くまで
  点が出ないように)。開いても既読は送らない。
- **保ち方**: 行は `AppController.timesFeed` (ワークスペースごと、メモリだけ)。`SyncEngine.onTimelineMessage` で
  `message.*` を全部受け、編集・削除は見ていなくても持っている行に当てる。新しい行を足すのはフィードがどれかのタブの
  スタックにある間だけ (スレッドを上に積んでいる間も含む)。最初のページの読み込み中に届いた投稿は、読み込みの後にもう一度足す
  (ページが投稿より前に読まれた場合に消えないように)。
- **取り直し**: 開いたとき (上に積んだスレッドから戻ったときは取り直さない。読み進めたページを捨てないため)、再接続のあと、
  引っ張って更新。下端の行が見えたら次のページ。読み込みに失敗しても持っている行は残し、オフラインのときは上に
  「オフラインです。最後に読み込んだ投稿を表示しています。」。
- **退出・ミュート**: フィードの対象のチャンネルの組が変わったら、対象でなくなったチャンネルの行を外す。
- **⋯**: 「すべて既読にする」は確認のあと `read-all` (`scope: times`)、応答はホームの「すべて既読」と同じく read.updated と
  同じ扱いで当てる。「自分の times に書く」は自分の times を開いて入力欄にフォーカス。参加していなければ「自分の times を作る」
  (`POST /times`、ゲストには出さない)。
- **空のとき**: 対象の times が無ければ §7 の文 (最初の文を見出しに)。対象はあるが投稿が無いときは「まだ投稿がありません」。
- **検索**: チップ「Times」(スレッド内の隣、ファイル・キャンバスのタブでは出さない)、候補「Times の投稿 (is:times)」、説明文に
  `is:times`。会員でないチャンネルの結果には「未参加」を付け、名前は `SearchOut.channels` から (アーカイブ済みは「(アーカイブ済み)」)。
  押すと検索を閉じてプレビュー (M27) をその行の周りで開く (ストアに無いチャンネルは `SearchOut.channels` の行を会員でないとして
  入れてから)。最近の検索は `isTimes` も覚える。
- **テスト**: `TimesFeedTests` (行の条件、並び、ページ、ライブ、退出・ミュート、点、API の形、検索)、`TimesFeedSnapshotTests`、
  `LiveBackendTests.testTimesFeed` (実サーバ: ライブで先頭に入る、`is:times`、`scope: times`)。ビルド 62。
- **v0.1.15 レビューの修正 (iOS)**:
  - ページ (最初・次) は届いた時点の会員・times・ミュートで絞ってから入れる。退出・除外の前に読んだページから行が戻らない (#2)。
    画面を開いたときにも対象外のチャンネルの行を外す。
  - 読み込み中 (最初・次) に届いた変更 (作成・編集・削除・親の返信数・自分の投票) は全部とっておき、ページを入れた後に
    updated_seq の順でもう一度当てる。読み込み中に消えた行はページの古い版から戻らない (#3)。

## 12. 実装で決めたこと (M62 Android)

- **行は会話の行 (`MessageRow`) をそのまま使う**: 名前の横に times の名前 (`#times-…`)、アバターの左に「新しい」の点の欄 (12 dp)。
  行を押すと `revealMessage` でチャンネルのその行へ、「N 件の返信」と長押しの「スレッドで返信」はスレッドへ。長押しの操作は会話と
  同じ (編集・削除は自分の行 / admin)。アーカイブ済みの times の行は読むだけ (長押し・リアクションなし)。まとめ (M47) はしない。
- **点** は `seq > max(last_read_seq, 未送信の既読位置)`。「すべて既読にする」は確認のダイアログ (ホームの ⋯ と同じ) のあと
  `read-all {scope: times}`、応答で点が消える。
- **行の持ち場所**: `AppController.timesFeedState` (メモリだけ、ワークスペースの切り替えで捨てる)。行から会話を開いて戻ると前の行が
  すぐ出て、取り直しで置き換わる。スクロール位置は MainScreen の `LazyListState` で保つ。
- **ライブの行**: エンジンに `timelineEvents` (SharedFlow、再生なし) を足し、フィードの画面が出ている間だけ集める。返信の
  `parent_thread` で親の返信数も動かす。古い `updated_seq` の版では置き換えない。退出・ミュート・times の解除は store の変化
  (`version`) のたびに `pruned` で外す。
- **読み直し**: 画面を開いたとき、接続が戻ったとき (ONLINE になるたび)、引っ張って更新。続きは末尾の行が組み立てられたとき
  (失敗したら「続きを読み込めませんでした」で再試行)。最初のページの後から届いた古いページの答えは捨てる。
- **空のとき**: 参加している (ミュートしていない) times が無ければ §7 の文言、あるのに投稿が無ければ「まだ投稿はありません」。
  まだ一度も読めていなくてオフラインなら「オフラインです」。
- **⋯**: 「すべて既読にする」と、自分の times があれば「自分の times に書く」(開いて入力欄にカーソル)、無ければ (ゲスト以外)
  「自分の times を作る」(`POST /times` のあと同じ)。
- **検索**: チップ「Times」(スレッド内の隣)、空の入力の候補「Times の投稿 (is:times)」、条件の説明に「Times」。`SearchOut.channels`
  は結果の行の名前に使い、開くときは store に無ければ会員でないチャンネルとして入れてからプレビュー (M27) を開く。古いサーバの
  答え (`channels` / `is_times` が無い) も読める。
- **レビュー v0.1.15 の修正 (Android)**:
  - 最初と次のページは、入れる時点の会員・times・ミュートで絞る (取得中に退出・除外・ミュートした times の行は戻らない)。
  - ページ取得中に届いたイベント (作成・編集・削除・親の `parent_thread`) は `journal` に取り、ページを入れた後に `updated_seq`
    順で当て直す。取得中に消えた行 (トゥームストーン) は古いページから戻らず、新着・編集も消えない。
  - store が受け取った確定行 (差分同期で回復した行、自分の操作の REST 応答、投票の応答、親の返信数) も `Store.onTimelineRow`
    → `timelineEvents` でフィードに届く。読み込み済みの範囲より古い行は、続きのページがある間は入れない。`tryEmit` が
    バッファ満杯で失敗したら `timelineStale` が進み、表示中のフィードは読み直す。

    版に関係なくフィードの行にも入る。
  - スレッドの親は store・threads 一覧・messageFocus に無ければフィードの行、それも無ければ id で取得する (also_in_channel の
    返信から開いたとき)。親があるので thread state を読め、既読も確定できる。
  - チャンネルにも送った返信の行本体を押すと、チャンネルのその行へ (スレッドは開かない)。「N 件の返信」/「スレッドで返信」は親の
    スレッド。
