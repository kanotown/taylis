# リンクのカード（M185）

Slack のように、本文の中の**このサーバのメッセージのリンク**（`<server>/m/<id>`）を、リンク先のメッセージの抜粋のカードにする。
あわせて、メッセージを送った人（と管理者）が、そのメッセージのカード（メッセージのカードと M11g の外部のリンクのカード）を
**全員の画面から消せる**ようにする。利用者の要望：2026-11-05。

関連：IMPLEMENTATION_PLAN.md「M11g」「M185」、DATA_MODEL.md「messages」（`hidden_previews`）・「link_previews」、SECURITY.md §3.2・§14、
SYNC_PROTOCOL.md §6（`message.updated` の change `previews`）、`apps/shared/link-cards.json`（3 端末とサーバで同じケース）。
外部のリンクの取得（Open Graph、SSRF の対策）は今までどおり（SECURITY.md §14）。ドライブのリンク（`/d/`）のカードは DRIVE.md §13.1。

## 1. 全体

```
本文：「前の話 https://chat.example.com/m/0190… と https://example.com/page」
  │
  ├ メッセージのカード（M185）── POST /messages/previews {ids} ─→ 読む人の権限で ok / deleted / unavailable
  │     作者のアイコンと名前・#チャンネル（DM の相手、「#x のスレッド」）・日時・最初の数行・写真
  │     押すとそのメッセージを開く（今のパーマリンクの動作）
  │
  └ 外部のリンクのカード（M11g）── GET /link-previews?url= ─→ サイト名・題名・説明・画像
  
送った人（と管理者）：カードの × → PUT /messages/{id}/previews/hidden {url, hidden: true}
  → messages.hidden_previews にリンクのキー、新しい seq、message.updated（change "previews"）→ 全員の端末からカードが消える
```

- メッセージのカードは**読む人ごと**に作る。リンク先を読めない人には「表示できないメッセージ」だけを出し、作者・会話・本文・
  写真・存在するかどうかも出さない（DRIVE.md §13.1 の「表示できないファイル」と同じ考え方）。リンクを送っても権限は変わらない。
- サーバは本文を解釈しない（DATA_MODEL.md「本文の形式」）。どのリンクをカードにするかは端末が決め（§2）、サーバは聞かれた id に
  答えるだけ。カードの削除だけはサーバが本文のリンクを確かめる（§4.2）。

## 2. どのリンクがカードになるか（3 端末で同じ）

ケースは `apps/shared/link-cards.json` の `cards`（Desktop / Web は `tests/messageLinkCards.test.tsx` が読む。iOS・Android も読むこと）。

1. **本文のリンク**：本文の字句解析が読むリンクを順に（2026-11-05 から。Desktop / Web `links.ts` `bodyLinks`、iOS・Android
   `Links.all` は字句解析のリンクの字句を集める）。`[表示名](URL)` の URL と、むき出しの URL を `apps/shared/inline-format.json`
   の規則で：空白・`<` `>`・全角や CJK の記号（、。「」（）など）の手前まで、末尾の `.` `,` `:` `;` `!` `?` `'` `"` `…` と URL の中で
   開いていない `)` `]` は含めない、`/m/` などこのサーバの形のリンクは UUID の後に `/` `?` `#` が無ければそこまで。コード
   （```` ``` ```` のブロックと `` ` `` の中）と強調（`**…**` など）の中はリンクでない。本文でチップになるリンクとカードのリンクが
   いつも同じになる。以前（M11g〜）は `https?://[^\s<>)\]]+` から末尾の `.,!?;:。、」』）` を落としただけで、「「…/m/<id>」を見て」
   「…/m/<id>を見て」は `」を見て` まで含んだ壊れた URL の外部のカードになり、メッセージのカードにならなかった（2026-11-05、
   SYNC_PROTOCOL.md §7.10）。`body_keys` のケースで 3 端末とサーバが同じキーを確かめる。
2. **メッセージのカード**：ログインしているサーバの `/m/<uuid>`（パーマリンクの判定と同じ：サーバのアドレスと `/m/` は大文字・小文字を
   区別しない、`?`・`#` 以降は無視、id は小文字にする）。**同じメッセージは 1 枚**、**そのメッセージ自身は除く**、本文の順に
   **最大 3 枚**（Slack は数を決めていないが、長い列は読みにくい。4 つ目以降のリンクは本文のチップのまま）。カードの URL は、
   そのメッセージへの最初のリンク（消すときに送る、§4）。ほかのサーバのパーマリンクはふつうの外部のリンク。
3. **外部のカード（M11g）**：メッセージのリンクでもドライブのリンク（`/d/`、自分のカードがある）でもない**最初のリンク 1 つ**。
   通話を知らせるメッセージ（`message.call` がある、M117）には出さない。AI のボットの投稿は自動で取らない（AI.md §4、
   「プレビューを表示」）のまま。
   - **M11g からの変更**：以前は「本文の最初のリンク。それがパーマリンクかドライブのリンクならカード無し」だった。今は
     パーマリンク・ドライブのリンクを飛ばして次のリンクのカードを出す（メッセージのカードと外部のカードが並ぶ）。
4. **消したカード**：`MessageOut.hidden_previews` にそのリンクのキー（§4.1）があるカードは出さない。**次のリンクを繰り上げない**
   （4 つ目のメッセージや 2 つ目の外部のリンクがカードにならない）。消したものの代わりが勝手に出ると、消した意味がないため。
5. **並び**：添付の下に、メッセージのカード（本文の順）→ 外部のカード。本文の中のリンク自体は今までどおり（メッセージのリンクは
   「メッセージを表示」のチップ）。
6. **出す画面**：メッセージの行を描くところ（タイムライン・スレッド・参加前のプレビュー・Times のフィード）。検索結果・
   一覧の 1 行・通知・入力欄のプレビューには出さない。送信中（`pending`）の行にも出さない。

## 3. メッセージのカードの API

### 3.1 `POST /api/v1/messages/previews`

```jsonc
// 要求
{ "ids": ["0190…", "0190…"] }           // 1〜20 個（MESSAGE_PREVIEW_BATCH）。範囲外・UUID でないものは 422
// 応答 200
{ "items": [MessagePreviewOut, …] }      // 重複を除いた id ごとに 1 つ、聞いた順
```

- 認証が要る（ほかの API と同じ）。ユーザーごとに 1 分 120 回（`MESSAGE_PREVIEW_RATE_LIMIT_PER_USER`、`429 rate_limited`、
  `Retry-After`）。データベースだけを読み、外へは接続しない。
- クエリの数は id の数によらず一定（メッセージ・チャンネル・自分のメンバーシップ・必要なら参加前のプレビューの設定・添付）。

### 3.2 読める規則と返すもの

**読める**は `GET /messages/{id}` と同じ規則（`channels.require_readable`）：その会話のメンバー、または公開チャンネルで
ゲストでない人（参加前のプレビュー M27。管理者が M88 の設定で切っていれば不可）。

| 場合 | `state` | ほかの項目 |
| --- | --- | --- |
| 読める | `ok` | すべて |
| 読める会話のメッセージで、削除された | `deleted` | なし |
| それ以外（存在しない・ほかのサーバの id・メンバーでない非公開チャンネル / DM / グループ DM・抜けた非公開チャンネル・ゲストの未参加の公開チャンネル・プレビューが切られた未参加の公開チャンネル） | `unavailable` | なし（すべて null / 空） |

- アーカイブされた会話も読める人には `ok`（読むだけの会話）。スレッドの返信は会話の規則で決まり、`parent_id` が付く。
  管理者も特別扱いしない（メンバーでない非公開チャンネル・DM は `unavailable`）。
- 削除されたメッセージは、読める人にだけ `deleted` と言う（読めない人には、削除されたことも存在したことも言わない）。

`MessagePreviewOut`（`ok` のときだけ埋まる）：

| 項目 | 内容 |
| --- | --- |
| `id`、`state` | 聞いた id と上の状態 |
| `channel_id`、`channel_type` | 会話（`public` / `private` / `dm` / `group_dm`） |
| `channel_name` | 公開・非公開チャンネルの名前。DM・グループ DM は null（読める人はメンバーなので、端末の会話の一覧から相手の名前を出す） |
| `parent_id` | スレッドの返信なら親の id（カードは「#x のスレッド」） |
| `sender_id`、`created_at`、`edited_at` | 作者と日時（作者の名前とアイコンは端末のユーザーの一覧から） |
| `excerpt`、`excerpt_truncated` | 本文の先頭を**書いたまま**（軽量 markdown とメンションのトークン `<@uuid>` を残す）。最大 6 行・300 文字、メンションのトークンの途中では切らない。何か落としたら `excerpt_truncated` |
| `attachment_count`、`attachment_types` | 添付の数と content type（最大 10。本文の無いメッセージの「画像を送信」などの言葉に） |
| `thumbnail_attachment_id` | 最初の写真（`has_thumbnail`）か動画のポスター（`has_poster`）。投稿のファイル（CF1）でドライブの別の場所・ゴミ箱に移したものは除く（読む人に 404 になるため）。`GET /attachments/{id}/thumbnail` で読む |

- **新しく見せるものは無い**：`ok` の中身は、同じ人が `GET /messages/{id}`・`GET /channels/{id}` で見られるものの一部。
  `unavailable` はどの理由でも同じ形なので、id を並べても存在や会話を推測できない。
- 抜粋はメンションのトークンのまま返し、端末が自分のユーザーの一覧で名前にする（ゲストに見えない人は「@メンバー」。
  一覧の 1 行と同じ）。

### 3.3 端末のキャッシュと読み直し（Desktop / Web の実装）

- カードが画面の 1 画面以内に来たら聞く（M11g のカードと同じ。「最初の未読へ」で数百行が足されても全部は聞かない）。
- 30 ms の間に聞かれた id を 1 つの要求にまとめ、20 件ずつ送る。
- 答えはセッションの中で id ごとに持つ。5 分たった答えは、次にカードを描くとき読み直す（その間は古いカードのまま）。
  失敗（429・オフライン）は 1 分は聞き直さず、カードを出さない（本文のリンクのチップからは開ける）。
- **手元にあるメッセージは手元の行で描く**：リンク先の会話を読み込んでいて、その行が端末にあれば、本文・添付・削除は手元の
  行から（編集・削除がすぐカードに出る）。それ以外の編集は次に読み直したとき。ライブの同期はこれ以上しない。
- ブロックした人（MODERATION.md §4）のメッセージのカードは、名前・アイコン・本文・写真を出さず「ブロック中のユーザーのメッセージ」。

## 4. プレビューを削除する

### 4.1 キー

`messages.hidden_previews text[]`（移行 0131）に、消したカードのリンクの**キー**を持つ（URL ごと。メッセージにリンクが 2 つあれば
片方だけ消せる）。キーは文字列だけで作る（パーセントの復号・IDN の変換はしない。Swift・Kotlin・TypeScript・Python で同じ結果に
なるように）：

1. 前後の空白を除き、`^(https?)://([^/?#\s]+)([^#\s]*)(#\S*)?$` に合わなければキー無し（http(s) 以外、空白入り）。
2. スキームとホスト（ポートを含む）を小文字に、フラグメント（`#…`）を落とし、パスが空（または `?` から始まる）なら `/` を前に足す。
   パスとクエリは書いたまま。

例：`HTTPS://Example.COM/Path?Q=1#frag` → `https://example.com/Path?Q=1`、`http://example.com` → `http://example.com/`。
ケースは `apps/shared/link-cards.json` の `keys`（サーバの `link_cards.preview_key` も同じものを通す）。
端末は「カードのリンクのキーが `hidden_previews` にあるか」で消したかを決める。

**リンクの読み方の変更とキー（2026-11-05、移行 0132）**：§2 1. の読み方が変わると、同じリンクのキーが変わることがある
（`「https://example.com/a」を見て` は `https://example.com/a」を見て` から `https://example.com/a` に、Wikipedia の
`Foo_(bar)` は `…Foo_(bar` から `…Foo_(bar)` に）。それまでに消したカードがまた出ないよう、移行 0132 が保存されたキーを
書き換える：今の読み方のキーでなく、本文のどれかのリンクの以前の読み方のキーであるものを、同じリンクの今のキーに置き換え
（重複はまとめ、合うリンクの無いキーはそのまま）、変わったメッセージは編集と同じく新しい `updated_seq` を取る（チャンネルの
`last_seq` を 1 つ進める。イベントは出さないが、差分の同期で全端末が行を読み直す）。ケースは `link-cards.json` の
`legacy_keys`（`tests/test_hidden_preview_keys_migration.py`）。戻しても書き換えたキーはそのまま（以前のサーバでも、ふつうの
リンクのキーは同じ）。

### 4.2 `PUT /api/v1/messages/{id}/previews/hidden`

```jsonc
// 要求
{ "url": "https://example.com/page", "hidden": true }   // url は本文に書かれたリンク（8〜2048 文字）。false で戻す
// 応答 200：MessageOut（hidden_previews が変わった後）
```

| 確かめること | だめなとき |
| --- | --- |
| メッセージがある（削除されていない） | `404 message_not_found` |
| 会話のメンバー | `403 not_a_member` |
| 会話がアーカイブされていない | `409 channel_archived` |
| 人のメッセージ（参加・退出の行でない） | `400 system_message_readonly` |
| 送った人、または管理者（`channels.moderate`。削除と同じ） | `403 not_message_owner` |
| `hidden: true` のとき、`url` のキーが本文のリンクのキーのどれか（コードの中を含めて広めに見る：本文のすべての `http(s)://` から、§2 1. の今の読み方と 2026-11-05 より前の読み方（末尾の句読点の有無も）の両方。`link_cards.link_keys`） | `400 preview_not_in_message`（http(s) でないものも） |

- **冪等**：もう消えているものを消す・出ているものを戻すのは何も変えない（200、seq も進まずイベントも出ない）。
- 変わったときは、チャンネルの seq を 1 つ取り（`allocate_seq`、チャンネルの行のロック）、`updated_seq` を新しい seq にし、`message.updated`
  （change `"previews"`、メッセージ全体）を会話に出す。差分の同期（`/sync`）も新しい行を返すので、イベントを取りこぼした端末も揃う。
- 本文に無くなったリンクのキーは、消す・戻すときと**編集のとき**に落とす（編集でリンクを消して後で戻せば、新しいカードとして出る）。
  よって配列は本文のリンクの数より大きくならない。削除したメッセージの `hidden_previews` は空。
- ほかの人（送った人でも管理者でもない人）は消せない。自分の画面だけで畳む機能も作らない（Slack と同じ）。

### 4.3 端末の操作

- Desktop / Web：消せる人（自分のメッセージか管理者、参加前のプレビューでない、送信済み）には、カードの右上に × を出す（マウスなら
  カードに乗ったときとフォーカス、タッチの画面ではいつも）。押すとすぐ消し（確認なし）、トーストに「プレビューを削除しました」と
  「元に戻す」（`hidden: false`）。応答の行（新しい `updated_seq`）で自分の行を置き換え、ほかの端末と人には `message.updated` で届く。
- メッセージのカードの「表示できないメッセージ」「削除されたメッセージ」も消せる。

## 5. カードの見た目（Desktop / Web）

- 細い枠（`border-line`、角丸）だけの引用のようなカード。太い色の線を左に付けない（2026-09-30 のテスターの指摘と同じ）。
  幅は外部のカードと同じ（最大 36rem）。
- 1 行目：作者のアイコン（18 px）・名前（太字）・会話（`#general`、DM の相手、「#general のスレッド」）・日時（「今日 10:24」）。
  2 行目から：抜粋を 1 行ずつプレーンテキストにして（記号を落とし、メンションは名前、絵文字は絵文字に）空行を除き、最大 4 行
  （超えれば「…」）。本文が無ければ「画像を送信」などの言葉。写真があれば右に 56 px の正方形。
- 押す（Enter）とメッセージを開く（今のパーマリンクの動作 `openPermalink`。会話を開いてその行を中央に、スレッドならスレッドで）。
- 読み込み中：同じ枠に「メッセージを読み込み中…」。読めない：鍵のアイコンと「表示できないメッセージ」、その下に
  「このメッセージを見る権限が無いか、見つかりません。」（押せない）。削除：ゴミ箱のアイコンと「削除されたメッセージ」。
- 文言は ja / en / zh-Hans（`linkCards.*`）。

## 6. 互換

- 古い端末：`hidden_previews` を知らないので、消された外部のカードも出し続ける（メッセージのカードはそもそも出さない）。
  古い端末から消すことはできない。
- 古いサーバ：`POST /messages/previews` が 404 / 405 → 端末は失敗と同じ扱い（カードを出さない）。`MessageOut` に
  `hidden_previews` が無ければ空とみなす。消す操作は 404 / 405 のエラーになる。
- 移行 0131 を戻すと列が消える（消したカードがまた出る。前のサーバの動きのまま）。
- 2026-11-05 より前の読み方の端末（カードは未リリースだったので開発版だけ）：以前のキーで消しても、サーバはそのキーも本文の
  キーとして受け付ける（§4.2）。今の端末から見るとそのカードは消えていない（移行 0132 は移行のときにあったキーだけを書き換える）。

## 8. iOS / Android が実装すること

サーバと Desktop / Web は M185 で済んだ。スマホは次をそろえる（API は `openapi/openapi.json` の `MessagePreviewsIn` /
`MessagePreviewsOut` / `MessagePreviewOut` / `PreviewHiddenIn` と `MessageOut.hidden_previews`）。

1. **モデル**：`MessageOut.hidden_previews: [String]`（無ければ空、端末の DB にも持つ）。`MessagePreviewOut`（§3.2 の表。`ok`
   以外は id と state だけを信じる）。`message.updated` の change `"previews"` は特別な処理をせず、ほかの change と同じに行を
   置き換えるだけでよい（新しい `updated_seq`）。
2. **どのカードか**：§2 の規則を 1 つの関数に（`cardLinks(body, baseUrl, selfId, hidden, call)` → メッセージのカード
   `[(id, url)]` 最大 3 と外部のリンク 1 つ）。リンクの検出は §2 1.（2026-11-05 から字句解析のリンク）、パーマリンクの判定は今の `/m/` のもの。
   キーは §4.1。`apps/shared/link-cards.json` の `keys` と `cards` を単体テストで全部通すこと。
3. **聞き方**：カードが画面に近づいたら id を聞く。少し（30 ms 程度）まとめて `POST /messages/previews`、20 件ずつ。答えは id ごとに
   セッションの中で持ち（iOS は M11g のカードのように端末の DB に置いてもよい）、5 分で古い扱い、失敗は 1 分あけてから。
   429 は失敗と同じ。カードは中身によらず同じくらいの高さの枠を先に出し、行の高さが後から大きく変わらないようにする
   （iOS の M11g のカードの注意、DATA_MODEL.md「link_previews」）。
4. **描き方**：§5 と同じ内容（アイコン・名前・会話・日時、抜粋は 1 行ずつ今の「1 行のプレビュー」の規則でプレーンテキストにし、
   メンションは名前、空行を除いて最大 4 行、写真のサムネイル）。DM の名前は自分の会話の一覧から、無ければ「ダイレクト
   メッセージ」。スレッドの返信は「#x のスレッド」。ブロックした人は「ブロック中のユーザーのメッセージ」。読めない・削除・
   読み込み中は §5 の文言。太い色の線は付けない（薄い枠か淡い背景）。
5. **押したとき**：今のパーマリンクを開く動作をそのまま呼ぶ（会話・スレッドへ移って行を中央に）。読めないカードは押せない。
6. **手元の行**：リンク先の会話の行を端末が持っていれば、それで抜粋・写真・削除を描いてよい（Desktop と同じ。必須ではない）。
7. **消す**：自分のメッセージ（管理者ならどれでも）、送信済み、参加前のプレビューでないとき、カードの長押し（またはメッセージの
   長押しの操作に「プレビューを削除」。カードが複数あれば、押したカードの分だけ）で `PUT /messages/{id}/previews/hidden`
   `{url: カードのリンク, hidden: true}`。確認は出さず、バナー / スナックバーに「プレビューを削除しました」と「元に戻す」
   （`hidden: false`）。応答の `MessageOut` で行を置き換える。エラーは今のエラーの表示（`preview_not_in_message` も
   `apps/shared/errors.json` にある）。
8. **外部のカード（M11g）も同じ**：`hidden_previews` にキーがあれば出さず、同じ「プレビューを削除」で消せる。外部のカードは
   「最初のリンク」から「メッセージ・ドライブのリンクでない最初のリンク」に変わる（§2 の 3.）。
9. **文言**：「メッセージを開く」「メッセージを読み込み中…」「表示できないメッセージ」「このメッセージを見る権限が無いか、見つかりません。」
   「削除されたメッセージ」「{name} のスレッド」「ダイレクトメッセージ」「プレビューを削除」「プレビューを削除しました」「元に戻す」
   （en / zh-Hans は Desktop の `linkCards.*` に合わせる）。

### 8.1 iOS の実装（2026-11-05）

- **モデル**：`MessageOut` / `MessageState` の `hiddenPreviews`（無い・null は空。端末の DB の行（JSON）にも入り、M185 より前に
  保存した行は空）。`MessagePreviewOut` は `ok` 以外では id と state だけを読み（知らない state は `unavailable`）、id は小文字に
  する。`message.updated`（change `previews`）は今までどおり行を置き換えるだけ。
- **どのカードか**：`MessageLinkCards.of(body:base:selfId:hidden:call:)`（`UI/MessageLinkCards.swift`）。リンクの検出は M11g の
  `Links.all`、パーマリンクの判定は `Permalink.messageId`、キーは `MessageLinkCards.previewKey`。iOS は以前から、このサーバの
  キャンバス（`/c/`）・予定（`/e/`）・ページ（`/p/`）のリンクにも Open Graph のカードを出していなかったので、それらもドライブの
  リンクと同じく飛ばし、次のリンクを外部のカードにする（`link-cards.json` のケースには関係しない）。
- **聞き方**：`MessagePreviews`（アカウントの `Store` が持つ。このセッションだけで、端末の DB には置かない）。行が画面に来たとき
  （行の `.task`）に id を積み、30 ms 後に 20 件ずつ `POST /messages/previews`（1 つ終わってから次）。答えは 5 分は聞き直さず、
  その後は次に描くときに聞く（その間は前のカード）。失敗（429・オフライン・5xx）は 1 分聞き直さず、前の答えが無ければカードを
  出さない（本文のリンクのチップからは開ける）。
- **高さ**：カードはどの状態（読み込み中・読める・読めない・削除）でも「見出しの 1 行 + 本文 2 行」以上の枠（Dynamic Type の
  文字の大きさで決める）。答えが来ても行はほとんど伸びない（抜粋が 3〜4 行のときだけ伸びる）。1 行の状態（削除・読めない・
  読み込み中）は枠の中で上下の中央。写真は右に 56 pt の正方形（アルバムのサムネイルのキャッシュを使う）。
- **描き方**：細い枠（`separator` の 1 pt、角丸 8）だけで、左の色の線は付けない。見出しは 18 pt のアイコン・名前（太字）・会話・
  「今日 10:24」。抜粋は 1 行ずつ `Timeline.plainText`（一覧の 1 行と同じ規則）にし、メンションは名前、カスタム絵文字は画像、
  空行を除いて最大 4 行（超えれば「…」）。本文が無ければ「画像を 2 枚送信しました」など（`attachment_types` と `attachment_count`
  から）。リンク先の行を端末が持っていれば、その本文と添付で描く（編集がすぐ出る。削除は手元の行が消えるので、次に聞いたとき）。
  ブロックした人は名前・アイコン・本文・写真を出さず「ブロック中のユーザーのメッセージ」（会話と日時は出す）。
- **押したとき**：`AppController.openPermalink(id, from:)`（本文のリンクと同じ。行の `messageLinkContext` を渡す）。読めない・
  削除のカードはボタンにしない。
- **消す**：行の長押し（カードの上でも）で開くメッセージの操作に「プレビューを削除」。カードが 1 枚ならその行、複数ならどれかを
  選ぶメニュー（「名前 · #会話」、「表示できないメッセージ」、外部のカードは題名かホスト）。出ているカードだけを出す（失敗して
  出ていないもの・プレビューの無いリンクは出さない）。行の長押しが行全体を取るので、カードだけの長押しは作らない。VoiceOver は
  カードの操作「プレビューを削除」。確認は出さず、`PUT …/previews/hidden` の応答で行を置き換え、トーストに「プレビューを削除
  しました」と「元に戻す」（5 秒、`NoticeAction`）。エラーはいつものエラーのトースト。消せるのは自分のメッセージか管理者で、
  送信済み、参加前のプレビュー（`readOnly`）でないとき（`MessageLinkCards.canRemove`）。
- **文言**：Desktop の `linkCards.*` に合わせて Localizable.xcstrings に。「元に戻す」（Undo）と「ダイレクトメッセージ」
  （Direct message）は同じ日本語で別の訳（Reset、Direct messages）が既にあるので、キー付き（`linkCards.undo`、
  `linkCards.directMessage`）。
- **テスト**：`ChikuwaChatTests/MessageLinkCardsTests.swift`（`link-cards.json` の `keys` と `cards` の全ケース、`hidden_previews`
  のデコードと保存、`message.updated`（change `previews`）、まとめて聞くこと・5 分・1 分、抜粋・会話・日時・写真の規則、枠の高さ、
  消せる人、出ているカードの一覧、削除と「元に戻す」、エラー、ライトとダークのスナップショット）。

### 8.2 Android の実装（M185、2026-11-05）

- **モデル**：`MessageOut.hiddenPreviews` / `MessageState.hiddenPreviews`（Room は行を JSON で持つので、前からの行は空のまま読める）。
  `MessagePreviewOut` / `MessagePreviewsOut`、`ApiClient.messagePreviews` / `setPreviewHidden`。change `"previews"` は何もせず、
  今までどおり新しい `updated_seq` の行で置き換わる。
- **どのカードか**：`MessageCards.cardLinks`（`ui/MessageLinkCard.kt`）とキーの `MessageCards.previewKey`。リンクは `Links.all`
  （M11g の `Links.first` と同じ規則）。全角の空白など（`\p{Z}`）でもリンクが終わるようにした（JVM の `\s` は ASCII だけで、
  Web とサーバ（Unicode の `\s`）と違っていた。端末の ICU では前から Unicode）。
- **Android だけの違い**：このサーバの `/c/`（キャンバス。本文にカードがある、M58）・`/p/`・`/e/` のリンクにも、Android は前から
  外部のカードを出していなかった。M185 でもそれらは飛ばし、ドライブのリンクと同じに次のリンクが外部のカードになる。
- **聞き方**：`MessagePreviewHub`（`sync/MessagePreviews.kt`、`SyncEngine.messagePreviews`）。カードが組み立てられたとき
  （`LazyColumn` は画面の近くの行だけを組み立てる）に聞き、30 ms の間の id を 1 つの要求に、20 件ずつ。答えはセッションの中で
  5 分。失敗（429・オフライン・古いサーバ）は 1 分あけてから聞き直し、カードを出さない。読んであったカードは読み直しに失敗しても
  そのまま出し、1 分後にもう一度聞く（描くたびには聞かない）。
- **描き方**：1 dp の `outlineVariant` の枠（角丸 8 dp、最大幅 420 dp）。最小の高さ 64 dp の同じ枠を、読み込み中（「メッセージを
  読み込み中…」）・読めない（鍵と 2 行、押せない）・削除（ゴミ箱、押せない）にも使う。1 行目は 18 dp のアイコン・名前・会話・
  日時（`Timeline.stampLabel`、「今日 10:24」）、その下に抜粋（`EmojiLineText`、カスタム絵文字は画像、最大 4 行）と 56 dp の写真。
  本文が無ければ「画像を送信しました」など（`attachmentSummary`）。リンク先の会話の行を端末が持っていれば、その本文・添付で描く。
- **押す**：`controller.openPermalink(id, LocalMessageLinkContext)`（本文の「メッセージを表示」と同じ動作）。
- **消す**：カードの長押しはメッセージの長押しのシートを開き、その「プレビューを削除」はそのカードの分だけ。行の長押しでは
  画面に出ているカードごとに並べる（1 枚なら「プレビューを削除」、複数なら「プレビューを削除：名前」。名前は作者と会話、外部の
  カードはサイト名）。いきなり消さずにシートを挟むのは、長押しはリアクションなどにも使うため。TalkBack ではカードのカスタム
  操作「プレビューを削除」がすぐ消す。消すとスナックバーに「プレビューを削除しました」と「元に戻す」（`AppController.previewRemoved`、
  `MainScreen`）。消せるのは自分のメッセージか管理者、送信済み（`seq` あり）、`readOnly` でない行（参加前のプレビュー、
  アーカイブした Times のフィード）。
- **テスト**：`MessageLinkCardsTest`（`link-cards.json` の `keys` と `cards` の全ケース、全角の空白、`/c/`・`/p/`・`/e/`・`/d/` を
  飛ばすこと、抜粋の描き方、写真の選び方、会話の名前とシートの名前、`hidden_previews` の読み込み・Room の JSON・古い行、
  change `"previews"` で行が置き換わること、まとめて聞くこと・20 件ずつ・5 分・失敗の後の 1 分）。
