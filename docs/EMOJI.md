# カスタム絵文字: 文字の絵文字・横長の絵文字・絵文字のセット (M100)

利用者の要望 (2026-10-04) で M12f のカスタム絵文字 (DATA_MODEL.md `custom_emoji`) を広げた。

- **文字の絵文字**: 「ありがとうございます」「確認しました」のようなよく使うリアクションが、小さな正方形に文字を
  詰めた画像で読みにくい → 画像ではなく、短い文字を色付きのラベル (ピル) として描く絵文字の種類 `text`。
- **横長の絵文字**: 横長の画像が正方形に押し込まれて小さい → 高さは他の絵文字と同じ、幅は縦横比どおり (3:1 まで)。
- **絵文字のセット**: 利用者のオリジナルの絵文字 (LINE 絵文字の形式、180×180 の透過 PNG、40 個ずつ) を、
  ピッカーのタブ 1 つにまとめて入れる。日本語の検索語 (「ありがとう」で「おじぎ」が出る) を付ける。

ショートコードは今までどおり ASCII (`^[a-z0-9][a-z0-9_+-]{1,31}$`) のまま。IME なしで打て、Slack と同じで、
URL (`/messages/{id}/reactions/:name:`) にもそのまま入る。日本語は **表示名** (`label`) と **キーワード**
(`keywords`) に持つ。

## 1. 文字の絵文字 (`kind = "text"`)

- `POST /emoji/text {name, label, color?, keywords?}` (ゲスト以外の誰でも、画像の絵文字と同じ)。`label` は前後の
  空白を除き、改行などの空白は 1 つの空白にして 1〜12 文字 (制御文字は不可、`400 emoji_label_invalid`)。
- `color` は固定のパレットのキー: `gray` `red` `orange` `yellow` `green` `blue` `purple` `pink` (null = gray)。
  ライト / ダークそれぞれの背景と文字の色は `apps/shared/text-emoji.json` にあり、各クライアントはその写しを持つ
  (各クライアントのテストが共有ファイルと比べる)。
- 行の `content_type` は `""`、`width` / `height` は 0、`storage_key` は `""`。`GET /emoji/{id}/image` は 404。
- 描き方 (4 クライアント共通): 高さは同じ場所の画像の絵文字と同じ、幅は文字に合わせる (最小は正方形)。文字は
  高さの 0.68、左右の余白は高さの 0.28、角の丸みは高さの 0.3、太字。本文の中・リアクション・ピッカー・`:` の補完・
  ステータスのどこでも同じ。
  - Desktop / Web: `TextEmojiPill` (span、CSS 変数で色、ダークはテーマに従う)。
  - iOS / Android: ピルを画像に描いて (`CustomEmoji.textPill` / `TextEmojiPill.draw`) 画像の絵文字と同じキャッシュ
    (`emojiImages`) に入れる。画像を表示する既存の経路がそのままピルを表示する。ライト / ダークが変わったら
    描き直す (iOS: RootView の colorScheme、Android: MainActivity)。
- 古いクライアント (M100 より前) は `kind` を知らず画像を取りに行き 404 になる。そのときは `:name:` の文字で出る。

## 2. 横長の絵文字

- 画像の絵文字は最初 (M12f) から `width` / `height` をアップロード時に保存している (取り込みで縮めたものも縮めた
  後の大きさ)。**縦横比はそこから求める**ので、移行での埋め戻しも CLI (`backfill-emoji-sizes`) も要らない。
- 描く箱: 高さ = その場所の絵文字の高さ (本文 1.375em / 16pt、リアクション 16px など)、幅 = 高さ × 縦横比。
  縦横比は 1〜3 に丸める (縦長は正方形の箱に収め、4:1 より横長は 3:1 の箱に収める)。画像が来る前から同じ箱を
  取る (2026-10-04 のガタつきの修正と同じ規則: 置き場所の大きさは最初から決まっている)。
- ピッカーのマスは正方形のまま、画像を縮めて収める (`square`)。

## 3. 絵文字のセット (`emoji_packs`)

- 表 `emoji_packs (id, name 一意 64 文字まで, position, tab_content_type, tab_storage_key, created_by, created_at,
  updated_at)`。`custom_emoji.pack_id` (null = セットなし) と `custom_emoji.position` (セットの中の順)。
- タブのアイコンはオブジェクトストアの `emoji-packs/<pack id>/tab-<uuid>`。差し替えると鍵が変わり、
  `EmojiPackOut.tab_version` (鍵の最後の部分) も変わる。クライアントは `(id, tab_version)` でキャッシュする。
  `GET /emoji/packs/{id}/tab` (要ログイン)。アイコンがないセットはタブに最初の絵文字を出す。
- API (作成・変更・削除・取り込みは管理者だけ、監査ログ `emoji_pack.create / update / delete / import`):
  - `GET /emoji/packs` (bootstrap の `emoji_packs` にも)
  - `POST /emoji/packs {name}` (空のセット)、`PATCH /emoji/packs/{id} {name?, position?}`
  - `DELETE /emoji/packs/{id}`: **セットだけを消し、絵文字は残す** (セットなし = 「カスタム」のタブに移る)。
    本文やリアクションで使われている絵文字が消えないように。絵文字ごと消したいときは絵文字を個別に削除する。
  - `PATCH /emoji/{id} {label?, color?, keywords?, pack_id?, position?}`: 表示名・色・キーワードは作成者か管理者、
    セットと順番は管理者。
- イベント `emoji_pack.updated {pack, deleted}` (audience all)。セットを消したときは、そのセットの絵文字それぞれに
  `emoji.updated` (`pack_id: null`) も出る。
- ピッカー (4 クライアント): 「カスタム」のタブはセットなしの絵文字だけ。その後ろにセットごとのタブ (アイコン)。
  タブは 1 本のリストのセクションへ跳ぶ（§9）。
  セットのタブは絵が大きいので 1 マスを 2 倍にする (Desktop 4 列 56px、iOS 4 列 64pt、Android 2 マス分 64dp)。
  検索はすべての絵文字が対象。

## 4. セットの取り込み (`POST /emoji/packs/import`)

管理者が Desktop / Web の「管理」→「カスタム絵文字」→「セットを追加」で、フォルダか ZIP を選ぶ。

- フォルダ: フォルダの中の画像と `pack.json` を `files` (複数) で送る (ほかのファイル、例えば `タグ案.md` は送らない、
  送られても読まない)。ZIP: `archive` で送る。ZIP の中は直下でも 1 つのフォルダの中でもよく、ファイルは名前
  (パスの最後) で探す。`__MACOSX` とドットファイルは無視。
- `pack.json`:

  ```json
  {
    "name": "ドットはんぺん",
    "tab": "tab.png",
    "items": [
      {"file": "032_おじぎ.png", "shortcode": "hpd-bow", "label": "おじぎ", "keywords": ["ぺこり", "ありがとう"]}
    ]
  }
  ```

  ファイル名は NFC にそろえて比べる (macOS は日本語のファイル名を分解形 (NFD) で渡す)。
- 検査はアップロードと同じ: 画像は PNG / GIF / JPEG / WebP、`EMOJI_MAX_BYTES` (256 KB) 以下、512px 以下。
  `pack.json` は 1 MB まで、items は 300 個まで、ZIP は 1000 項目・展開後 64 MB まで、送信全体 64 MB まで
  （フォルダーはファイルの合計で数える。Caddy はこのパスだけ本文を 70 MB まで通す。レビュー v0.1.37 #8）。
- **全部か何もしないか**: 先に全部を検査し、どれか 1 つでも駄目なら何も書かない。
  - `400 emoji_pack_manifest_invalid` (pack.json がない・JSON でない・形が違う・ショートコードかファイルの重複)、
    `400 emoji_name_invalid` (ショートコードの形)、`400 emoji_pack_file_missing` (pack.json にあるファイルがない)、
    `400 emoji_not_image` / `emoji_too_big`、`413 emoji_too_large`、`400 emoji_pack_archive_invalid` (ZIP が読めない、
    同じ名前のファイルが 2 つ)。`details.file` に問題のファイル。
  - `409 emoji_name_taken`: ショートコードが **ほかの絵文字** (別のセットかセットなし) に使われている。
    `details.shortcodes` にその一覧。
- **やり直しても重複しない**: セットは名前で、絵文字はショートコードで探す。
  - セットがなければ作る (順番は最後)。あればそれを使う。
  - そのセットにすでにあるショートコードは表示名・キーワード・順番を pack.json に合わせる (**画像は差し替えない**)。
    ないものは追加する。pack.json から外れた絵文字は消さない (消すのは個別に)。
  - `tab` があればタブのアイコンを差し替える。
  - 結果 `{pack, created, updated, unchanged}` (ショートコードの一覧)。
- 取り込みの `emoji.updated` は追加・更新した絵文字ごとに 1 つ、`emoji_pack.updated` は 1 つ。

## 5. 検索と `:` の補完

- カスタム絵文字は名前・表示名・キーワードで探す。順位: 名前の前方一致 → 名前の部分一致 → 表示名 / キーワードの
  前方一致 → 部分一致 (同順位は名前順)。比べる前に NFKC・小文字にし、カタカナはひらがなにする
  (「アリガトウ」でも「ありがとう」が当たる)。標準の絵文字も日本語のキーワード (apps/shared/emoji.json) で当たる。
- `:` の補完は ASCII の 2 文字以上 (今まで) に加えて、`:` か `：` の後の日本語 1 文字以上 (`:ありがとう`、`：了解`)。
  `:` の前は行頭・空白・`(`・`（`・`「` のときだけ (「例：説明」では出ない)。
- サーバは検索をしない (表は bootstrap で全部クライアントにある)。キーワードは保存時に NFC・小文字・重複なしにし、
  20 個・1 つ 32 文字まで (`400 emoji_keywords_invalid`)。

## 7. 絵文字だけのメッセージを大きく (M101)

利用者の要望 (2026-10-04): Slack / LINE のように、絵文字やスタンプだけのメッセージは大きく出す。サーバの変更はない
(クライアントの表示だけ)。

### 7.1 判定 (4 クライアント共通、`apps/shared/emoji-only.json`)

1. 標準のショートコードを先に置き換える (`:tada:` → 🎉、apps/shared/emoji.json、本文を描くときと同じ)。
2. 文字をコードポイントで前から読む。
   - 空白 (U+0020・タブ・改行 (LF / CR)・U+00A0・全角の空白 U+3000) は区切り。前後の空白は無視。
   - `:name:` (名前は `^[a-z0-9][a-z0-9_+-]{1,31}$`) で **その端末が知っている** カスタム絵文字は 1 個。種類は
     `text` (文字の絵文字)、`pack` (セットに入っている画像の絵文字、`pack_id` あり)、`image` (それ以外の画像)。
   - キーキャップ (`[0-9#*]` FE0F? 20E3)、国旗 (地域指示子 1F1E6–1F1FF の 2 つ)、絵文字の並び (要素 (200D 要素)*)
     はそれぞれ 1 個 (`unicode`)。要素 = `pictographic` のコードポイント、FE0F?、肌の色 (1F3FB–1F3FF)?、1F3F4 の後
     ならタグ (E0020–E007E)* E007F。
   - それ以外 (普通の文字・Markdown の記号・メンション・知らない `:x:`・単独の肌の色や ZWJ) が 1 つでもあれば
     「絵文字だけ」ではない。
3. 1〜**23 個** (Slack と同じ上限) なら絵文字だけ。ちょうど 1 個で `pack` なら **スタンプ**。
4. `pictographic` は Unicode の Emoji 属性 (Unicode 17) から ASCII・地域指示子・肌の色・ZWJ / FE0F / 20E3 / タグを
   除き、1F000–1FAFF を丸ごと足したもの (まだ割り当てのない新しい絵文字もそこに来る)。★ (U+2605) や ♪ (U+266A)
   は Emoji ではないので文字のまま。© ® ™ のような Emoji 属性の記号は FE0F が無くても数える (単独で送られることは
   まず無いので割り切り)。
5. 各クライアントは `max_items`・`whitespace`・`pictographic` の写しを持ち、テストが共有ファイルと比べ、`cases`
   (52 件) を通す: Desktop `tests/emojiOnly.test.tsx`、iOS `CustomEmojiTests.testEmojiOnlyFollowsTheSharedCases`、
   Android `EmojiOnlyTest`。

### 7.2 大きさ

| | Desktop / Web (px) | iOS (pt) | Android |
|---|---|---|---|
| 標準の絵文字 (文字の大きさ) | 32 (行の高さ 40) | 30 | 30 sp |
| 画像の絵文字 (高さ) | 36 | 34 | 34 sp |
| 文字の絵文字 (ピルの高さ、文字はふだんの約 1.6 倍) | 32 | 26 | 32 sp |
| セットの絵文字 (2 個以上か、ほかの絵文字と一緒) | 64 | 64 | 64 sp |
| スタンプ (セットの絵文字 1 個だけ) | 120 | 120 | 120 dp |

- 横長の絵文字は高さが上のとおり、幅は高さ × 縦横比 (3:1 まで、§2 と同じ)。ピルの幅は文字に合わせる。
- 本文の 1.6 倍: ふだんのピルの文字は Desktop 約 13.6px (本文 14.5px の 1.375em × 0.68)、iOS 約 10.9pt (16pt × 0.68)、
  Android 約 13.6sp (16sp の 1.25em × 0.68)。Android の本文の中の絵文字は文字に合わせて sp、スタンプだけ dp。
- 箱は画像が来る前から同じ大きさで取る (ガタつかない、§2 と同じ規則)。大きい箱は行を高くしてよい (Desktop は
  `inline` の負のマージンを使わない、iOS / Android は行が箱に合わせて伸びる)。
- スタンプは吹き出しや枠を付けず、左寄せの絵だけ。アニメーションする絵文字は大きくても動く。
- iOS はセットの絵文字の画像を 60pt (3 倍の画面で 180px、LINE 形式の元の絵と同じ) でキャッシュする (ほかは 48pt の
  まま)。48pt では 120pt のスタンプがぼやけた。Android は元の画像をそのまま持つ。

### 7.3 どこで大きくするか

- 大きくするのはメッセージの行 (チャンネル・DM のタイムライン、スレッド、チャンネルのプレビュー、times の一覧) の
  本文だけ。Desktop `MessageRow` → `MessageBody jumbo`、iOS `MessageRow` → `MessageBodyView(jumbo: true)`、
  Android `MessageRow` → `MessageBody(jumbo = true)`。
- 大きくしないところ: 検索結果・メンション・アクティビティ・ピン留め・保存済み・通知・返信先の引用 (1 行の抜粋)・
  DM 一覧のプレビュー・入力欄のプレビュー・編集履歴・AI の答え・ワークフローのプレビュー (どれも `jumbo` を渡さない)。
- 編集済みのメッセージも同じ判定 (「(編集済み)」は見出しの行)。編集中は入力欄なので普通の大きさ。

## 8. サーバのフォルダから入れるプリセットのセット (M102)

利用者の決定 (2026-10-04): 利用者の 3 つのセット (§6) を、管理画面から 1 つずつ取り込むのではなく、サーバに置いた
フォルダから入れる。**絵はリポジトリに入れない** (フォルダはサーバにだけ置く)。

### 8.1 置き方と動き

- 設定 `EMOJI_PRESETS_DIR` (既定は空 = 使わない)。compose はアプリのコンテナに
  `${EMOJI_PRESETS_DIR_HOST:-./emoji-presets}` を `/presets` に読み取り専用でマウントし、`EMOJI_PRESETS_DIR=/presets`
  にする。フォルダが空なら何もしない。
- そのすぐ下の、`pack.json` があるフォルダそれぞれが 1 つのセット (中身は §4 の取り込みと同じ: `pack.json` と画像。
  ほかのファイルは読まない)。フォルダ名 (NFC) が **プリセットの鍵** (`emoji_packs.preset_key` / `custom_emoji.preset_key`)。
  ドットで始まるフォルダ、`pack.json` のないフォルダ、フォルダでないもの (`REVIEW.md`) は無視。100 フォルダまで。
- 取り込むのは **起動のたび** (アプリの起動を待たせない裏の処理) と、手で `python -m app.cli import-emoji-presets`
  (`--dir` で別のフォルダ、`--restore <フォルダ>` は下)。結果はログ (`emoji presets: Chikuwa: new pack, 40 added, …`)
  と CLI の出力。CLI の終了コードは 0 (問題なし)・1 (飛ばしたフォルダがある / 管理者がまだいない)・2 (ほかのプロセスが取り込み中)。
- 実行者はシステム: 監査ログ `emoji_pack.preset` (actor なし、フォルダ・追加・変更・差し替えの数)。行の `created_by`
  は最初の管理者 (有効な人を優先)。管理者がまだいなければ何もせず、次の起動か CLI で入る。
- 複数のアプリのプロセス: 全体を 1 つのトランザクションで行い、最初に `pg_try_advisory_xact_lock(hashtext('emoji_presets'))`
  を取る。取れなかったプロセスは何もしない (取ったほうが入れる)。

### 8.2 2 回目以降 (やり直しても重複しない)

- セットはプリセットの鍵で探し、なければ `pack.json` の名前で探す (前に管理画面から取り込んだ同じ名前のセットは
  **引き取る**: 鍵を付け、画像はそのまま、今のファイルのハッシュを覚える)。どちらもなければ作る (順番は最後)。
  `pack.json` の名前は新しく作るときだけ使う (管理者が付けた名前は戻さない)。
- 絵文字はショートコードで探す。表示名・キーワード・順番は `pack.json` に合わせる。新しい項目は足す。`pack.json`
  から外れた絵文字は消さない (§4 と同じ)。
- **画像**: ファイルの SHA-256 を `preset_hash` (タブは `emoji_packs.preset_tab_hash`) に覚え、変わったときだけ
  差し替える (新しい鍵 `emoji/<id>-<uuid>` に置き、確定してから古いものを消す)。絵を直したいときは、直したファイルを
  同じ名前で置き直して再起動 (か CLI) すればよい。§4 の取り込み (画面から) は今までどおり画像を差し替えない。
  クライアントは絵文字の画像を id で覚えているので、新しい絵はアプリを開き直したとき (HTTP のキャッシュは最大 1 日)
  に出る。
- 何も変わらなければ何も書かない (イベント・監査ログ・オブジェクトストアへの書き込みなし)。変わった絵文字ごとに
  `emoji.updated`、セットを作ったかタブが変わったら `emoji_pack.updated`。

### 8.3 管理者が消したものは戻さない

- 管理者がプリセットのセットを消す (`DELETE /emoji/packs/{id}`) と `emoji_preset_removals (preset_key, '')`、
  プリセットの絵文字を 1 つ消す (`DELETE /emoji/{id}`) と `(preset_key, shortcode)` が残り、次の起動ではそのセット
  (その絵文字) を入れない。セットを消しても絵文字は残る (§3)。
- 管理者がプリセットの絵文字を別のセットへ動かした・セットから外したときも、そのままにする。
- 戻したいとき (サーバで): `python -m app.cli import-emoji-presets --restore <フォルダ名>`。そのフォルダの記録を消して
  取り込む。セットは作り直され、残っていた絵文字 (セットなしになっていたもの) はそのセットに戻り、消した絵文字は
  画像から作り直す。

### 8.4 うまくいかないとき

- 1 つのフォルダの問題 (`pack.json` が読めない・形が違う、ファイルがない、画像が駄目、ショートコードの形) は、
  そのフォルダだけを飛ばして警告をログに出す (セーブポイントで巻き戻し、置いた画像も消す)。ほかのフォルダは入る。
  アプリの起動と `/readyz` には関係しない。検査と上限は §4 と同じ (画像 256 KB・512px、`pack.json` 1 MB、300 項目)。
- ショートコードがほかの絵文字 (手で追加したものや別のセット) に使われているときは、その 1 つだけを飛ばして警告する。
- オブジェクトストアが使えないとき (起動直後など) は、そのフォルダが失敗として飛ばされ、次の起動か CLI で入る。

### 8.5 置き場所

- 本番: `/srv/chikuwachat/infra/emoji-presets/<フォルダ>/` (deploy.sh と vps-bootstrap.sh が作る。リリースは中身に
  触らない)。送り方は infra/README.md「絵文字のセット (プリセット)」。バックアップには入れない (取り込んだ絵は
  オブジェクトストアと DB にある。元のフォルダは利用者の手元)。
- 開発: 手元の `/emoji` (git から除外) を使う。docs/DEVELOPMENT.md。

## 9. ピッカーは 1 本のリスト（2026-10-07）

利用者の報告（2026-10-07）：カテゴリのタブを切り替えると、前のタブのスクロール位置のまま次のタブが出て分かりにくい。
Slack と同じく、すべての絵文字を 1 本のリストにした。

- 並び：「最近使った絵文字」（あるときだけ）→「カスタム」（セットなし、文字の絵文字のピルが先）→ セットごと
  （§3、マスは 2 倍）→ 標準のカテゴリ（顔 … 旗）。タブも同じ順（最近は時計のアイコン、セットはアイコン）。
- 各セクションの見出し（カテゴリ名）は、そのセクションをスクロールしている間リストの上端に残る（次の見出しが押し出す）。
- タブを押すと、そのセクションの見出しがちょうどリストの上端に来る位置へ一気にスクロールする。押したタブはすぐ
  選択になり、途中で別のタブが光ることはない。
- 手でスクロールすると、選択のタブは上端にあるセクション（上端より上に始まった最後のセクション）に追従する。
- 開くたびに先頭（最近使った絵文字）から。検索中は今までどおり当たったものの平らな一覧（タブなし）。検索を消すと
  リストの先頭に戻る（元の位置には戻さない）。
- 「＋ 絵文字を追加…」は「カスタム」セクションの最後。

### 9.1 Desktop / Web

- `EmojiPicker`（`ui/EmojiPicker.tsx`）がスクロールするリストを 1 つ持ち、見出しは CSS の `position: sticky`。
  並び・位置からのセクション・チャンクの計算は `ui/emojiPickerLayout.ts`（テスト `emojiPickerScroll.test.tsx`）。
- 絵文字は約 1900 個、カスタム絵文字は数百になりうる（描くと画像を取りに行く）。グリッドを 6 行ずつのチャンクに
  分け、チャンクは最初から正確な高さ（行数 × マス）を取り、見えている所の前後 320px に入ったときに中身を描く
  （IntersectionObserver を 1 つ）。高さが変わらないので、描いてもリストは動かない。タブで遠くへ跳んだときは
  跳んだ先のチャンクを同じ更新で描く（1 フレーム空白にならない）。
- 選択のタブが変わってもセクションは描き直さない（memo、コールバックは固定）。
- 計測（Chrome、開発サーバのカスタム絵文字 約 600 個）：開く 15〜25ms（最初の 1 回は 40〜60ms）、先頭から最後まで
  スクロールして 60fps、50ms を超えるロングタスクなし。

### 9.2 Android

`EmojiPickerSheet`：すべての絵文字を 1 つの `LazyVerticalGrid`（8 列）に並べ、セクションの見出しは
`stickyHeader`（全幅、背景を塗って上に貼り付く）。並びは「よく使う」→「カスタム」→ セットごと → 標準のカテゴリ。
タブを押すとその見出しへ `scrollToItem` で飛ぶ（アニメーションなしなのでタブがちらつかない。押したタブは
一覧をドラッグするまで選ばれたまま：最後の方のセクションは見出しを一番上まで持ってこられないため）。
選ばれるタブは先頭に見えている項目のセクション（`derivedStateOf` + `EmojiPicker.sectionAt`、見出しの位置は
`EmojiPicker.headerIndices`）で、タブの列も選ばれたタブが見えるように横にスクロールする。
検索中は見出しのない平らなグリッド。開くたび・検索語を変えるたびに一番上から。項目は `key` と `contentType`
（見出し／標準／カスタム）付き、カスタム絵文字の画像はマスが見えたときに読み込む。

### 9.3 iOS

`EmojiPickerView`：`ScrollView` の中の `LazyVStack(pinnedViews: [.sectionHeaders])` に、セクションごとの `Section`
（見出しは背景を塗った 28pt）。並びとセクションの行は `EmojiPickerLayout.sections`（「よく使う」→「カスタム」→ セット
ごと → 標準のカテゴリ、空のセクションは出さない）。中身は 8 個ずつ（セットは 64pt を 4 個ずつ）の行、文字の絵文字は
ピルの 1 行。行の単位で遅延して作るので、開いたときに全部のマスを並べない。カスタム絵文字の画像はマスが現れたとき
（`onAppear`）に取りに行く。

- タブ：「よく使う」は時計のアイコン、セットはアイコン、ほかは名前。押すと `ScrollViewReader.scrollTo` で、
  セクションの先頭の 1pt の目印（id `top:<セクション>`）を見出しの高さだけ下に置く位置へアニメーションなしで飛ぶ。
  セクション自体の id（見出しを含むセクション全体）や高さ 0 のビューには scrollTo が効かない。
- 選ばれるタブ：各行の位置を PreferenceKey で集め、見出しの下に見えている最初の行のセクション
  （`EmojiPickerLayout.activeSection`、iOS 17 / 18 共通）。タブで飛んだ後は `EmojiPickerHighlight` が、着くまで
  途中のセクションを無視し、最後の方で見出しが上端まで来ないときは止まった所のセクションを離れるか手で
  スクロールするまで押したタブのまま。選ばれたタブはタブの列で中央に寄せる。
- 選択の状態は `@Observable` のモデルに置き、読むのはタブの列だけ。ピッカー本体（長いリスト）はセクションが
  変わっても作り直さない（作り直すとセクションの境で 30〜45ms のフレームが出た）。
- 計測（シミュレータ iPhone 17 Pro、Debug ビルド、カスタム絵文字 195 個とセット 1 つ）：開く約 0.13 秒、
  120pt ずつ一番下までスクロールして 1 ステップの中央値 11ms・95% 14ms・最大 21ms。
- VoiceOver：見出しは見出し、マスは `:shortcode:`（カスタムは表示名と `:name:`）、選ばれたタブは「選択」。
  リアクション・入力欄・ステータス・セクションの絵文字・自分の候補のどこでも同じピッカー。
