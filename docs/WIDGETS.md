# ウィジェット（iOS / Android）

ホーム画面から、アプリを開かずに見たり操作したりするためのもの。**在室状況**（2026-10-13）、**未読・メンション** と
**今日の予定・締切**（2026-10-14）の 3 つ（利用者の要望）。どれもサーバーの変更はない。

## 1. 在室状況のウィジェット

| | iOS（WidgetKit、iOS 17 以上） | Android（Jetpack Glance） |
| --- | --- | --- |
| 大きさ | 小・中。ロック画面の丸・四角・1 行（ボタンなし）。iOS 18 のコントロール（在室 / 帰宅の切り替え） | 2×1・2×2・4×1・4×2（ランチャーが伝える実際の大きさで選ぶ） |
| 出すもの | ワークスペース名、自分の状態（アプリと同じ色とアイコン）、「在室 n 人」 | 同じ |
| ボタン（小さいとき） | 1 つ：今が在室の種類なら最初の「帰宅」の種類へ、そうでなければ最初の「在室」の種類へ | 同じ |
| ボタン（広いとき） | 自分の状態の先頭 4 つ（アプリと同じ順） | 入るだけ。入らなければ種類ごとに 1 つ（在室・帰宅・学内・学外の順）、残りは順に |
| 本体を押す | アプリの「在室状況」を開く（`chikuwachat://attendance?server=…`。必要ならワークスペースを切り替える） | 同じ（そのワークスペースの在室状況） |

- **数え方・並び・色**：アプリのヘッダーのチップとボードと同じ規則（PRESENCE.md §7）。ゲスト・bot・停止中の人は数えない。
- **メモ**：ウィジェットはメモを書かない。今と同じ状態を押せばメモを残し、ほかの状態ではメモを消す（アプリの 1 タップと同じ）。
- **送り先**：`PUT /api/v1/attendance/me`（アプリと同じ）。押した直後に新しい状態を出し、失敗したら最後に確かめた状態に戻して
  「更新できません」（iOS はほかに「サインインし直してください」「変更できませんでした」）。在室状況がオフ・ゲストなら
  「在室状況はオフです」。
- **ワークスペース**（3 つとも、2026-10-14）：ウィジェットごとに選べる。既定は「アプリで開いているワークスペース」（アプリで開いて
  いるものに付いていく。この機能より前に置いたウィジェットもこれ）。iOS はウィジェットの「編集」（AppIntentConfiguration）、
  Android は置くときと長押しの「ウィジェットの設定」（`android:configure`、`reconfigurable|configuration_optional`）。
  選べるのはサインイン中のワークスペース。選んだものがサインアウトされたら「サインインしてください」を出す（iOS）／
  アプリに付いていく形に戻す（Android）。スナップショットはワークスペースごとに持ち、アプリで開いていない
  ワークスペースは、ウィジェットか定期の仕事がそのアカウントのトークンで読み直す（在室状況・今日は API、未読は
  `GET /sync/summary` の数だけ。会話の行は最後にアプリで開いたときのまま）。
- **見た目**（2026-10-14）：見出しはどれも同じ形（ワークスペースのアイコンか頭文字と名前）。在室状況は在室の人の顔を並べ、
  切り替えボタンは行き先の状態の色で塗る。未読は大きい数と「@n・DM n」、行に種類の印（#・相手の顔・人の印）。今日は
  カレンダーの色の縦棒とそろえた時刻、タスクはチェックボックス。iOS 18 の色付き・透明のホーム画面（`widgetAccentable`）、
  Android 12 以上の壁紙の色（Material You）とウィジェットの選択画面の見本（プレビュー）に対応。

## 2. 未読・メンションのウィジェット

- **数**：アプリのアイコンのバッジと同じ数（SYNC_PROTOCOL.md §10.5 の規則：チャンネルはメンション、DM は未読、ミュートは
  メンションだけ、他人の Times はメンションのときだけ。アーカイブ・抜けた会話は数えない。共通の見本
  `apps/shared/unread-rules.json` で確かめる）。iOS はアイコンと同じく、フォロー中のスレッドのメンションと鳴った
  リマインダーも足す（「スレッドなど n」）。
- **大きさ**：iOS は小・中・ロック画面、Android は 2×1〜4×2。小さいときは数と内訳（メンション・DM）、広いときは会話の行
  （新しい順、名前と数）と「ほか n 件」。**本文は出さない**（名前と数だけ。iOS は名前に `.privacySensitive()`）。
- **押したとき**：行はその会話（通知を押したときと同じ）。本体は、iOS はアプリを開くだけ（アイコンと同じ）、Android は
  そのワークスペースのホーム。
- **新しさ**：アプリが同期のたびに書く。iOS のウィジェットは 15 分より古ければ `GET /sync/summary` で数だけ確かめる（0 なら
  行を消す）。Android はプッシュが来たとき、ネットを使わずに数（サーバーの `badge`）と先頭の会話を進める。会話の一覧を
  軽く取る API はないので、行はアプリの同期で正しくなる。

## 3. 今日の予定・締切のウィジェット

- **中身**：今日の予定（終日と前日から続くものが先、次に時刻順。アプリのカレンダーと同じ）と、自分のタスク（個人用か担当）で
  今日が期限か期限切れのもの（期限切れは赤）。空なら「今日の予定なし」。
- **大きさ**：iOS は小（次の予定とタスクの数）・中（予定とタスクの 2 列）・大・ロック画面。Android は 2×1〜4×3。
- **押したとき**：予定の行はその予定、タスクの行はそのタスク（通知と同じ開き方。チャンネルのものはその「予定」「タスク」
  タブ）、本体はカレンダー、タスクの見出しは「タスク」。
- **新しさ**：`GET /calendar/events`（今日と明日）と `GET /tasks/mine` を、iOS はウィジェットの拡張が共有のトークンで、
  Android はアプリのプロセスの WorkManager の仕事が読む。予定の終わり・期限・0 時に表示を進める（明日の分も持つので、
  ネットがなくても日付が変わる）。読み直すのは、アプリの変更の知らせ・古いとき・日が変わったとき。

## 4. データの流れ（在室状況）

- **アプリが書く**：同期（起動・再接続・在室状況のイベント）と自分の変更のたびに、小さなスナップショット（サーバー、
  ワークスペース名、自分の ID、状態の一覧、自分の状態とメモ、数、時刻、最後の失敗）を書き、ウィジェットに描き直しを頼む。
  サインアウトで消す。
  - **サインアウトとの競合**（iOS、2026-10-14、REVIEW-v0.1.62 #3）：ウィジェットの読み直し（3 つとも）やボタンの送信の途中で
    そのアカウントがサインアウト・削除されると、遅れて届いた応答（失敗も）が開始時のスナップショットを書き戻し、消したはずの
    メモ・非公開チャンネルの名前・予定の題名が App Group に戻っていた。今は、始める前にアカウントのセッションの世代
    （MOBILE_UI.md §21.3、`AccountSessions`）を覚え、保存はセッションのロックの中で「世代が同じでサインイン中」のときだけ
    行う。アプリのサインアウトは世代を上げてトークンを消してからスナップショットを消すので、どちらの順に起きても消した
    ものは戻らない。保存しなかった読み直しは何も返さず、タイムラインも返す直前にサインイン中かを確かめ、違えば何も描かない
    （サインインを促す面）。他のワークスペースのスナップショットはそのまま。
  - 「アプリで開いているワークスペース」は、サインイン中のアカウントのスナップショットからだけ選ぶ（アプリの一覧
    `Widget/workspaces.json` とセッションの記録の両方でサインイン中のもの）。コントロール（iOS 18）と切り替えの Intent も同じ。
  - iOS：App Group `group.jp.chikuwachat.ios` の中のファイル `Widget/attendance.json`（アカウントごと）。UserDefaults は
    ウィジェットのプロセスに古い値が残ったのでファイルにした。
  - Android：アプリの SharedPreferences（`attendance_widget`）。
- **ボタン**：
  - iOS：ウィジェットの拡張の中の App Intent が、共有の鍵束（`3WF4YQB4L6.jp.chikuwachat.ios.shared`、共有の拡張と同じ）
    のトークンで送る。期限切れは共有の拡張と同じ手順で更新する。描き直しは 15 分ごと、5 分より古ければ `GET /attendance`
    で読み直す。
  - Android：アプリのプロセスの WorkManager の仕事が、アプリの API クライアント（トークンの更新・サインアウトの扱いも同じ）
    で送る。決まった時刻の描き直しはしない（アプリの同期かボタンで新しくなる）。
  - **押した人のアカウントに結び付く**（Android、REVIEW-v0.1.62 #1）：仕事は押したときのスナップショットの自分の ID を持ち、
    そのサーバーに今サインインしているのがその人のときだけ送る。サインアウトの後に同じサーバーへ別の人がサインインしていれば
    送らない（その人の状態を変えず、前の人のメモも持ち込まない）。読み直し（`GET /attendance`）と変更の答えの後にも、
    クライアントが替わっていないことを確かめる。仕事の列はワークスペースごと（`attendance-widget-press:<サーバー>`）で、
    サインアウト・一覧から外す・別のアカウントでのサインインのときに取り消す。失敗の「更新できません」は、押した人の
    スナップショットにだけ付ける。
- **読み直しも同じ**（Android）：アプリで開いていないワークスペースの読み直し（`WidgetRefreshWorker`）と今日の読み直し
  （`TodayWidgetWorker`）は、答えの後にそのアカウントのセッションが続いていることを確かめ、途中でサインアウトや別の人の
  サインインがあれば読んだものを捨てる（サインアウトで消したウィジェットに前の人の内容を書き戻さない）。
- サーバーの変更はない。

## 5. 配布の準備

- iOS：拡張 `jp.chikuwachat.ios.Widgets`（版とビルド番号はアプリと同じ。`release-ios.sh` が 4 つの Info.plist を確かめる）。
  App ID は Xcode の自動署名が登録済み（App Groups 付き）。種類を足すだけならポータルの作業は要らない。
- Android：依存 `androidx.glance:glance-appwidget`（Jetpack）。Android 12 より前は、ボタンの仕事が短く通知を出すので
  チャンネル「在室状況の更新」がある。
