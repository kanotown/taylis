# 定期投稿と提出の回収 (L6、M59〜M60)

ROADMAP の L6。D4 の推奨 A に沿う: 「#週報」のようなチャンネルに毎週スレッドを立て、各自がそのスレッドに返信して提出し、
提出状況 (「提出 7/10」) が見え、締切を過ぎたら出していない本人にだけ催促する。研究室以外でも使える汎用の機能として作る
(定例会の議題募集、日報、当番の確認なども同じ仕組み)。

## 1. 方針

- **定期投稿**はチャンネルに付く。投稿者はその定期投稿ごとのボット (Webhook と同じ `role = bot` のユーザー。名前は定期投稿の名前、
  例「週報」)。ボットはチャンネルのメンバーにする。
- **本文**は雛形と同じ置き換え (`{date}` `{weekday}` `{week}`、M30・`apps/shared/templates.json`) をサーバで行う。日付は定期投稿の
  タイムゾーンでの投稿日。
- **回収**は任意。オンにすると、投稿ごとに「対象者」と「締切」を持つ。対象者がその投稿のスレッドに返信したら提出済み
  (内容は問わない。チャンネルにも送信した返信も数える。消したら未提出に戻る)。
- **催促**は締切を過ぎたとき 1 回、未提出の対象者それぞれに L4 の催促と同じ個人のリマインダー (`reminders`、メモ「〇〇 の提出を
  お願いします (締切 10/9 (金) 18:00)」) を作る。プッシュはリマインダーの経路。本人以外には誰に催促したかを出さない。
- 管理 (作る・直す・止める・消す・今すぐ投稿) はチャンネルのオーナーと管理者。

## 2. データ

`recurring_posts`

| 列 | 意味 |
|---|---|
| id, channel_id, created_by, bot_user_id | |
| name (1〜40) | ボットの表示名にもなる (例「週報」) |
| body (1〜4000) | 雛形 (置き換えあり) |
| schedule | `{"kind": "weekly", "weekdays": [4], "time": "09:00"}` (0 = 月曜。複数の曜日可) か `{"kind": "monthly", "day": 1, "time": "09:00"}` (31 日がない月は月末) |
| tz | 例 `Asia/Tokyo` (作った端末から) |
| collect | NULL か `{"targets": {"group_ids": [...], "user_ids": [...]}, "due": {"after_days": 3, "time": "18:00"}}`。対象はグループと人の和で、投稿の時点のチャンネルのメンバーに限る (投稿ごとに固定) |
| enabled, next_run_at, last_run_at | 停止中は投稿しない。next_run_at は schedule と tz から計算し直す |
| created_at, updated_at, deleted_at | |

`collections` (回収のある投稿ごと)

| 列 | 意味 |
|---|---|
| message_id (主キー) | 定期投稿が立てたメッセージ |
| recurring_post_id, channel_id | |
| target_user_ids | 投稿の時点で固定した対象者 |
| due_at | 締切 (投稿日 + after_days の time、tz) |
| reminded_at | 催促を作った時 (1 回だけ) |

提出済みかは、その場で数える: スレッドの返信 (`parent_id = message_id`、消されていない) の送信者のうち対象者。

## 3. API (`/api/v1`)

- `GET /channels/{id}/recurring-posts` / `POST` / `PATCH /recurring-posts/{id}` / `DELETE` (オーナー・管理者)。
- `POST /recurring-posts/{id}/run` — 今すぐ投稿 (次の予定は変えない)。
- `MessageOut.collection` (回収のある投稿だけ): `{due_at, target_count, submitted_user_ids, target_user_ids, reminded_at}`。
  返信が付いたり消えたりしたら、親の `message.updated` (change = "collection") で各端末へ (スレッドの返信数と同じ流れ)。

## 4. 実行

- reminders の worker と同じ周期で、`next_run_at <= now` の有効な定期投稿を投稿する (1 回の実行で 1 件。サーバが止まっていた間の
  分はまとめて 1 回だけ投稿し、次の予定から再開する)。同じ予定で二重に投稿しない (next_run_at を投稿と同じトランザクションで進める)。
- 締切を過ぎて `reminded_at` が空の collections に、未提出の対象者の催促を作る。
- チャンネルがアーカイブされたら止める。ボットや作った人がいなくなっても動き続ける (管理はオーナー・管理者)。

## 5. 画面

| 場所 | Desktop / Web | iOS / Android |
|---|---|---|
| チャンネル詳細 | 「定期投稿」: 一覧 (名前・次の予定・回収の有無)、作る・直すダイアログ (名前、本文 (雛形の置き換えの説明付き)、曜日と時刻 / 毎月の日と時刻、回収: 対象 (グループ・人) と締切 (何日後の何時))、止める・消す・今すぐ投稿 | 一覧と、止める・今すぐ投稿 (作る・直すは M60 で全画面のフォーム) |
| 投稿 | 親の下に「提出 7/10 · 締切 10/9 (金) 18:00」のチップ。押すと「提出済み / 未提出」の一覧 (チャンネルのメンバーに見える) | 同じ |
| 自分 | 自分が対象で未提出のものは、チップが目立つ色 (「未提出」) | 同じ |

## 6. 実装の順番

- **M59**: サーバ (表・API・worker・催促・雛形の置き換え) と Desktop / Web。
- **M60**: iOS と Android (チップと提出状況、定期投稿の一覧と管理)。
