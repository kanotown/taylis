# 締切 (L5、M85〜M86)

ROADMAP の L5 (LAB.md §E): 学会・奨学金・修論提出などのチャンネル全員向けの締切。チャンネルの見出しに次の締切のチップ
(「全国大会 原稿 あと 3 日」)、サイドバーの「締切」一覧 (今週 / 今月 / それ以降 / 過ぎたもの)、研究室 bot が 7 / 3 / 1 / 0 日前に
チャンネルへ知らせる。

**状態**: M85 (サーバと Desktop / Web) は実装済み (2026-10-03、移行 0070)。M86 (iOS / Android) は §8 の仕様で未着手。

## 1. 方針: タスク (M55) の上に作る

LAB.md §E の設計時は葉モジュール `deadlines` (表 `deadlines` と `deadline_notices`、`deadline.updated`、bootstrap に 90 日分) を
想定していたが、その後にできたタスク (TASKS.md) が大半を持っている。L9 (REVIEWS.md §1) と同じく、**別の仕組みは作らず、
タスクの種類 (`tasks.kind = deadline`) にする** (利用者の了承 2026-10-02「推奨の案で」。LAB.md・ROADMAP の L5 の行にも書いた)。

| 締切に要るもの | タスクにあるか |
|---|---|
| チャンネルに付く、メンバーに見える | ある (チャンネルのボード) |
| 題名・日時 (終日も可)・メモ (URL) | ある (`title`、`due_on` + M81 の `due_at` / `due_tz`、`notes` は Markdown なので URL も) |
| 作る・直す・消す権限、同期 | ある (投稿できるメンバー、`task.updated` / `task.deleted`、再接続で読み直す) |
| 担当者と当日の通知 | ある (任意の担当者、期限の日 8:00 のプッシュ) |
| カレンダーに出す | ある (`/tasks/due`) |
| **事前の通知を bot がチャンネルに投稿** | **無い** → `task_deadline_notices` と worker (§3、§4) |
| **見出しのチップと「締切」一覧** | **無い** → `GET /tasks/deadlines` (§5) と画面 (§6) |

## 2. 決めたこと (推奨の案)

| # | 項目 | 決めた案 | 採らなかった案 |
|---|---|---|---|
| 1 | 作り方 | **タスクの種類 `deadline`** (列を 2 つ、表を 2 つ足すだけ) | LAB.md の葉モジュール `deadlines` (同期・権限・画面がもう 1 組) |
| 2 | 作れる人 | **ボードを変えられる人** (投稿できるメンバー。投稿制限のチャンネルはオーナーと admin) で、**ゲストは不可** (LAB.md §E「ゲスト以外のメンバー」) | オーナー / admin だけ (LAB.md §7 の案。ボードの規則で bot が書けるのは作った人が投稿できる所だけなので、悪用の余地は増えない) |
| 3 | どこに | **公開・非公開チャンネルのボード** (自分用・DM には作れない)。メッセージ・キャンバスからは作らない | DM にも (相手 1 人なら個人のリマインダーで足りる) |
| 4 | 日付 | **必ず要る** (消せない)。時刻は任意 (M81) | 日付なしの締切 |
| 5 | 繰り返し | **しない** (`task_invalid_rrule`)。毎年の学会は作り直す | M81 の繰り返し (次の回の通知の計画が要る) |
| 6 | 事前の通知 | **締切ごとに何日前の集合** (`notice_days`、既定 7 / 3 / 1 / 0、0〜60 を 6 個まで、空 = 知らせない)。**その日の 9:00** (締切のゾーン)。時刻付きの締切でその時刻より前でない通知は出さない (8:30 締切の当日 9:00 は出さない。前日が知らせる) | 分単位の offset (`notify_offsets`、LAB.md の案。画面で選ぶのは日数だけ) / 当日は締切の時刻に |
| 7 | 誰が投稿するか | **1 つの「締切」ボット** (`role = bot`、`system_bots` の `deadlines`、最初に要る時に作る)。投稿の時にチャンネルにいなければ入り直す | 締切ごと・チャンネルごとのボット (定期投稿と違い、名前を分ける理由が無い) |
| 8 | 投稿の文 | 「⏰ 締切まであと 3 日です: **全国大会 原稿** (10/9 (金))」「⏰ 明日が締切です: …」「⏰ 今日が締切です: … (10/9 (金) 17:00)」、担当者がいれば 2 行目に「担当: 加納、佐藤」(名前だけ。メンションしない) | 担当者・`@channel` をメンションする (4 回のプッシュはうるさい。担当者には当日 8:00 のタスクのプッシュがある) |
| 9 | 見出しのチップ・一覧の取り方 | **`GET /tasks/deadlines`** (参加中のチャンネルの締切、30 日前から先。端末は 1 回読み、`task.updated` / `task.deleted` で保つ) | bootstrap や ChannelOut に入れる (bootstrap の形を変えると古い端末に響く。イベントはもう `task.*` で届く) |
| 10 | 古いスマホ | **出し分けない**: 配布済みの iOS / Android は知らない `kind` を `task` と読む (§7) | M76 のような `include=` の出し分け |

## 3. データ (移行 0070)

`tasks` に足したもの:

| 列 | 型 | 意味 |
|---|---|---|
| kind | `task` / `review` / **`deadline`** | CHECK を広げた |
| notice_days | smallint[] NULL | 何日前に知らせるか (大きい順、重複なし)。締切だけ (CHECK: `(kind = 'deadline') = (notice_days IS NOT NULL)`) |
| notice_tz | varchar(64) NULL | 9:00 を読むゾーン。時刻付きなら `due_tz`、日付だけなら作った人のゾーン (要求の `tz` → おやすみ時間のゾーン → Asia/Tokyo)。締切だけ |

CHECK: 締切は `channel_id` と `due_on` を持つ。索引 `tasks_deadline_idx (channel_id, due_on) WHERE kind = 'deadline' AND deleted_at IS NULL`。

`task_deadline_notices` (冪等の記録):

| 列 | 意味 |
|---|---|
| task_id, days_before, fire_at | 主キー。**計画した時刻を鍵に含める**: 締切をずらすと新しい行ができて改めて投稿し、一度投稿した時刻は二度と投稿しない |
| status | `pending` → `fired` か `cancelled` |
| message_id | ボットが投稿したメッセージ |

`system_bots` (`key` → `user_id`): サーバが自分で投稿するボット。今は `deadlines` (表示名「締切」) だけ。

## 4. 通知の計画と投稿

- **計画** (`tasks/deadlines.py` の `sync_notices`): 作成・変更・移動・完了・削除のたびに、締切の日付・時刻・`notice_days`・状態から
  欲しい行 `{何日前: その日の 9:00}` を作り、行を合わせる。欲しくなくなった pending は cancelled、新しい時刻は pending (もう過ぎて
  いれば cancelled: 後から投稿しない)、cancelled で時刻がまだ先なら pending に戻す (完了 → 戻す)。fired はそのまま。
- **投稿** (`fire_notices`、scheduled ループで 15 秒ごと): 時刻の来た pending を締切ごとに集め、**いちばん近い 1 件だけ**を投稿し、
  残りは cancelled (サーバが止まっていて 3 日前と前日が両方来たら「明日が締切です」だけ)。投稿しないもの: 締切が消えた・完了・
  計画が変わった (行の時刻が今の計画に無い)・**締切を過ぎた** (時刻、日付だけなら翌日 0:00)・チャンネルがアーカイブ済みか無い・
  ボットが管理者に無効化された (無効化はすべての締切の通知を止める方法になる)。
- 投稿は普通のメッセージの経路 (`create_message`、`advance_read=False`、`client_msg_id = uuid5(task/days/fire_at)`)。seq・outbox・
  未読・検索・通知の設定はそのまま効く。ボットは投稿制限のチャンネルにも書ける (M15a の例外。そこで締切を作れるのはオーナーと admin)。
  失敗はログに残し、その行は cancelled (次の周期で何度も試さない)。
- 題名のメンション (`<@…>`・`<!channel>`) は名前の文字にして投稿する (ボットの投稿で誰かを呼ばない)。

## 5. API (`/api/v1`)

- `POST /tasks` `{channel_id, kind: "deadline", title, due_on | due_at, tz?, notes?, assignee_ids?, notice_days?}` → 201 `TaskOut`
  (`notice_days` 省略で `[7, 3, 1, 0]`)。
- `PATCH /tasks/{id}` に `notice_days` (全体を置き換える。`[]` で知らせない)。他の項目は今までどおり。
- `GET /tasks/deadlines?channel_id=` (省略で参加中の全チャンネル) → `TaskOut[]`: 締切 (未完了も完了も) で期限が 30 日前 (自分のゾーン)
  以降のもの、日付 → 時刻 (日付だけは同じ日の時刻付きの後) → id の順、500 件まで。`channel_id` が DM なら
  `400 task_channel_unsupported`、メンバーでなければ `403 not_a_member`。
- `TaskOut` / `TaskData` (task.updated) に `notice_days` (int[] | null。締切以外は null)。`TaskKind` に `deadline`。
- 新しいエラー `task_invalid_deadline` (400): 締切を自分用にする・日付なしで作る・日付を消す・締切以外に `notice_days`。
  ほか: 繰り返し → `task_invalid_rrule`、メッセージ・キャンバスから → `task_invalid_source`、ゲスト → `403 guest_restricted`、
  投稿制限 → `403 posting_restricted`、DM → `400 task_channel_unsupported`。`notice_days` の範囲外 (0〜60、6 個まで) は 422。
- イベントは足していない (`task.updated` / `task.deleted` / `task.assigned` / `task.due` のまま。`kind` が `deadline` になるだけ)。
  `MessageOut.tasks` (`MessageTaskOut.kind`) は変えない (締切はメッセージから作らない)。

## 6. 画面 (Desktop / Web、M85)

| 場所 | 変えたこと |
|---|---|
| チャンネルの見出し | 名前・タブの後に、そのチャンネルの次の締切 (未完了でまだ過ぎていない一番近いもの) のチップ「⏰ 全国大会 原稿 あと 3 日」(今日は「今日」/「今日 17:00」、明日は「明日」)。前日までは赤、7 日以内は黄、それより先は灰。押すと締切の詳細 |
| チャンネルの ⋯ | 「締切を追加…」(ボードを変えられる人だけ) |
| ボード | 列の上に「⏰ 締切を追加」。締切のカードに ⏰ |
| タスクのダイアログ | 新しいタスクをチャンネルのボードに作るとき「タスク / ⏰ 締切」の切り替え。締切は「締切日」(消せない)・時刻、「事前の通知」(14 日前・7 日前・3 日前・前日・当日のチェック、既に持つ他の日も出す)、繰り返しは出さない、追加先に「自分のタスク」を出さない。題名「締切を追加 / 締切を編集」。読むだけの表示に「事前の通知」 |
| サイドバー | 「タスク」の次に「締切」(スマホ幅はホームのタイル)。今週 (カレンダーと同じ日曜始まりの週の土曜まで) / 今月 / それ以降 / 過ぎたもの (完了も含む、新しい順)。行は日付 (「10/9 (金)」「今日 17:00」) とカード (#チャンネル、状態)、押すと詳細。右上に「締切を追加」(最初のボードを選んだ状態、追加先で変える) |

- 端末の持ち方: `TaskHub` の締切の窓 (最初に見出しのチップか「締切」が出たときに読み、アプリを閉じるまで保つ。`task.updated` で
  締切なら入れ、締切でなくなった・30 日より前になったら外し、`task.deleted`・チャンネルからの退出で外し、再接続で読み直す)。
  M85 より前のサーバでは `/tasks/deadlines` が `/tasks/{task_id}` に当たって 422 になるので「対応していません」と読む (チップは出ない)。
- カレンダーの締切は今までどおり「☐ 題名」(⏰ は付けていない)。

## 7. 古い端末

- 配布済みの iOS は `TaskKind` を `init(from:)` で知らない値を `.task` に読み、Android は `kind` を文字列のまま持ち知らない値をタスクとして
  出す (どちらも試験あり: iOS TaskTests の `later_kind`、Android ReviewRequestsTest)。だから M86 までのスマホでは締切は**普通のタスク**
  として見え (⏰・チップ・一覧・事前の通知の設定は無い)、題名・状態・担当などを直せる。`notice_days` は送らないので変わらない。
- 古いスマホで締切の期限を消すと `400 task_invalid_deadline` (古い端末の表に無いコードなのでサーバの英文)。繰り返しを付けると
  `task_invalid_rrule`。どちらも保存されないだけで壊れない。
- ボットの投稿は普通のメッセージなので、どの端末でもそのまま読める。

## 8. スマホ (M86) に要るもの

iOS と Android の両方。サーバの変更は無し (M85 のまま)。Desktop の `src/ui/deadlines.ts` (規則)、`src/sync/tasks.ts` の締切の窓、
`src/ui/DeadlinesView.tsx`、`tests/deadlines.test.tsx` を移す。

1. **読み取り**: `TaskKind` に `deadline` (iOS は enum に case を足す。知らない値を `.task` に読む今の `init(from:)` は残す)。
   `TaskOut.notice_days` (int の配列 | null、省略可)。`GET /tasks/deadlines` (`channel_id` は省略) を `TaskHub` の窓として持つ:
   最初に見出しのチップか「締切」が出たときに読み、アプリが動いている間は保ち、`task.updated` (締切で期限が 30 日前以降なら入れる、
   そうでなければ外す)・`task.deleted`・チャンネルからの退出で更新し、再接続 (とフォアグラウンドに戻ったとき) に読み直す。
   404 / 422 は「このサーバは締切に対応していません」(チップを出さない)。
2. **見出しのチップ**: 会話の画面のナビゲーションバー (またはタブの列の上の 1 行) に、そのチャンネルの次の締切
   (種類が締切・未完了・まだ過ぎていない (時刻付きは時刻、日付だけはその日の終わりまで)・日付 → 時刻 (日付だけは同じ日の時刻付きの
   後) → id で一番前) を「⏰ <題名> あと N 日」(今日は「今日」か「今日 17:00」、明日は「明日」/「明日 17:00」)。前日まで (N ≤ 1) は赤、
   7 日以内は黄、それより先は灰。押すとタスクの詳細 (今のタスクのフォーム)。公開・非公開チャンネルだけ。
3. **「締切」画面**: ホームのタイル「締切」(「タスク」の次)。今週 (日曜始まりの週の土曜まで) / 今月 (今月の残り) / それ以降 /
   過ぎたもの (完了も、新しい順。空の節は出さない)。行に日付 (「10/9 (金)」、今日は「今日」、時刻付きは「17:00」を付ける)、題名
   (完了は打ち消し線)、#チャンネル、担当者。押すとタスクのフォーム。右上の ＋ で新しい締切 (追加先は投稿できるチャンネルから)。
4. **フォーム**: 新しいタスクをチャンネルのボードに作るとき「タスク / 締切」の切り替え (レビュー依頼・メッセージ / キャンバスから・
   DM では出さない)。締切は「締切日」(必須、消すボタンなし)・時刻 (M84 の部品)、「事前の通知」(14 日前・7 日前・3 日前・前日・当日の
   チェック、既定は 7・3・1・当日、既に持つ他の日も出す。説明「『締切』のボットがこのチャンネルに、その日の 9:00 に投稿します」)、
   繰り返しは出さない、追加先に「自分のタスク」を出さない。作成は `POST /tasks {kind: "deadline", channel_id, title, due_on | due_at,
   tz, notice_days}`、編集で通知の日を変えたら `PATCH {notice_days}` (大きい順)。読むだけの表示に「事前の通知: 7 日前・3 日前・前日・当日」
   (空は「通知しない」)。見出しは「締切を追加 / 締切を編集」、削除の確認は「この締切を削除しますか？ (前もっての通知も止まります)」。
5. **ボードのカード**に ⏰ (iOS は `alarm`、Android は `Icons.Outlined.Alarm`)。チャンネルの「タスク」タブの ＋ メニューか上部に
   「締切を追加」。
6. **エラー**: `task_invalid_deadline` は `apps/shared/errors.json` から生成済み (M85 で ErrorMessages を更新)。
7. **試験**: Desktop の `tests/deadlines.test.tsx` の例 (残り日数の文、過ぎたかどうか、次の締切の選び方、4 つの節、作成と変更の本文、
   窓の出入り、422 は未対応) を移す。
