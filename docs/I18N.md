# I18N: UI の言語 (M115)

アプリの表示を 日本語 (既定) / English / 简体中文 から選べる。サーバ・Desktop / Web・iOS・Android が同じ決め方で
同じ言葉を使う。

## 1. 決め方 (全クライアント共通の契約)

- `users.locale` ∈ `"ja"` / `"en"` / `"zh-Hans"` / `null`。`null` = 端末 (ブラウザ) の言語に合わせる (既定)。
- `UserMe.locale` (bootstrap の `me` にも載る)。`PATCH /users/me {locale}` で変える (`null` で「端末に合わせる」に戻す、
  それ以外の値は 422)。ほかの `PATCH /users/me` と同じく `user.updated` を出すので、別の端末は `GET /users/me` を読み直して
  すぐに切り替える (SYNC_PROTOCOL.md `user.updated`、M111 と同じ)。
- クライアントは **すべての要求に `Accept-Language`** を付ける: 選んだ言語、選んでいなければ端末の言語 (`ja` / `en` / `zh-Hans`)。
- 画面に出す言語: `me.locale` → 端末の言語 (ja / en / zh* のどれか、それ以外は ja) → ja。ログイン前は端末の言語。
- サーバが **1 人に向けて** 書く文 (エラーの `message`、プッシュの題と本文、アクティビティの項目 (予約の知らせ・リマインダーの
  確認のメモ・カレンダーの通知など)、テスト通知) の言語: `users.locale` → `Accept-Language` → ja。
  - 要求の中で返す文 (エラー) はその要求の `Accept-Language`。
  - 要求の外で書く文 (プッシュ・保存する知らせ) のために、ログイン・トークンの更新・SSO の交換・`PUT /devices/current` の
    `Accept-Language` を `devices.locale` に覚える。プッシュは端末ごとに `users.locale` → `devices.locale` → ja で作る
    (同じ人の iPhone は英語、Mac は日本語、もありうる)。保存する知らせは `users.locale` → 最後に使った端末の
    `devices.locale` → ja。
- **共有する内容は日本語のまま** (ワークスペースの言語): チャンネルの参加 / 退出の行のサーバ側の本文、投票・日程調整の
  選択肢と「決定」の行、締切・予約・フィードのボットがチャンネルに書く投稿、ワークフローの回答の投稿 (「2026年7月28日 (火)」
  「はい / いいえ」)、通話を始めたメッセージの本文 (「🎧 通話を始めました」、M130。M117 は 📞。新しいクライアントは `message.call` から
自分の言語で描く)、定期投稿の `{weekday}` などの差し込み、AI のボットの答えと要約、管理者への報告の DM、サーバが
  作るタスクの既定の列名、`apps/shared/nav-items.json` の既定の名前 (クライアントは key で訳して出す)。何人もが読む行を、
  書いた人の言語で決めると読む人ごとに食い違うため。参加 / 退出の行は `system_event` から各クライアントが自分の言語で
  描く (Desktop の `systemMessage.ts`)、本文はその代わり (古いクライアント) として日本語で残す。

## 2. 共有するもの (apps/shared)

- `apps/shared/i18n/glossary.json`: 主要な用語の 3 言語の対訳と文体の決まり。**新しい用語を 2 か所以上で訳す前にここに足す**。
- `apps/shared/errors.json`: エラーコード → `{ja, en, zh-Hans}` (と HTTP 状態ごと・ネットワーク・不明の文)。
  `python3 apps/shared/gen_errors.py` が次を作る (手で直さない):
  - サーバ `server/app/i18n/errors.json`
  - Desktop `apps/desktop/src/api/errorMessages.ts` (`ERROR_MESSAGES_BY_LOCALE` など、試験用に ja の別名 `ERROR_MESSAGES`)
  - iOS (Swift): `static var locale = "ja"` を画面の言語に合わせて置き換えると、`byCode` / `byStatus` / `network` / `unknown`
    がその言語を返す。`byCodeByLocale` などで直接も引ける。
  - Android (Kotlin): `@Volatile var locale` と `byCode` / `NETWORK` / `UNKNOWN` (getter)、`*ByLocale` の表。
  - 表示は「サーバの `message` ではなくコードから引いた文、無ければサーバの `message`」のまま (サーバの `message` も同じ言語)。

## 3. サーバ

- `server/app/i18n/__init__.py`: `normalize` (`zh` / `zh-CN` / `zh-TW` … は `zh-Hans`)、`from_accept_language` (q 値の順)、
  `effective`、`error_text`、`t(key, locale, **params)`、`weekday`、`text_locale(db, user)`、`device_locale(user, device)`。
- `server/app/i18n/messages.json`: プッシュ・カレンダー・リマインダー・予約などの文。キー → `{ja, en, zh-Hans}`、引数は `{name}`。
- エラー: `core/errors.py` の処理が `message` をコード (無ければ HTTP 状態) から要求の言語で置き換える。要求の言語は
  ログイン済みなら `users.locale` (`get_auth_context` が `request.state` に置く)、無ければ `Accept-Language`、無ければ ja。
- 試験: `tests/test_i18n.py` (全キーが 3 言語にあり引数が同じ、`Accept-Language` の解釈、エラー・プッシュ・知らせの言語)、
  `tests/test_error_codes.py` (errors.json の全コードが 3 言語)。

## 4. Desktop / Web

- `src/i18n/`: `ja.ts` (元の文、そのまま)、`en.ts`、`zhHans.ts`。キーは `area.name`。`MessageKey = keyof typeof ja` なので
  en / zh に欠けたキーは型の誤り。
- `t(key, params)`: `{name}` の差し込みと ICU 風の複数形 `{count, plural, =1 {…} one {…} other {# …}}`。
  文の中に部品 (リンク・太字) を入れる時は `tRich(key, {link: (text) => <a…>{text}</a>})` (`<link>…</link>` の形)。
- **読み込み時に `t()` を呼ばない**: モジュールの定数は getter (`get label() { return t("…"); }`) か `labelled(value, key)` に
  する (言語を変えた時に古い文が残るため。試験が読み込み時の呼び出しを見つけて落とす)。
- 日付・時刻は `Intl` (`intlLocale()`)、曜日は `weekdayName(day, "short" | "long")` (0 = 月曜)。
- 設定 → 表示 → 言語:「端末に合わせる / 日本語 / English / 简体中文」。選ぶと `PATCH /users/me {locale}` で保存し、
  その場で全体を描き直す (アプリの木を言語で key する)。選んだ値は `localStorage` (`taylis.locale`) にも置き、起動直後と
  ログイン前に使う。`api/client.ts` がすべての要求に `Accept-Language` を付ける。Tauri の本体 (Rust) に日本語の
  メニューやダイアログは無い。
- 試験: `tests/i18n.test.ts` (全キーが 3 言語にある・空でない・引数が同じ、en / zh にかなが無い、複数形と言語の決め方、
  読み込み時の `t()` の禁止)。ほかの試験は `tests/setup.ts` で ja に固定して走る。
- `npm run i18n:leftovers` (`scripts/i18n-leftovers.mjs`): コメント・辞書の外に残った日本語の行を出す。意図して日本語の
  行 (§1 の共有する内容、日本語の入力を見分ける正規表現、`/日程` コマンドの名前、言語の自称など) は理由付きの許可リストに
  あり、許可されていない行があると 1 で終わる。

## 5. 文を足す

1. Desktop: `ja.ts` に日本語、`en.ts` と `zhHans.ts` に訳を足す (3 つとも、同じ引数)。用語は glossary に合わせる。
2. iOS / Android: それぞれの文字列の仕組み (String Catalog / `strings.xml`) に 3 言語で足す。
3. エラーコード: `apps/shared/errors.json` に 3 言語で足して `gen_errors.py` を走らせる。
4. サーバの 1 人向けの文: `messages.json` に 3 言語で足し、`i18n.t(key, locale, …)` で使う。共有する内容 (§1) は訳さない。
5. 英語は文頭だけ大文字 (sentence case)、中国語は全角の句読点。日本語の文の括弧とコロンは全角の（ ）と：で、隣に空白を入れない (2026-10-06。プレースホルダー・URL・コード・時刻と、サーバも書く曜日付きの日付「10/9 (金)」は半角のまま)。glossary の `style` を見る。

## 6. 言語を足す

1. `apps/shared/errors.json` の `locales` と全コードに足し、`gen_errors.py` を直して走らせる。
2. サーバ: `i18n.LOCALES` / `Locale` / `normalize` と `UserUpdate.locale` の `Literal`、`messages.json` の全キー、OpenAPI を作り直す。
3. 各クライアント: 辞書 (Desktop は `src/i18n/<lang>.ts` を `index.ts` の表に)、言語の選択肢、`Accept-Language`。
4. glossary に列を足す。
