# 共有枠の予約 (M99)

研究室には Claude Team の「Premium」のシートが 3 つあり、たくさんの学生で順番に使う。チャンネルに「予約の枠」を作ると、
メンバーは「予約する」で順番待ちに入り、担当者 (数人の学生の管理係) が Claude の管理画面で実際にシートを付け替えてから
Taylis のボタンを押す。割り当てから一定時間 (既定 6 時間) は外されないことを保証し、それを過ぎた人は、待っている人がいれば
猶予 (既定 15 分) の後に入れ替えの対象になる。研究室以外でも使える汎用の機能 (共有アカウント・実験装置・計算機の枠など、
数に限りのあるものを順番に使う) として作る。

**状態**: M99 (2026-10-04、移行 0078) でサーバ・Desktop / Web・iOS (build 89)・Android を実装。枠の設定は Desktop / Web だけ。

Taylis は外の資源 (Claude の管理画面) を操作しない。**ボタンは「管理画面でそうした」という記録**で、Taylis はその記録から
順番・保証・知らせを決める。

## 1. 方針

- **枠はチャンネルに付く** (DM は不可、1 チャンネル 5 個まで)。設定は名前・枠の数 (capacity)・最低保証時間 (時間、既定 6)・
  猶予 (分、既定 15)・担当者 (チャンネルのメンバーから選ぶ、20 人まで)・受付中か。作る・直す・消すのはチャンネルのオーナーと
  管理者 (Desktop / Web)。作るにはチャンネルのメンバーであること (ボットがチャンネルに入るため。フィード・Webhook と同じ)。
- **1 人 1 枠**。1 つの枠に、ある人の「待ち」か「利用中」は 1 つだけ (`reservations_active_uniq`)。
- **担当者の操作**: 割り当てた・外した・入れ替えた・(ほかの人の待ちを) 取り消す。担当者・チャンネルのオーナー・管理者が
  できる (管理者は未参加の公開チャンネルでも)。担当者を選んでいなければ、担当者あての知らせはチャンネルのオーナー (と
  メンバーの管理者) に届く。
- **ボットは 1 チャンネルに 1 つ** (`reservation_bots`、名前「予約」、`users.bot_kind = 'reservation'`)。最初の枠と一緒に作って
  チャンネルに入れ、以後そのチャンネルの枠すべてが使う (枠を消しても残る)。フィードの「既存のボットを使う」の候補には出ない。
- **記録はチャンネルの投稿**: 予約・取り消し・割り当て・返却・外した・入れ替えのたびに、ボットが短い 1 行をチャンネルに
  投稿する (メンションは取らない: 名前は文字。`<@` `<!` は全角)。チャンネルを読めば経緯が分かる。
- **本人への知らせはボットからの DM** (ふつうの DM のプッシュ・未読。新しいプッシュの種類は足さない)。メールアドレスは
  DM と担当者の画面にだけ出し、チャンネルには書かない。

## 2. データ

`reservation_pools` / `reservation_bots` / `reservations` (DATA_MODEL.md)。

`reservations.status`:

```text
waiting ──割り当てた──▶ holding ──返却する──▶ returning ──外した──▶ done (end_reason = returned)
   │                      └───────────外した / 入れ替えた──────────▶ done (end_reason = removed)
   └──取り消す / チャンネルを抜けた──▶ cancelled
```

- `guarantee_until` = 割り当ての時刻 + その時の `min_hours` (割り当てで固定。設定を変えても今の人には効かない)。
- `evict_notice_at` / `evict_at`: 保証を過ぎた人に「猶予の後に外す」と知らせた時刻と、猶予の終わり。
- `ready_notified_at`: 担当者に「割り当てて / 入れ替えて / 外して」と知らせた時刻 (同じことを 2 回知らせない)。
- 終わった行 (done / cancelled) は消さずに残す (履歴)。枠を消すと行も消える (投稿は残る)。

## 3. API (`/api/v1`)

| | |
|---|---|
| `GET /channels/{id}/reservation-pools` | チャンネルを読める人。`PoolOut` の一覧 (古い順) |
| `POST /channels/{id}/reservation-pools` (201) | `{name, capacity, min_hours?, grace_minutes?, operator_ids?, tz?, enabled?}`。オーナー・管理者 (`403 reservation_manage_restricted`)、DM は `400 reservation_channel_unsupported`、6 個目は `409 too_many_reservation_pools`、担当者がメンバーでない・ゲスト・ボットなら `400 reservation_operator_invalid` |
| `PATCH /reservation-pools/{id}` | 同じ項目の一部 |
| `DELETE /reservation-pools/{id}` (204) | 待ちと利用中の記録ごと消す。管理画面のシートには触れない |
| `POST /reservation-pools/{id}/reserve` | 「予約する」。メンバー (ゲスト不可)。既に待ち・利用中なら何もしない (200)。停止中は `409 reservation_pool_disabled` |
| `POST /reservations/{id}/cancel` | 「取り消す」。本人か担当者。待ちだけ (`409 reservation_state_conflict`)。取り消し済みなら何もしない |
| `POST /reservations/{id}/return` | 「返却する」。本人だけ (`403 reservation_not_yours`)。利用中だけ |
| `POST /reservations/{id}/assign` | 「割り当てた」。担当者 (`403 reservation_operator_required`)。空きが無ければ `409 reservation_pool_full`。利用中なら何もしない |
| `POST /reservations/{id}/remove` | 「外した」。担当者。利用中・返却中。終わっていれば何もしない |
| `POST /reservation-pools/{id}/swap` | 「入れ替えた」`{remove_id, assign_id}`。担当者。外すと割り当てを 1 回で。両方済んでいれば何もしない |

どの操作も、呼んだ人から見た `PoolOut` を返す。`tz` は作った端末のゾーン (ボットの投稿と DM の時刻の書き方)。
チャンネルを読めない人には `404 reservation_pool_not_found` / `reservation_not_found`。アーカイブ中は変更できない
(`409 channel_archived`)。

`PoolOut`: `id, channel_id, name, capacity, min_hours, grace_minutes, tz, enabled, operator_ids, bot_user_id, holders, waiting,
next_evict_id, my_reservation_id, can_manage, can_operate, created_at, updated_at`。
`ReservationOut`: `id, user_id, status, requested_at, assigned_at, guarantee_until, returned_at, evict_at, email, position, step,
pair_id, ready`。`email` は操作できる人 (`can_operate`) にだけ入る (Claude の管理画面でアカウントを探すため)。

## 4. 順番の決め方 (plan)

`app/modules/reservations/plan.py` の純粋な関数。カード・知らせ・worker が同じものを使う。待っている人を予約の古い順に、

1. 空いている枠 (利用中 + 返却中 < 枠の数) → `step = assign` (担当者は今すぐ割り当てられる)
2. 返却中の人の枠 (返却の古い順) → `step = swap`、`pair_id` = その人
3. **保証を過ぎた人の枠 (保証の終わりが早い人から)** → `step = swap`、`pair_id` = その人
4. 残りは `step = wait` (誰かの保証が過ぎるのを待つ)

と順に当てる。3. で当たった人が「外す候補」。`next_evict_id` (「次に外す」) は最初の候補、候補がいなくて待つ人が残るときは
保証の終わりが一番早い利用中の人 (いつ空きそうかの目安)。

**知らせ** (どれも 1 回だけ。状態が変わるたびと worker で plan を作り直して合わせる):

| いつ | 誰へ | 内容 |
|---|---|---|
| 予約した (空きなし) | 担当者 | 「〇〇 さん (アドレス) が「枠」を予約しました。待ち N 人目です」 |
| 待つ人に空きが当たった (`step = assign`) | 担当者 (押した本人は除く) | 「〇〇 さん (アドレス) に「枠」を割り当ててください (空きがあります)」 |
| 候補になった (保証を過ぎ、待つ人がいる) | 本人 | 「保証時間 (…まで) が過ぎ、待っている人がいます。HH:MM 以降に担当者が外します。使い終わっていれば「返却する」を」 |
| 候補でなくなった (待つ人が取り消した など) | 本人 | 「待つ人がいなくなったので、そのまま使えます」 |
| 猶予が過ぎた | 担当者 | 「入れ替えできます: 〇〇 さん (アドレス) を外して △△ さん (アドレス) に割り当て、「入れ替えた」を」 |
| 返却した | 担当者 | 「〇〇 さん (アドレス) が返却しました。管理画面で外して「外した」を。次は △△ さんです」 |
| 割り当てた | 本人 | 「「枠」が割り当てられました。… までは外されません」 |
| 外した / 入れ替えで外れた | 本人 | 「「枠」から外されました」(返却なら「返却が済みました」) |
| 担当者が待ちを取り消した | 本人 | 「予約は担当者 (〇〇 さん) が取り消しました」 |

- **worker**: リマインダーと同じループ (`SCHEDULED_SEND_INTERVAL_SECONDS`、15 秒) で、待つ人がいる枠と候補に知らせた枠を
  見直す (`reservations.tick`)。時間で変わるのは「保証を過ぎた」と「猶予が過ぎた」の 2 つだけ。待っている人がチャンネルを
  抜けた・無効化されたら、その待ちを取り消す。アーカイブ中のチャンネルは見ない。
- **並行**: どの変更も枠の行を `FOR UPDATE` でロックしてから読む。担当者 2 人が同時に押しても順に処理され、2 回目は
  「済んでいる」ので何もしない。最後の 1 枠を別々の人に同時に割り当てようとすると、後の方は `409 reservation_pool_full`。
- **DM はコミットの後**に送る (DM を開く処理が自分でコミットするため)。送れなかった知らせはログに残るだけで、カードと
  チャンネルの投稿が同じことを示す。`client_msg_id` は行と内容から作る UUIDv5 (送り直しで重ならない)。

## 5. 同期

`reservation.updated` (audience channel、seq なし) `{channel_id, pool_id, deleted}`。カードは人によって違う (自分の状態、
担当者だけのアドレス) ので、イベントには載せず、**端末は受け取ったら `GET /channels/{id}/reservation-pools` で読み直す**
(その会話の枠を持っているか、開いている会話なら)。会話を開いたとき・再接続のあとも読む。bootstrap には入れない。

## 7. Claude Premium シートの使い方 (研究室の例)

1. 研究室の管理者 (またはチャンネルのオーナー) が Desktop / Web で、シートを配るチャンネル (例 #claude) を開く。
2. ヘッダーの ⋯ →「共有枠の予約…」(またはチャンネルの詳細の「共有枠の予約」) で「枠を追加」: 名前「Claude Premium シート」、
   枠の数 3、最低保証 6 時間、猶予 15 分、担当者に管理係の学生 (Claude の管理画面を操作できる人) を選んで「追加」。
   最初の枠で「予約」ボットがチャンネルに入る。
3. 今すでにシートを使っている人がいれば、その人に「予約する」を押してもらい、担当者が「割り当てた」を押して記録を合わせる
   (保証はその時点から数える)。
4. 使いたい人はチャンネルの上の「Claude Premium シート」チップ →「予約する」。空きがあれば担当者に DM が届くので、担当者は
   管理画面でその人 (カードと DM にアドレスが出る) を Premium にしてから「割り当てた」。
5. 埋まっているときは待つ。誰かの保証 (6 時間) が過ぎると、その人に「15 分後に外します」と DM が届き、15 分後に担当者へ
   「入れ替えできます」と届く。担当者は管理画面で入れ替えて「入れ替えた」。
6. 使い終わった人は「返却する」。担当者に届くので、管理画面で外して「外した」(次の人がいれば続けて割り当てる)。

## 8. 残り・やらないこと

- ボットの名前の変更 (今は「予約」固定)。スマホでの枠の設定。
- 1 人が複数の枠を持つ、時間帯を決めた予約 (カレンダー型)、優先度。
- 管理画面 (Claude など) の自動操作。Taylis は記録と順番と知らせだけを持つ。
- 履歴の画面 (終わった行は残しているが、見るのはチャンネルの投稿)。
- DM の送信はコミットの後で、その間にプロセスが落ちると知らせが 1 つ欠ける (カードと投稿は正しい)。
