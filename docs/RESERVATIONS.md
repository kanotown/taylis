# 共有枠の予約 (M99 → M112)

研究室には Claude Team の「Premium」のシートが 3 つあり、たくさんの学生で使う。ワークスペースの「予約」のページに枠を作ると、
メンバーは**時間を決めて予約する** (毎時 0 分から 1 時間単位、2 週間先まで) か、**今すぐ使いたいときは順番待ち**に入る。
担当者 (数人の学生の管理係) が Claude の管理画面で実際にシートを付け替えてから Taylis のボタンを押す。研究室以外でも使える
汎用の機能 (共有アカウント・実験装置・計算機の枠など、数に限りのあるものを時間で使う) として作る。

**状態**: M99 (2026-10-04、移行 0078) でチャンネルの枠と順番待ちを実装。M112 (2026-10-05、移行 0084) で利用者の決定
(2026-10-05) に沿ってワークスペースの「予約」のページ・時間の予約・アクティビティの通知に作り替えた。サーバ・Desktop / Web・
iOS・Android。枠の設定は Desktop / Web だけ。2026-10-06 (移行なし): 1 人 1 枠につき予約・待ち・利用中は 1 つ (§1) と、
予約の長さの既定を最長に (§6)。

Taylis は外の資源 (Claude の管理画面) を操作しない。**ボタンは「管理画面でそうした」という記録**で、Taylis はその記録から
順番・保証・知らせを決める。

## 1. 方針

- **枠はワークスペースのもの** (最大 20 個)。設定は名前・枠の数 (capacity)・予約の最長 (`max_hours`、時間、既定 6)・今すぐの
  保証 (`min_hours`、時間、既定 6)・猶予 (`grace_minutes`、分、既定 15)・担当者 (20 人まで、ゲスト・ボット不可)・見える人・
  記録のチャンネル (任意)・受付中か。**作るのは管理者**、直す・消すのは管理者と枠を作った人 (Desktop / Web)。
- **見える人** (`visibility`): 既定は全員 (ゲストを除く)。チャンネル (`visibility_channel_id`) かグループ (`visibility_group_id`)
  のメンバーに絞れる。担当者・作った人・管理者はいつも見える。絞った先のチャンネル・グループが消えると、担当者・作った人・
  管理者だけに見える (閉じる側に倒す)。見えない人には `404 reservation_pool_not_found`。見えなくなった人の待ち・予約は worker が
  取り消す。
- **予約** (kind `booking`): 開始は枠のタイムゾーン (`tz`) の毎時 0 分、長さは 1 時間〜`max_hours`、今の時間帯から 14 日後の
  終わりまで。**取り消し** (割り当て前)、**延長** (次の時間が空いていれば 1 時間ずつ、`max_hours` まで)、**返却** (利用中)。
- **1 人 1 枠につき 1 つ** (2026-10-06、利用者の決定。以前の「予約は 2 件まで」を置き換え): 順番待ち・予約中 (これからの
  予約も)・利用中 (今すぐ・始まった予約)・返却中 (返却を押したが担当者がまだ「外した」を押していない。管理画面ではまだその人に
  付いているので数える) のどれかがある人は、その枠で「今すぐ」も新しい予約もできない (`409 reservation_already_active`、
  `details`: `reservation_id`・`kind`・`status`)。予約を持ったまま今すぐを頼んで 2 つの枠を押さえることを防ぐ。検査は枠の行の
  ロックの中なので、同じ人が 2 台から同時に「今すぐ」と「予約する」を押しても残るのは 1 つ。同じ今すぐ・同じ時間の予約の
  送り直しは今までどおり何もしない (200)。自分の予約の延長・取り消し・返却はできる。別の枠は別に数える。担当者が代わりに
  予約する操作は無い (§10)。
- **今すぐ (順番待ち)** (kind `walkin`、M99 の仕組み): 空いている枠を、**次の予約が始まるまで**使える (「〜13:00 まで」)。
  割り当てからの保証は `min_hours` か、予約がその枠を必要とする時刻の早い方。保証を過ぎた人は、待つ人がいれば猶予の後に
  入れ替え、予約が始まるときはその時刻に入れ替える (予約の 10 分前に本人へ知らせる)。1 人 1 枠につき 1 つ (上)。
- **予約が優先**: 枠の数の検査は 1 時間ごとに、その時間の予約 (予約中・利用中・返却中) と、保証がその時間にかかっている今すぐの
  利用者の合計が枠の数を超えないこと。今すぐの保証は予約が必要とする時刻で終わるので、**約束 (予約・保証) が破られることは
  ない**: 予約は開始時に必ず枠があり、今すぐの人は保証の内には外されない。
- **担当者の操作**: 割り当てた・外した・入れ替えた・(ほかの人の待ち・予約を) 取り消す・(ほかの人の予約を) 延長する。担当者・
  作った人・管理者ができる。予約の割り当ては開始の 10 分前から (`409 reservation_too_early`)。担当者を選んでいなければ、
  担当者あての知らせは枠を作った人 (いなければ管理者) に届く。
- **知らせはアクティビティとプッシュ** (§5)。チャンネルへの投稿は既定でしない。枠に**記録のチャンネル**を選ぶと、「予約」の
  ボットがそこに 1 行ずつ書く (メンションは取らない: 名前は文字)。ボットはチャンネルに 1 つ (`reservation_bots`)。

## 2. データ

`reservation_pools` / `reservation_bots` / `reservations` / `reservation_notices` (DATA_MODEL.md)。

`reservations.status`:

```text
walkin:  waiting ──割り当てた──▶ holding ──返却する──▶ returning ──外した──▶ done (returned)
            │                       └────────外した / 入れ替えた─────────▶ done (removed)
            └──取り消す / 見えなくなった──▶ cancelled
booking: booked ──割り当てた (開始の 10 分前から)──▶ holding ──(walkin と同じ)──▶ done
            ├──取り消す / 見えなくなった──▶ cancelled
            └──終わりまで割り当てられない──▶ done (expired)
```

- `start_at` / `end_at`: 予約の時間 (毎時 0 分、`end_at > start_at`)。延長は `end_at` を動かす。
- `guarantee_until`: 今すぐは割り当ての時刻 + `min_hours` と、予約がその枠を必要とする時刻の早い方 (割り当てで固定)。
  予約は `end_at` (延長で動く)。
- `evict_notice_at` / `evict_at`: 今すぐの人に「外す」と知らせた時刻と、外す時刻 (待つ人のため: 知らせ + 猶予、予約のため:
  予約の開始)。
- 終わった行 (done / cancelled) は消さずに残す (履歴)。今日の終わった予約はタイムラインに出す。枠を消すと行と知らせも消える。

## 3. API (`/api/v1`)

| | |
|---|---|
| `GET /reservation-pools` | 見える枠の `PoolOut` の一覧 (古い順) |
| `POST /reservation-pools` (201) | `{name, capacity, min_hours?, max_hours?, grace_minutes?, operator_ids?, tz?, enabled?, log_channel_id?, visibility?, visibility_channel_id?, visibility_group_id?}`。管理者 (`403 reservation_manage_restricted`)、21 個目は `409 too_many_reservation_pools`、担当者が無効・ゲスト・ボットなら `400 reservation_operator_invalid`、見える人の指定が足りなければ `400 reservation_visibility_invalid`、記録のチャンネルは自分がメンバーのチャンネル (DM は `400 reservation_channel_unsupported`) |
| `GET /reservation-pools/{id}` | 1 つ |
| `PATCH /reservation-pools/{id}` | 同じ項目の一部 (`log_channel_id` / `visibility_*` は null で外す)。管理者と作った人 |
| `DELETE /reservation-pools/{id}` (204) | 予約・待ち・利用中の記録と知らせごと消す。管理画面のシートには触れない |
| `POST /reservation-pools/{id}/bookings` | `{start_at, hours}` で予約。`400 reservation_booking_invalid` (`details.reason`: grid / past / horizon / duration)、`409 reservation_slot_full` (`details.at`: 最初の満の時間)、ほかの予約・待ち・利用中があれば `409 reservation_already_active`、停止中は `409 reservation_pool_disabled`。同じ時間の予約がもうあれば何もしない (送り直し) |
| `POST /reservation-pools/{id}/reserve` | 「今すぐ (順番待ち)」。メンバー (ゲスト不可)。既に今すぐの待ち・利用中なら何もしない、予約があれば `409 reservation_already_active` |
| `POST /reservations/{id}/extend` | `{hours?: 1}`。予約中・利用中の予約。本人か担当者 |
| `POST /reservations/{id}/cancel` | 待ちか割り当て前の予約。本人か担当者。取り消し済みなら何もしない |
| `POST /reservations/{id}/return` | 「返却する」。本人だけ (`403 reservation_not_yours`)。利用中だけ |
| `POST /reservations/{id}/assign` | 「割り当てた」。担当者 (`403 reservation_operator_required`)。空きが無ければ `409 reservation_pool_full`、予約の開始の 10 分前より前は `409 reservation_too_early` |
| `POST /reservations/{id}/remove` | 「外した」。担当者。利用中・返却中。終わっていれば何もしない |
| `POST /reservation-pools/{id}/swap` | 「入れ替えた」`{remove_id, assign_id}`。担当者。外すと割り当てを 1 回で (`assign_id` は待ちか開始した予約) |
| `GET /channels/{id}/reservation-pools` | 廃止 (M112)。いつも `[]` (M99〜M111 のクライアントはチップを出さない) |

どの操作も、呼んだ人から見た `PoolOut` を返す。`PoolOut`: `id, name, capacity, min_hours, max_hours, grace_minutes, tz, enabled,
operator_ids, log_channel_id, visibility, visibility_channel_id, visibility_group_id, holders, waiting, bookings, todos, next_evict_id,
my_reservation_id, my_active_id, can_manage, can_operate, horizon_days, created_at, updated_at`。`my_active_id` は呼んだ人の
その枠の 1 つの予約 (待ち・予約中・利用中・返却中、無ければ null。古いサーバは送らないので、端末は一覧から同じものを探す)。`bookings` は今日 (枠のゾーン) 以降の予約
(予約中・利用中・今日終わったもの)。`todos` は担当者の作業 (`TodoOut {key, action: assign/swap/remove, reason: free/returned/
booking_ended/guarantee_over, assign_id, remove_id, due_at, upcoming}`、担当者以外は空)。`ReservationOut`: `id, user_id, kind, status,
requested_at, start_at, end_at, assigned_at, guarantee_until, returned_at, evict_at, email, position, step, pair_id, ready, until,
can_extend`。`email` は操作できる人にだけ入る。`until` は空きのある待ちの人が使える終わり (予約の始まり、保証より短いときだけ)。
`can_extend` は呼んだ人の予約が 1 時間延ばせるか。

## 4. 順番の決め方 (plan)

`app/modules/reservations/plan.py` の純粋な関数 (tests/test_reservation_plan.py)。ページ・知らせ・worker・予約の検査が同じもの
を使う。

- **ある時刻の枠を求める人** (この順): 1. 始まった予約 (開始の早い順)、2. 今すぐの待ち (古い順)。
- **当てる枠** (この順): 1. 空き (利用中 + 返却中 < 枠の数) → `step = assign`、2. 手放された枠 (返却中、時間の終わった予約、
  早い順) → `step = swap` (すぐできる)、3. 保証を過ぎた今すぐの人 (保証の終わりが早い順) → `step = swap` (予約のためならすぐ、
  待つ人のためなら猶予の後)。残りは `step = wait`。
- **担当者の作業** (`todos`、すぐできるものだけ): `assign:<id>` (空きに割り当てる)、`swap:<外す id>:<入る id>`、`remove:<id>`
  (返却された・予約時間の終わった枠を待つ人がいない)。**まもなく** (`upcoming`): 10 分以内に始まる予約 (`booking:<id>`、その時に
  外す人がいれば `remove_id`)。
- **今すぐの終わり** `free_until`: 今から、予約 (予約中・利用中) と他の今すぐの人の保証がすべての枠を必要とする最初の時刻
  (上限は今 + `min_hours`)。割り当てのときの保証になる。待つ人が 2 人以上空きに当たるときは、前の人がその枠を使う前提で数える。
- **予約の検査** `booking_conflict`: 1 時間ごとに、重なる予約 + その時間に保証のかかる今すぐの人 + 1 ≤ 枠の数。最初に満たない
  時間を返す (`409 reservation_slot_full` の `details.at`)。延長は延ばす分の時間だけを見る。
- **並行**: どの変更も枠の行を `FOR UPDATE` でロックしてから読む。最後の 1 枠を 2 人が同時に予約しても後の方は `409`。
  同じ人の「今すぐ」と「予約する」(や 2 つの予約) が同時に来ても、後の方は `409 reservation_already_active`。担当者
  2 人が同時に押しても順に処理され、2 回目は「済んでいる」ので何もしない。
- **worker**: リマインダーと同じループ (`SCHEDULED_SEND_INTERVAL_SECONDS`、15 秒、`reservations.tick`)。動いている枠 (待ち・
  予約中・利用中のある枠) ごとに: 見えなくなった人の待ち・予約を取り消す、終わりまで割り当てられなかった予約を `expired` に、
  外す人に知らせる (待つ人のため: 保証を過ぎたとき、予約のため: 開始の 10 分前)、担当者の作業を知らせる (予約は開始の
  10 分前に 1 回、時間の終わった予約、猶予の過ぎた入れ替え)、なくなった作業を済みにする。変化がなければ何も書かない。
- **外す時刻は毎回計算し直す** (レビュー v0.1.37 #5): 保証を過ぎた今すぐの人の外す時刻 (`evict_at`) は、その席を求める相手
  ごとの時刻のうち一番早いもの。予約なら `max(保証の終わり, 予約の開始)`、待つ人なら「最初に知らせた時刻 (`evict_notice_at`) +
  猶予」(知らせた時刻 `evict_at` より前にはしない)。先に待つ人のために猶予付きの時刻を知らせた後で、予約がそれより早く席を
  必要とすれば (開始の 10 分前の時点で)、時刻を予約の開始に改めて本人に知らせ直し、開始時刻には入れ替えの作業が出る。その予約が
  取り消されれば待つ人の時刻に戻して知らせ直す。待つ人も予約もいなくなれば従来どおり「そのまま使えます」。改めた時刻と前の時刻が
  どちらも過ぎていれば知らせ直さない (作業はどちらにしても出ている)。

## 5. 知らせ (アクティビティとプッシュ)

M99 のボットからの DM とチャンネルの投稿はやめた。知らせは **アクティビティの項目** (`reservation_notices`、種類
`reservation`) と、同じトランザクションの `reservation.notice` (audience user) で、プッシュはそこから作る (PUSH_NOTIFICATIONS.md
§4、`kind = reservation`)。コミットの後に送るものは無い (M99 の「DM が 1 つ欠けうる」は解消)。

| いつ | 誰へ | 文 (例) |
|---|---|---|
| 空きに当たった待ち (`assign:<id>`) | 担当者 | 「🙋 〇〇 さん (アドレス) に「枠」を割り当ててください (空きがあります)。」 |
| 予約の開始の 10 分前 (`booking:<id>`) | 担当者 | 「🗓 13:00 から 〇〇 さん (アドレス) が「枠」を予約しています (〜16:00)。△△ さん (アドレス) を外して割り当ててください。」 |
| 開始した予約 (前に知らせていないとき) | 担当者 | 「🗓 〇〇 さん (アドレス) の予約 (13:00〜16:00) が始まりました。「枠」を割り当ててください。」 |
| 入れ替えできる (`swap:…`) | 担当者 | 「🔁 「枠」: △△ さん (…) (保証時間が終了) を外して 〇〇 さん (…) に割り当ててください。」 |
| 返却された・予約時間が終わった (`remove:<id>`) | 担当者 | 「🔙 … が「枠」を返却しました。外して「外した」を押してください。」/「⏹ … の予約時間 (16:00 まで) が終わりました。…」 |
| 外される (待つ人のため) | 本人 | 「⏳ 「枠」の保証時間 (…まで) が過ぎ、待っている人がいます。HH:MM 以降に担当者が外します。…」 |
| 外される (予約のため、開始の 10 分前) | 本人 | 「⏳ 「枠」は 13:00 から予約の人が使います。その時刻に担当者が外します。」 |
| 外されなくなった | 本人 | 「👍 「枠」を待つ人がいなくなったので、そのまま使えます。」 |
| 割り当てた / 外した・返却が済んだ | 本人 | 「✅ 「枠」が割り当てられました。…」/「⏹ 「枠」から外されました。」 |
| 担当者が取り消した | 本人 | 「↩️ 「枠」の予約 (…) は担当者 (〇〇 さん) が取り消しました。」 |
| 割り当てられないまま終わった | 本人 | 「⌛ 「枠」の予約 (…) は割り当てられないまま時間が過ぎました。」 |

- **担当者の作業は 1 つのキーで全員に**送り (`reservation_notices.key`、1 人 1 キー 1 回)、誰かが押した (またはもう要らない)
  ときに**全員の分を済み** (`done_at`、`done_by`) にして `activity.updated` で知らせる。押した担当者自身には済みの写しを
  黙って残す (プッシュなし、キーは「知らせた」として数える)。済みの項目はアクティビティで薄く「対応済み」と出し、未読の数に
  入れない。プッシュを作る時点で済んでいれば送らない (すでに出たプッシュは消さない)。
- 同じキーの作業はもう一度知らせない (ページの「担当者の作業」には出る)。
- **担当者あての知らせは、今その枠を操作できる人だけ** (レビュー v0.1.37 #2): 作業の文にはアドレスが入るので、宛先は API の
  `can_operate` と同じ規則で選ぶ (担当者のうち無効化・ゲスト・ボットでない人。いなければ作った人 (ゲストでなければ)、それも
  だめなら管理者)。「知らせた」かどうかも今の宛先について数えるので、担当者全員が権限を失った作業は、代わりの宛先に改めて届く
  (担当者に足された人にも、まだ残っている作業が届く)。権限を失う前に書かれた項目は消さないが、届ける・見せるときにもう一度
  確かめる: アクティビティの一覧と未読の数、WebSocket の `reservation.notice` (audience を空にする)、プッシュ (作らない) の
  どれにも、操作できない人には出さない (`app/modules/reservations/access.py`)。権限が戻れば、残っている項目はまた見える。
- アクティビティは `include=reservation` を付けたクライアントにだけ返す (M76 の canvas_mention と同じ: M39〜M111 の端末は
  知らない種類で落ちる)。済んでいない項目はメンションと同じに数える (バッジが赤くなる。本人あての知らせなので)。

## 7. 同期

- `reservation.updated` (audience **all**、seq なし) `{pool_id, deleted}`。中身は人によって違う (自分の予約、担当者だけの
  アドレスと作業) ので載せず、**端末は受け取ったら `GET /reservation-pools` で読み直す** (続けて届いたものは 300 ms で 1 回に
  まとめる)。bootstrap のたびにも読む (タイルの数字のため)。見えない枠の id が届くことはある (中身は無い)。
- `reservation.notice` (audience user) `{item_id, pool_id, reservation_id, text, operator, at}`: アクティビティのバッジを
  読み直し、開いている端末はバナー / 通知を出す。
- `activity.updated` `{item_ids}`: 済みになった作業 (M76 の消された抜粋と同じイベント)。端末はその行を済みにし、バッジを
  読み直す。

## 8. Claude Premium シートの使い方 (研究室の例)

1. 管理者が Desktop / Web のサイドバーの「予約」→「枠を追加」: 名前「Claude Premium シート」、枠の数 3、予約の最長 6 時間、
   今すぐの保証 6 時間、猶予 15 分、担当者に管理係の学生 (Claude の管理画面を操作できる人)。研究室のメンバーだけに見せるなら
   「見える人」をグループ (例 @lab) に。記録を残したければ「記録を書くチャンネル」(例 #claude)。
2. 使いたい人は「予約」→「予約する」で日付・開始・長さを選ぶ。今空いていてすぐ使いたいなら「今すぐ (順番待ち)」(次の予約が
   始まるまで)。
3. 担当者には、予約の 10 分前に「13:00 から 〇〇 さん (アドレス) …」がアクティビティとプッシュで届く。時間になったら管理画面で
   その人を Premium にして「割り当てた」(前の人を外すなら「入れ替えた」)。ほかの担当者の通知は「対応済み」になる。
4. 予約の時間が終わると担当者に「外して」が届く。管理画面で外して「外した」。使い終わった人が早めに「返却する」を押しても同じ。
5. 担当者は「予約」のページの「担当者の作業」を見れば、今すべきこと (と 10 分以内のこと) が全部わかる。

## 9. 既存の枠の移行 (0084)

- M99 の枠は残る (名前・枠の数・保証・猶予・担当者・作った人・待ちと利用中の行)。行はすべて今すぐ (`kind = walkin`) になる。
- 見える人: **非公開チャンネルの枠はそのチャンネルのメンバー** (`visibility = channel`)、公開チャンネルの枠は全員。
- 記録のチャンネルは空 (どこにも書かない)。チャンネルのボットは残る (記録のチャンネルにそのチャンネルを選べばまた使う)。
- `max_hours` は 6。`reservations.channel_id` と `ready_notified_at` は消える (知らせは `reservation_notices` が覚える)。
- 移行の時点で利用中の人の保証 (`guarantee_until`) はそのまま。その時間は予約から守られる。

## 10. 残り・やらないこと

- スマホでの枠の設定、ボットの名前の変更、予約の繰り返し (毎週など)、優先度、ほかの人の代わりの予約。
- 管理画面 (Claude など) の自動操作。Taylis は記録と順番と知らせだけを持つ。
- 履歴の画面 (終わった行は残しているが、見るのは今日のタイムラインと記録のチャンネル)。
- 出てしまったプッシュは、ほかの担当者が対応しても消さない (アクティビティの項目は済みになる)。サイレントプッシュでの消去は
  PUSH_NOTIFICATIONS.md の置き場所だけ。
- タイムラインは端末のタイムゾーンで 1 日を描く。枠の `tz` が端末と違い、時差が 1 時間単位でないと予約の格子とずれる。
