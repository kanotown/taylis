# タスクとカンバン (M55〜M56)

テスターの要望 (2026-10-01): 個人用と共有用の ToDo、カンバン。利用者と決めたこと (2026-10-01):

- キャンバスのチェックリストとは別の**専用の「タスク」**。キャンバスの `- [ ]` は今のまま軽いメモ用に残す。
- カンバンの列は**固定の 3 列**: 未着手 / 進行中 / 完了。列を足すのは要望が出てから。
- 共有のタスクは**チャンネルに 1 つのボード** (見られる人 = チャンネルのメンバー。カレンダーと同じ考え方)。個人用は自分だけのリスト。
- 一緒に入れるもの: **メッセージからタスクを作る**、**期限の通知**、**期限をカレンダーに出す**、**担当者は複数**。

## 1. データ

`tasks`

| 列 | 型 | 意味 |
|---|---|---|
| id | uuid (v7) | |
| channel_id | uuid NULL | NULL = 個人用 (owner_id の人だけ)。あればそのチャンネルのボード |
| owner_id | uuid | 作った人 |
| title | text (1〜200) | |
| notes | text NULL (≤ 4000) | Markdown (メッセージと同じ記法) |
| status | `todo` / `doing` / `done` | 列 |
| position | double | 列の中の並び (小さいほど上)。移動のときは前後の間の値を入れる (詰まったらその列だけ振り直す) |
| due_on | date NULL | 期限 (日付だけ。時刻は持たない) |
| source_message_id | uuid NULL | メッセージから作ったとき。元のメッセージが消えても残す (リンクだけ切れる) |
| completed_at / completed_by | | 完了にした時と人 (完了から戻したら NULL) |
| client_task_id | text NULL | 作成の再送で二重にならないため (作った人ごとに一意) |
| created_at / updated_at / deleted_at | | 論理削除 (イベントで端末に消えたことを伝える) |

`task_assignees`: (`task_id`, `user_id`) 主キー。共有のタスクではチャンネルのメンバーだけを付けられる。個人用のタスクには付けない
(いつも本人)。チャンネルから抜けた人は、そのチャンネルのタスクの担当から外す。

## 2. 権限

| 操作 | 個人用 | 共有 (チャンネル) |
|---|---|---|
| 見る | 本人 | チャンネルのメンバー |
| 作る・直す・動かす・完了にする | 本人 | 投稿できるメンバー (アーカイブ済み・投稿制限は既存の規則) |
| 消す | 本人 | 作った人、担当者、チャンネルのオーナー、管理者 |

DM には共有のボードを作らない (カレンダーと同じ)。DM のメッセージからタスクを作ると個人用になる。

## 3. API (`/api/v1`)

- `GET /tasks?channel_id=` — そのボードの全タスク (完了は最近 100 件まで。`include_done=all` で全部)。
- `GET /tasks/mine` — 個人用のタスクと、自分が担当の共有タスク (参加しているチャンネルのもの)。完了は最近 50 件まで。
- `GET /tasks/due?from=YYYY-MM-DD&to=YYYY-MM-DD` — 期限がその範囲のタスク (見られるもの全部。カレンダー用、最長 100 日)。
- `POST /tasks` `{channel_id?, title, notes?, status?, due_on?, assignee_ids?, source_message_id?, client_task_id?}`
- `PATCH /tasks/{id}` (変えた項目だけ。`assignee_ids` は全体を置き換え) / `DELETE /tasks/{id}`
- `POST /tasks/{id}/move` `{status, before_id? , after_id?}` — 列の移動と並べ替え (position はサーバが決める)。
- 出力 `TaskOut`: 上の列 + `assignee_ids` + `channel_name` + `source` (`{message_id, channel_id, excerpt}` か null) + `can_delete`。

## 4. 同期

- outbox のイベント: `task.updated` (作成・変更・移動。タスク全体) と `task.deleted` (`{id, channel_id}`)。宛先は共有なら
  チャンネルのメンバー、個人用なら本人。チャンネルの seq は使わない。
- 人ごとに違う項目は載せない (`can_delete` は端末が `owner_id`・担当者・自分の役割から判断する。必要なら `deleter_ids` を載せる)。
- 端末は開いているボード・自分のタスク・カレンダーの期間に関係するものだけ更新し、再接続で読み直す (カレンダーと同じ)。

## 5. 通知

- **割り当て**: 共有のタスクで担当に加えられた人に「〇〇 がタスクを割り当てました: 題名 (#チャンネル)」(`kind = task`)。
  自分で自分を加えたときは出さない。
- **期限**: 未完了のタスクの担当者 (個人用は本人) に、期限の日の 8:00 (その人のタイムゾーン) に「今日が期限: 題名」。
  タイムゾーンはカレンダーの通知と同じ規則 (端末から送られたもの → おやすみ時間の設定 → Asia/Tokyo)。
  M12e のリマインダーと同じ worker で送る。期限・担当・完了が変わったら付け直す。おやすみ時間・一時停止の間は送らない。
- 「自分 → 通知」に「タスク (割り当て・期限)」のオン/オフ (既定オン)。

## 6. 画面

| 場所 | Desktop / Web | iOS / Android |
|---|---|---|
| チャンネル | タブ列に「タスク」: 3 列のカンバン (ドラッグで移動・並べ替え)、列の下に「＋ 追加」 | 「タスク」タブ: 列を上部の切り替え (未着手 3 / 進行中 1 / 完了) で見せ、カードの長押し・メニューで移動 |
| 自分 | サイドバーの「タスク」: 個人用のリストと「自分の担当」(ボードごと) | ホームのタイル「タスク」: 同じ内容 |
| カード | 題名、担当者のアイコン、期限 (過ぎたら赤)、メモの有無、元のメッセージ | 同じ |
| 詳細 | ダイアログ: 題名、メモ、状態、期限、担当者 (メンバーから選ぶ)、元のメッセージへのリンク、削除 | 全画面 |
| メッセージから | ホバーと長押しのメニューに「タスクにする」: 題名に本文の抜粋、元のメッセージを付けた作成フォーム | 長押しのメニュー |
| カレンダー | 期限のあるタスクを、その日の終日の行に「☐ 題名」(完了は打ち消し線) で出す。押すとタスクの詳細 | 同じ |

## 7. 実装の順番

- **M55**: サーバ (表・API・イベント・通知) と Desktop / Web (ボード、自分のタスク、メッセージから作る、カレンダーへの表示)。
- **M56**: iOS と Android。
- あとで: 列を足す、繰り返しのタスク、サブタスク、期限の時刻。
