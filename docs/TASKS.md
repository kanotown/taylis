# タスクとカンバン (M55〜M56)

テスターの要望 (2026-10-01): 個人用と共有用の ToDo、カンバン。利用者と決めたこと (2026-10-01):

- キャンバスのチェックリストとは別の**専用の「タスク」**。キャンバスの `- [ ]` は今のまま軽いメモ用に残す。
- カンバンの列は**固定の 3 列**: 未着手 / 進行中 / 完了。列を足すのは要望が出てから (M81 で足した、§11)。
- 共有のタスクは**チャンネルに 1 つのボード** (見られる人 = チャンネルのメンバー。カレンダーと同じ考え方)。個人用は自分だけのリスト。
- 一緒に入れるもの: **メッセージからタスクを作る**、**期限の通知**、**期限をカレンダーに出す**、**担当者は複数**。

**状態**: M55 (サーバと Desktop / Web) は完了 (2026-10-01、移行 0053)。実装で決めたこと・直したことは §8。M56 (iOS / Android) も完了 (2026-10-01、iOS build 56)。iOS: 列は上部の切り替え、移動はカードの長押しと ⋯ のメニュー (ドラッグは無し)、詳細は全画面のフォーム、ホームのタイル「タスク」、メッセージの長押しの「タスクにする」、カレンダーの行、「自分 → 通知」の切り替え、`kind = task` のプッシュでタスクを開く、Android は実装済み (2026-10-01、§9)。

## 1. データ

`tasks`

| 列 | 型 | 意味 |
|---|---|---|
| id | uuid (v7) | |
| channel_id | uuid NULL | NULL = 個人用 (owner_id の人だけ)。あればそのチャンネルのボード |
| owner_id | uuid | 作った人 |
| title | text (1〜200) | |
| notes | text NULL (≤ 4000) | Markdown (メッセージと同じ記法) |
| status | `todo` / `doing` / `done` | 列 |
| position | double | 列の中の並び (小さいほど上)。移動のときは前後の間の値を入れる (詰まったらその列だけ振り直す) |
| due_on | date NULL | 期限 (日付だけ。時刻は持たない) |
| source_message_id | uuid NULL | メッセージから作ったとき。元のメッセージが消えても残す (リンクだけ切れる) |
| completed_at / completed_by | | 完了にした時と人 (完了から戻したら NULL) |
| client_task_id | text NULL | 作成の再送で二重にならないため (作った人ごとに一意) |
| created_at / updated_at / deleted_at | | 論理削除 (イベントで端末に消えたことを伝える) |

`task_assignees`: (`task_id`, `user_id`) 主キー。共有のタスクではチャンネルのメンバーだけを付けられる。個人用のタスクには付けない
(いつも本人)。チャンネルから抜けた人は、そのチャンネルのタスクの担当から外す。

## 2. 権限

| 操作 | 個人用 | 共有 (チャンネル) |
|---|---|---|
| 見る | 本人 | チャンネルのメンバー |
| 作る・直す・動かす・完了にする | 本人 | 投稿できるメンバー (アーカイブ済み・投稿制限は既存の規則) |
| 消す | 本人 | 作った人、担当者、チャンネルのオーナー、管理者 |

DM には共有のボードを作らない (カレンダーと同じ)。DM のメッセージからタスクを作ると個人用になる。

## 3. API (`/api/v1`)

- `GET /tasks?channel_id=` — そのボードの全タスク (完了は最近 100 件まで。`include_done=all` で全部)。
- `GET /tasks/mine` — 個人用のタスクと、自分が担当の共有タスク (参加しているチャンネルのもの)。完了は最近 50 件まで。
- `GET /tasks/due?from=YYYY-MM-DD&to=YYYY-MM-DD` — 期限がその範囲のタスク (見られるもの全部。カレンダー用、最長 100 日)。
- `POST /tasks` `{channel_id?, title, notes?, status?, due_on?, assignee_ids?, source_message_id?, client_task_id?}`
- `PATCH /tasks/{id}` (変えた項目だけ。`assignee_ids` は全体を置き換え) / `DELETE /tasks/{id}`
- `POST /tasks/{id}/move` `{status, before_id? , after_id?}` — 列の移動と並べ替え (position はサーバが決める)。
- 出力 `TaskOut`: 上の列 + `assignee_ids` + `channel_name` + `source` (`{message_id, channel_id, excerpt}` か null) + `can_delete`。

## 4. 同期

- outbox のイベント: `task.updated` (作成・変更・移動。タスク全体) と `task.deleted` (`{id, channel_id}`)。宛先は共有なら
  チャンネルのメンバー、個人用なら本人。チャンネルの seq は使わない。
- 人ごとに違う項目は載せない (`can_delete` は端末が `owner_id`・担当者・自分の役割から判断する。必要なら `deleter_ids` を載せる)。
- 端末は開いているボード・自分のタスク・カレンダーの期間に関係するものだけ更新し、再接続で読み直す (カレンダーと同じ)。

## 5. 通知

- **割り当て**: 共有のタスクで担当に加えられた人に「〇〇 がタスクを割り当てました: 題名 (#チャンネル)」(`kind = task`)。
  自分で自分を加えたときは出さない。
- **期限**: 未完了のタスクの担当者 (個人用は本人) に、期限の日の 8:00 (その人のタイムゾーン) に「今日が期限: 題名」。
  タイムゾーンはカレンダーの通知と同じ規則 (端末から送られたもの → おやすみ時間の設定 → Asia/Tokyo)。
  M12e のリマインダーと同じ worker で送る。期限・担当・完了が変わったら付け直す。おやすみ時間・一時停止の間は送らない。
- 「自分 → 通知」に「タスク (割り当て・期限)」のオン/オフ (既定オン)。

## 6. 画面

| 場所 | Desktop / Web | iOS / Android |
|---|---|---|
| チャンネル | タブ列に「タスク」: 3 列のカンバン (ドラッグで移動・並べ替え)、列の下に「＋ 追加」 | 「タスク」タブ: 列を上部の切り替え (未着手 3 / 進行中 1 / 完了) で見せ、カードの長押し・メニューで移動 |
| 自分 | サイドバーの「タスク」: 個人用のリストと「自分の担当」(ボードごと) | ホームのタイル「タスク」: 同じ内容 |
| カード | 題名、担当者のアイコン、期限 (過ぎたら赤)、メモの有無、元のメッセージ | 同じ |
| 詳細 | ダイアログ: 題名、メモ、状態、期限、担当者 (メンバーから選ぶ)、元のメッセージへのリンク、削除 | 全画面 |
| メッセージから | ホバーと長押しのメニューに「タスクにする」: 題名に本文の抜粋、元のメッセージを付けた作成フォーム | 長押しのメニュー |
| カレンダー | 期限のあるタスクを、その日の終日の行に「☐ 題名」(完了は打ち消し線) で出す。押すとタスクの詳細 | 同じ |

## 7. 実装の順番

- **M55**: サーバ (表・API・イベント・通知) と Desktop / Web (ボード、自分のタスク、メッセージから作る、カレンダーへの表示)。
- **M56**: iOS と Android。
- あとで: 列を足す、繰り返しのタスク、サブタスク、期限の時刻 (M81 でサーバと Desktop / Web、スマホは M84。§11)。

## 8. M55 で決めたこと・直したこと

設計の問題として直したもの:

1. **元のメッセージの抜粋をコピーで持つと、編集・削除で消した本文が残る** (SECURITY.md §3 はリマインダーに本文のコピーを
   持たせない)。抜粋は作った時に 1 行で持つが、元のメッセージを編集すると読み直し、削除するとリンク (`message_id`) と抜粋を
   消す (`source` は `{message_id: null, channel_id, excerpt: null}` になり、端末は「元のメッセージは削除されました」)。outbox の
   message.updated (本文の変更) / message.deleted を受ける TaskSourceHandler (messages は tasks を呼ばない)。自分用のタスクの
   持ち主がそのメッセージを読めなくなっていたら、編集後の抜粋は渡さず null にする。
2. **期限の通知の「端末から送られたタイムゾーン」は、操作した本人の分にしか無い** (担当者が 3 人なら、ほかの 2 人の端末は
   要求に関係しない)。通知の行 (`task_due_alarms`) に tz を持ち、作る時に「操作した本人なら要求の `tz` → おやすみ時間のゾーン →
   Asia/Tokyo」で決め、その後は行に残す (期限を変えても、その人のゾーンで計算し直す)。
3. **割り当てと期限のプッシュには宛先が本人のイベントが要る** (§4 の task.updated はチャンネル全員宛て)。`task.assigned`
   (加えた人以外の新しい担当者に。自分で加えたときは出さない) と `task.due` (期限の日の 8:00 に 1 回) を足した。アプリを開いている
   Desktop / Web はこれでデスクトップ通知を出す (カレンダーの `calendar.alarm.updated` と同じ)。
4. **`can_delete` は人ごとに違う** ので task.updated には載せず、`{task, deleter_ids}` にした (カレンダーの `editor_ids` と同じ。
   作成者 (まだメンバーなら)・担当者・チャンネルのオーナー・メンバーの管理者。アーカイブ済みなら空、自分用は本人)。
5. **ボードのタスクを別のチャンネルのメッセージから作ると、そのチャンネルの本文がボードのメンバーに見える**。ボードのタスクは
   そのチャンネルのメッセージからだけ (`400 task_invalid_source`)。自分用なら、自分が読めるメッセージ (未参加の公開チャンネルも)
   から作れる。読めないメッセージは `404 message_not_found`。

API の細かいところ:

- `GET /tasks/{id}` を足した (通知から開く)。見られないタスクはどの操作でも `404 task_not_found`。ボードの一覧はメンバーでなければ
  `403 not_a_member`、DM は `400 task_channel_unsupported` (作成も)。
- `GET /tasks?channel_id&include_done=recent|all`。`/tasks/due?from&to` の `to` は含まない日付 (カレンダーの `to` と同じ)、
  100 日まで、完了も含む、1000 件まで。`/tasks/mine` の完了は自分用と担当を合わせて最近 50 件。
- 並び: 新しいカード・状態だけの変更 (PATCH の `status`)・位置を指定しない移動は、未着手 / 進行中の一番下、完了の一番上 (新しい
  完了が上)。`move` の `after_id` は「すぐ上に来るカード」、`before_id` は「すぐ下」。どちらかでよく、両方あれば `after_id` を
  優先。その列に無い (動いた・消えた) カードは無視して既定の場所。位置は間の真ん中で、間が 1e-6 より狭ければその列を 1024 おきに
  振り直してから入れ、振り直したカードにも task.updated を出す。
- 作る・直す・動かす・完了にするは「投稿できるメンバー」(アーカイブ済みは `409 channel_archived`、投稿制限なら owner / admin
  だけ `403 posting_restricted`)。消すは §2 のとおり作成者・担当者・オーナー・管理者 (投稿制限には関係なく、アーカイブ済みは不可)。
- 題名は空白を 1 つにまとめる (1〜200)。メモは空なら null。担当者は 50 人まで、重複は 1 つに。`client_task_id` は 64 文字までの
  文字列。消したタスクの作成を再送すると 404 (2 つ目は作らない)。
- 未完了のタスクは 1 つのボード (自分用は 1 人) に 1000 件まで (`409 task_limit_reached`。完了から戻す時も数える)。
- 通知: 割り当てのプッシュはリアクションと同じく、その会話の通知が「なし」・ミュート中・DND・別の端末で操作中なら出さない。
  計画の時点でタスクが消えた・完了していれば出さない。期限の通知はリマインダー・予定と同じく、会話の設定は見ず DND の間は
  出さない (後で送り直さない)。期限の日の 8:00 を過ぎてから期限を付けた (または今日にした) ときは、その日の通知は出さない。
  アーカイブ済みのチャンネルのタスクは期限の通知を出さない (誰も完了にできないため)。`notify_tasks` がオフなら、どちらの
  プッシュも出さない (イベントは届く。Desktop / Web もデスクトップ通知を出さない)。
- プッシュは `kind = task`、`task_id` (APNs の本体と FCM の data)、`collapse_key = task:<id>`、タイトル「タスク」。
- 期限の通知の行は消さずに残し、時刻 (`fire_at`) の変わらない行は状態をそのままにする: 同じ期限で 2 度送らない (完了から戻しても、
  題名を変えても。期限を別の日にしてから戻すと、時刻が変わるので、まだ先なら改めて送る)。外れた人・完了・削除は cancelled、戻せば pending (時刻がまだ先なら)。

Desktop / Web で決めたこと:

- チャンネルの「タスク」タブは公開・非公開チャンネルだけ (広い画面は見出しの「メッセージ | キャンバス | 予定 | タスク」、スマホはタブの列)。
  3 列は広い画面では等幅、768px より狭いとそれぞれ約 300px でボードの中だけ横にスクロール (列に吸い付く。ページは横に動かない)。
- ドラッグはブラウザ標準の HTML5 DnD (依存を足さない)。落とす場所に線を出し、元の場所に落としたら何も送らない。手元で先に動かし、
  応答で置き換える。断られたら戻してエラーを出す。タッチのドラッグは無く、スマホとキーボードはカードの「…」(移動 → 列、上へ、
  下へ、削除) で動かす。
- 「＋ 追加」は最後のカードのすぐ下。Enter で追加して入力欄は開いたまま (続けて足せる)、Esc で閉じる。変換中の Enter は無視。
- 投稿できないボード (アーカイブ済み・投稿制限) は理由の帯を出し、ドラッグと追加を消す (メニューは `can_delete` なら削除だけ)。
- カード: 題名 (完了は打ち消し線)、担当者のアイコン (3 人まで重ね、残りは「+N」)、期限 (M/D、今日は「今日」、過ぎた未完了は赤)、
  メモの印、元のメッセージの印 (`message_id` があるときだけ。押すと「メッセージ」に切り替えてそのメッセージへ)。
- 詳細のダイアログ: 題名・メモ・状態 (3 つの切り替え)・期限 (日付の入力と消すボタン)・担当者 (自分を先頭に、メンバーのチェック。
  9 人以上なら名前で絞る)・元のメッセージ (抜粋とリンク、削除済みなら「元のメッセージは削除されました」)・削除 (確認つき)。
  保存は変わった項目だけを送り、期限を変えたときは端末の `tz` も送る。作成にも使い、「追加先」で「#ch のボード」か「自分のタスク」。
- 「タスクにする」(メッセージのホバーと長押しのメニュー、「リマインド…」の次): 題名は DM の一覧と同じ 1 行の抜粋 (200 文字まで)、
  元のメッセージ付き。DM・グループ DM と、投稿できないボードのメッセージは自分のタスクに固定。
- サイドバーとスマホ幅のホームのタイルに「タスク」(カレンダーの次)。「自分のタスク」(チェックで完了 / 戻す、「＋ 追加」、完了は
  「完了 (N)」に畳む) と「自分の担当」(チャンネルごと、見出しを押すとその「タスク」タブ。投稿できるボードならチェックで完了)。
- カレンダー: 月は終日の予定、タスク、時刻の予定の順に 3 行まで (残りは「+N」)、週は終日の段、一覧は「期限」の行。色は
  チャンネルの色 (自分用は灰青)。絞り込みの「自分」はタスクでは「自分用と自分の担当」(自分のタスクと同じ)。
- `task.assigned` / `task.due` はアプリを開いていればデスクトップ通知 (DND・一時停止・`notify_tasks` オフでは出さない)。
  ブラウザでは押すとタスクを開く。Tauri の通知プラグインは押されたことを返さないので、Desktop アプリでは前に出るだけ。
- タスクは端末に保存しない (Tauri の SQLite にも入れない)。開いているボード・自分のタスク・カレンダーの期間だけを持ち、再接続で
  読み直す。手元より古い `updated_at` のイベントでは置き換えない。

## 9. M56 (Android) で決めたこと

- `TaskHub` (sync/Tasks.kt) は Desktop の src/sync/tasks.ts の移植 (ボード・自分のタスク・カレンダーの期間の窓、task.* の適用、
  先に動かす移動と断られた時の戻し、再接続での読み直し、チャンネルから抜けたら外す)。規則は ui/TaskRules.kt (tasks.ts の移植)。
- チャンネルの「タスク」タブは「予定」の次 (公開・非公開チャンネルだけ)。上部の切り替えは「未着手 N」「進行中 N」「完了」(完了は最近
  100 件までなので数を出さない)。カードの ⋮ と長押しで同じメニュー (「〇〇」へ移動・上へ・下へ・削除)。列の移動は位置を指定しない
  (サーバの既定: 未着手 / 進行中は一番下、完了は一番上)。「＋ 追加」は開くとキーボードが出て、追加しても開いたまま。
- ホームのタイル「タスク」はカレンダーの次。チェックで完了 / 未着手に戻す (PATCH の `status`)。＋ で全画面フォーム (追加先は自分のタスク)。
- 「タスクにする」は長押しのシートの「リマインド…」の次。題名は通知と同じ 1 行 (200 文字まで)、追加先は Web と同じ規則。
- カレンダー (一覧・月) は期限のタスクを終日の予定の後・時刻の予定の前に「☐ 題名」(完了は ☑ と打ち消し線) で出し、月のマスに
  ボードの色の点を足す。チャンネルの「予定」タブには出さない (そのチャンネルには「タスク」タブがある)。
- 通知: kind task のプッシュは `task:<id>` ごとの通知。押すとそのチャンネルの「タスク」タブ (自分用は「タスク」) を開き、タスクの
  フォームを重ねる。アプリを開いている間の task.assigned / task.due はスナックバーと端末の通知 (`notify_tasks` オフならどちらも出さず、DND の間は端末の通知だけ出さない)。
  「自分 → 通知」の「タスク (割り当て・期限)」はサーバが `notify_tasks` を返すときだけ出す。

## 10. キャンバスのチェックリストから作る (M72、CANVAS.md §18.3)

冒頭の「キャンバスの `- [ ]` は軽いメモ用に残す」は変えない。担当や期限を追いたい行だけを、このタスクにできるようにした
(2 つ目のタスクの仕組みは作らない)。

- `POST /tasks` に `source_canvas_id` と `source_canvas_line` (今の本文にあるチェックリストの行そのもの)。両方そろって、
  `source_message_id` と同時でないこと。読めないキャンバスは `404 canvas_not_found`、ボード (や DM で共有) のタスクはその会話の
  キャンバスからだけ、行が本文に無ければ `400 task_invalid_source`。DM のキャンバスからは、メッセージと同じく自分用か、担当者を
  付けてその DM で共有 (L9)。
- 出力の `canvas_source` = `{canvas_id, excerpt}` (`source` とは別。キャンバスが完全に消えると `canvas_id` が null)。
- ~~**一方向**~~ **M80 で双方向にした (CANVAS.md §22)**: 作った時にサーバがその行の末尾に見えない印 (` <!--task:<id>-->`) を
  書き、以後はタスクを完了にする・戻すとその行のチェックが付く・外れ、キャンバスでチェックを付ける・外すとタスクが完了・
  未着手に戻る (それぞれ変えた人として。変える権利が無ければ何もしない)。抜粋は今までどおり作った時の写し。
- Desktop / Web: キャンバスの表示のチェックリストの未完了の行に「タスクにする」。ダイアログは行の文・`📅 YYYY-MM-DD`・行の
  メンションで埋める。カードには元のキャンバスの印 (押すとそのキャンバス)、詳細に「元のキャンバス」。iOS / Android は M73。

## 11. 期限の時刻・サブタスク・繰り返し・列を足す (M81)

§7 の「あとで」の 4 つ。利用者の了承 (2026-10-02、「一旦一通り完成まで進めたい」): どれも推奨の (簡単な) 案で入れる。
M81 はサーバと Desktop / Web、スマホ (iOS / Android) は M84。

### 11.1 決めたこと

### 11.2 データ (移行 0069)

`tasks` に足す列:

### 11.3 API (`/api/v1`)

出力 (`TaskOut` / `TaskData`) に足す項目 (足すだけ。今の項目の意味は変えない):

- `due_at` (日時 | null、UTC)、`due_tz` (string | null)
- `subtasks`: `[{id, title, done}]` (無ければ `[]`)
- `rrule` (string | null)
- `column_id` (uuid | null。null = その `status` の組み込みの列)

`MessageTaskOut` (メッセージの下のチップ) に `due_at`。`task.due` に `due_at`。

入力:

- `POST /tasks` / `PATCH /tasks/{id}` に `due_at`・`subtasks`・`rrule`。
  - `due_at` (オフセット付きの日時): `due_on` はそのゾーン (要求の `tz` → タスクの `due_tz` → おやすみ時間のゾーン → Asia/Tokyo) での日付になり、`due_on` を一緒に送っても `due_at` が勝つ。秒は切り捨て。
    `due_at: null` は日付だけに戻す (`due_on` は残る)。`due_on: null` は期限を全部消す (時刻も)。
  - **`due_on` だけの `PATCH` (古い端末)**: 時刻付きのタスクなら、同じ壁時計の時刻のまま新しい日付へ動かす (時刻は消さない)。
  - `subtasks`: `[{id?, title, done?}]` で全体を置き換える。知っている `id` はそのまま、無い・知らない `id` は新しい id。題名は空白をまとめ、空なら 400 (422)。51 個以上は 422。
  - `rrule`: `null` で繰り返しをやめる。期限が無い、規則が範囲外、`kind = review` は `400 task_invalid_rrule`。期限を消すときに `rrule` が残るのも 400 (一緒に `rrule: null` を送る)。
- `PATCH /tasks/{id}/subtasks/{subtask_id}` `{title?, done?}` → `TaskOut`。無い id は `404 task_subtask_not_found`。
- `POST /tasks/{id}/move` `{status?, column_id?, after_id?, before_id?}`: `status` を省略できるようにした (どちらか 1 つは要る)。
  - `column_id` あり: その列へ (状態は列のもの。`status` も送るなら列と同じでないと `400 task_invalid_column`)。別のボードの列・無い列も `400 task_invalid_column`。組み込みの列の id も使える。
  - `status` だけ (古い端末): 状態が今と同じなら**今の列のまま** (古い端末の 1 つにまとめた列の中の並べ替え)、違えばその状態の組み込みの列。
  - 並び (`after_id` / `before_id`) は列の中で決める (§8 の規則のまま、「列」= 状態 + 列)。
- `PATCH /tasks/{id}` の `status` (チェックで完了・「対応を始める」): その状態の組み込みの列へ (今と同じ状態なら動かない)。
- `GET /tasks/columns?channel_id=` → `TaskColumnOut[]` (`{id, channel_id, name, status, builtin, position}`、左から)。行が無いボードは組み込みの 3 列 (未着手・進行中・完了)。メンバーでなければ `403 not_a_member`、DM・グループ DM は `400 task_channel_unsupported`。
- `POST /tasks/columns` `{channel_id, name, status, after_id?}` → 201 `TaskColumnOut` (作った列)。`after_id` 省略で右端。
- `PATCH /tasks/columns/{id}` `{name?, after_id?}` (`after_id: null` で左端へ)。組み込みの列もできる。
- `DELETE /tasks/columns/{id}` → 204。カードは同じ状態の組み込みの列の後ろへ (完了の列は前へ)、並びはそのまま。状態は変わらない (完了の通知・次の回は起きない)。組み込みの列は `409 task_column_builtin`。
- 列の操作は「投稿できるメンバー」(タスクと同じ。アーカイブ済みは `409 channel_archived`)。無い列・見られない列は `404 task_column_not_found`。

新しいエラー: `task_invalid_rrule` (400)、`task_invalid_column` (400)、`task_subtask_not_found` (404)、`task_column_not_found` (404)、`task_column_builtin` (409)、`task_column_limit` (409)。

### 11.4 繰り返しの細かいところ

- 完了 (PATCH の `status`・move・完了の列への移動) で `todo` / `doing` → `done` になり、`rrule` があり `next_task_id` が NULL なら、次の回を作って `next_task_id` に入れる。
  行はロックしているので、同時に 2 回完了にしても 1 件。完了 → 戻す → 完了でも 2 件目は作らない (`next_task_id` が残る)。最初から `done` で作ったタスクからは作らない。
- 次の期限: 規則をその回の期限の日から読み (`DTSTART` = その日)、期限の日より後で、完了した人のゾーンの今日以降の最初の回。`COUNT` は飛ばした回も数えて減らし、`UNTIL` を過ぎる・回数が尽きると作らない (繰り返しの終わり)。
  時刻付きなら同じ `due_tz` の壁時計の時刻 (夏時間をまたいでも 14:00)。
- 次の回に写すもの: ボード (チャンネル)・作った人 (`owner_id` は元のまま)・題名・メモ・担当者・サブタスク (全部未完了に、新しい id)・規則 (`COUNT` は残りの回数)・時刻のゾーン。
  写さないもの: 元のメッセージ / キャンバス (チップは最初の回だけ)・`client_task_id`・列 (次の回は組み込みの「未着手」の一番下)。`kind` はいつも `task`。
- 次の回は普通のタスク: `task.updated` を出し、担当者の期限の通知を付ける (ゾーンは元の回のその人の通知の行のもの、無ければ §8 の規則)。`task.assigned` (割り当てのプッシュ) は出さない (もう担当だった人たち)。
  未完了の 1000 件の上限は数えない (完了が上限で失敗しないように)。
- **戻したとき**: 作った次の回はそのまま残す (もう変えられているかもしれない)。要らなければ消す。戻した回をまた完了にしても次の回は作らない。
- **消したとき**: その回だけ消える。未完了の回を消すと次の回は作られない (= 繰り返しが終わる)。完了した回を消しても、作られた次の回は残る。繰り返しをやめるには未完了の回で「繰り返さない」(`rrule: null`)。
- 規則を変えると、その回とそれから作る回に効く (回ごとに規則を持つ。作り終えた回には効かない)。
- 古い端末 (M84 より前): 繰り返しは見えず (🔁 も無い)、完了にするとサーバが次の回を作り、`task.updated` で届く。

### 11.5 列の細かいところ

- 古い端末 (M84 より前) は `status` だけを見るので、足した列のカードは同じ状態の列にまとめて出る (並びは `position`。列ごとに振るので、まとめると混ざる)。古い端末の並べ替えは列を変えない (§11.3)。
- 「完了」に属す列が複数あってよい (例: 「完了」と「見送り」)。どれに入れても完了 (担当者の完了の通知 L9・次の回が起きる)。完了の列どうしの移動は状態が変わらないので何も起きない。
- ボードの完了は列を問わず最近 100 件 (§8 のまま)。「完了をすべて表示」は全部の完了の列に効く。
- イベント `task.columns.updated` `{channel_id, columns}` (列の全体) をチャンネルのメンバーに。列を消したときに動いたカードはそれぞれ `task.updated`。再接続でボードと一緒に読み直す。
- L9 (レビュー依頼): 依頼は DM か、チャンネルのボードのカード。列を足しても状態は 3 つのままなので、チップ (`依頼中 / 対応中 / 完了`)・完了の通知はそのまま動く。DM には列が無い。

### 11.7 M81 で決めたこと (サーバと Desktop / Web)

- **列はチャンネルのボードだけ**。自分用のリスト・DM (L9 の共有タスク) には列が無く、`column_id` はいつも null。
- M81 より前のサーバでは `GET /tasks/columns` が `/tasks/{task_id}` に当たって 422 になる。端末は 404 と 422 を「列なし」(組み込みの 3 列) と読む。
- 足した列の下の「＋ 追加」は、作成 (組み込みの同じ状態の列に入る) のあと `move {column_id}` の 2 回 (`POST /tasks` に列は足していない)。
- 「完了をすべて表示」は完了のカードが 100 件以上あるとき、カードのある完了の列それぞれに出す (どれでも同じ全件を読む)。
- 次の回の「今日」は完了にした人のゾーン (要求の `tz` → おやすみ時間のゾーン → Asia/Tokyo)。次の回の担当者の通知のゾーンは、元の回の通知の行のものを引き継ぐ。
- 期限の日付だけを動かすと時刻付きのタスクは時刻を保つ (古い端末の日付の変更で時刻が消えないため)。新しい端末は時刻を消すとき `due_at: null` を送る。
- ダイアログの規則の比較はカレンダーと同じ `ruleChanged` (規則を開いた日付で読み直して比べる)。期限を消すと繰り返しも消える (`rrule: null` を一緒に送る)。
- 列の名前は空白を 1 つにまとめる (1〜50)。名前は重なってよい。組み込みの列の名前は変えられるが、状態 (種類) はどの列も変えられない (変えると中のカードの状態が変わってしまうため、要るなら列を作り直す)。

### 11.8 スマホ (M84) に要るもの

iOS と Android の両方。サーバの変更は無し (M81 のまま)。

1. **読み取り**: `TaskOut` の `due_at` (ISO8601、UTC)・`due_tz`・`subtasks` (`[{id, title, done}]`、無ければ空)・`rrule`・`column_id` を省略可で足す。
   `MessageTaskOut.due_at`、`task.due` の `due_at` / `tz`、新しいイベント `task.columns.updated` `{channel_id, columns: TaskColumnOut[]}`。
   **`status` は今の 3 値のまま** (enum を変えない)。知らない列 id のカードは、その状態の組み込みの列に出す。
2. **ボード**: `GET /tasks/columns?channel_id=` (404 / 422 は組み込みの 3 列)。上部の切り替えを列ごと (名前と数、左から) にし、カードは
   `column_id` (null は状態の組み込みの列) で分ける。カードのメニューの「移動」は列の一覧 → `POST /tasks/{id}/move {column_id}`。
   列の操作 (切り替えの長押し、またはボードの ⋯「列を編集」): 追加 (名前と種類 = 未着手 / 進行中 / 完了)、名前の変更、左へ / 右へ (`PATCH {after_id}`、
   左端は `after_id: null`)、削除 (足した列だけ、確認「カードは『<組み込みの列>』へ移ります」)。投稿できない人には出さない。
   `task.columns.updated` で列を置き換え、再接続でボードと一緒に読み直す。足した列の「＋ 追加」は作成のあと `move {column_id}`。
3. **カード** (ボード・自分のタスク・ホームのタイル): 期限に時刻 (「10/9 14:00」、端末のゾーン。時刻を過ぎた未完了は赤)、「☑ 2/5」(全部済みは緑)、繰り返しの 🔁。
4. **フォーム**: 期限の日付の横に時刻 (iOS は `DatePicker` の `.hourAndMinute`、Android は `TimePicker`。「時刻なし」に戻せる)。時刻ありは
   `due_at` (端末のオフセット付き) と `tz`、時刻を消すのは `due_at: null`。期限があるときだけ「繰り返し」(カレンダーの M69 の部品をそのまま:
   iOS `UI/CalendarRecurrence.swift`、Android `ui/CalendarRecurrence.kt`、開始日 = 期限の日。レビュー依頼には出さない。「完了にすると、次の回のタスクができます」)。
   期限を消すときは `rrule: null` も送る。「サブタスク」: チェック・題名の編集・並べ替え・削除・追加。保存のとき変わっていれば全体を
   `subtasks` で送る (id は残す)。保存済みのタスクのチェックはその場で `PATCH /tasks/{id}/subtasks/{sid} {done}` (先に表示して、断られたら戻す)。
5. **カレンダー**: 期限のタスクの行に時刻 (「☐ 14:00 題名」)、日付だけのものの後に時刻の順。
6. **メッセージの下のチップ**: 「… · 10/9 14:00 まで」。
7. **通知**: アプリを開いている間の `task.due` は `due_at` があれば「14:00 が期限: 題名」(プッシュの本文はサーバが作る)。
8. 新しいエラーコード (`task_invalid_rrule` など 6 つ) は `apps/shared/errors.json` から生成済み (M81 で ErrorMessages を更新)。
9. テスト: Desktop の `tests/taskExtras.test.ts` の例 (列の振り分け・左へ / 右へ・期限の表示・フォームの差分) を移す。

### 11.9 M84 iOS で決めたこと (build 77)

- **読み取り**: `TaskOut` の `due_at`・`due_tz`・`subtasks`・`rrule`・`column_id`、`MessageTaskOut.due_at`、`task.due` の `due_at` / `tz` はどれも省略可 (M81 より前のサーバでは無い・空)。読めない値や形の違うサブタスクは捨てて、タスク全体は落とさない。`status` の enum はそのまま。
- **列**: `TaskList` に `columns` と `columnsSupported`。ボードを読むとき `GET /tasks/columns` も一緒に読み、404 / 422 は組み込みの 3 列 (id = 状態の名前。`columnsSupported` = false で列の編集は出さない)。それ以外の失敗はボードの失敗。`task.columns.updated` で置き換え、再接続はボードと一緒に読み直す。列を足す・変える・消したあとも自分で読み直す (イベントと同じ中身)。
- **切り替え**: 3 列は今の segmented、4 列以上は横に流せるカプセル (名前が切れないように)。名前と数 (完了の列は数なし)。知らない `column_id` のカードはその状態の組み込みの列に出す。
- **移動**: 「移動」は今の列以外の列の一覧。足した列・サーバの組み込みの列は `column_id` だけ、組み込みの 3 列 (古いサーバ) は `status` だけを送る。上へ / 下へは今の列のまま。足した列の「＋ 追加」は作成のあと `move {column_id}`。
- **列の編集**: 切り替えの横の ⋯ (と切り替えの長押し) →「列を編集」のシート。各列の ⋯ に 名前を変更 (アラート) / 左へ / 右へ (`after_id`、左端は `null`) / 削除 (足した列だけ、確認「カードは『<組み込みの列>』へ移ります」)。下に「列を追加」(名前と種類)。投稿できる人で、サーバが列に対応しているときだけ。
- **カード**: 期限は「今日 14:00」「10/9 14:00」(端末のゾーン。時刻を過ぎた未完了は赤)、🔁 は SF Symbols の `repeat`、「☑ 2/5」(全部済みは緑)。自分のタスクの行も同じ部品。
- **フォーム**: 期限の下に「時刻を設定」(9:00 から) / `DatePicker(.hourAndMinute)` /「時刻なし」。期限をなくすと時刻と繰り返しも消える (`rrule: null` を一緒に送る)。期限があるとき (レビュー依頼以外)「繰り返し」は M69 の `RepeatPickerSection` (開始日 = 期限の日、下に「完了にすると、次の回のタスクができます」)。規則の比較はカレンダーと同じ `ruleChanged`。「サブタスク」はチェック・題名・⋯ (上へ / 下へ / 削除)・「サブタスクを追加」。保存で変わっていれば全体を送る (空の題名は捨てる、id は残す)。保存済みのタスクの保存済みの項目のチェックはその場で `PATCH …/subtasks/{sid}` (先に表示、断られたら戻してエラーを出す)。保存の差分はチェックを送ったあとの状態と比べる (同じ項目を二重に送らない)。
- **読み取りだけのフォーム**: 時刻付きの期限、繰り返しの要約、サブタスクの一覧 (☑ / ☐)。
- **カレンダー・チップ・通知**: 「☐ 14:00 題名」(日付だけのものが先、次に時刻の順)、「… · 10/9 14:00 まで」(時刻を過ぎたら赤)、`task.due` に `due_at` があれば「14:00 が期限: 題名」。
- 新しいエラーコード 6 つは生成済みの `ErrorMessages` でそのまま日本語になる (テストで確認)。
- テスト: `TaskExtrasTests` (新旧の JSON、列の振り分けと 404 / 422 の組み込みの 3 列、左へ / 右へ、移動の本文、サブタスクのチェックと戻し、フォーム → 要求 (時刻・規則・サブタスク)、カード・チップ・カレンダー・通知の文言、新しい呼び出しの経路と本文)、`TaskSnapshotTests.testColumnsTimesRepeatsAndSubtasks`。

## 12. 締切 (L5、M85)

チャンネルの締切 (学会・奨学金・修論提出) はタスクの種類 `kind = deadline` にした (L9 のレビュー依頼と同じく別の仕組みを作らない)。
日付が必須・繰り返さない・チャンネルのボードだけ・`notice_days` (何日前に「締切」のボットがチャンネルへ投稿するか、既定 7 / 3 / 1 / 0)。
`GET /tasks/deadlines` が見出しのチップと「締切」一覧を支える。詳しくは docs/DEADLINES.md。
