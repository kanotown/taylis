# 添削・レビュー依頼 (L9、M63〜M64)

ROADMAP の L9 (LAB.md §F)。学生が原稿 (添付や Overleaf のリンク) を載せたメッセージに「レビュー依頼」を付け、依頼先 (教員) と
希望日を決める。メッセージの下に状態 (依頼中 / 対応中 / 完了) が出て、依頼先は自分宛ての依頼を一覧で整理できる。修論・学会の
締切前に教員へ 10 人分の依頼が集まるときに効く。

**状態**: §7 は全部推奨の案に決まった (2026-10-02)。M63 (サーバ 移行 0056 §8、Desktop / Web §9) と M64 (iOS build 64 §10、Android §11) は完了 (2026-10-02)。

## 1. 方針: タスク (M55) の上に作る

LAB.md の設計時は専用の表 `review_requests` を想定していたが、その後にできたタスク (M55、TASKS.md) が必要なものの大半を
すでに持っている。

| レビュー依頼に要るもの | タスクにあるか |
|---|---|
| メッセージから作る | ある (`source_message_id`、メニューの「タスクにする」) |
| 依頼先 (複数可) と割り当ての通知 | ある (担当者、`kind = task` のプッシュ) |
| 希望日と当日の通知 | ある (`due_on`、期限の日 8:00 に担当者へ) |
| 状態 (依頼中 / 対応中 / 完了) | ある (`todo` / `doing` / `done`) |
| 自分宛ての一覧 | ある (「自分のタスク」の「自分の担当」) |
| **DM での依頼** (学生 → 教員の DM) | **無い**: DM のメッセージから作ると個人用になり、相手に見えない |
| **メッセージの下の状態** | **無い**: タスクは元のメッセージを指すが、メッセージ側には何も出ない |
| **自分が出した依頼の一覧** | **無い** |

そこで、別の仕組みは作らず、**メッセージに付いたタスク**を 3 か所広げる。レビュー依頼は「依頼先を担当者にしたタスク」で、
画面の言葉だけ変える。研究室以外の「この投稿の対応をお願い」にもそのまま使える。

## 2. 変えること

### 2.1 DM でもメッセージのタスクを共有する

- DM・グループ DM のメッセージから作るタスクに、**担当者として DM のメンバーを付けられる**ようにする。担当者がいるタスクは
  その DM のメンバー全員に見える (`tasks.channel_id = DM`)。担当者がいなければ今までどおり個人用。
- DM にはボード (「タスク」タブ) は作らない (TASKS.md §2 のまま)。DM のタスクが出るのは、メッセージの下 (§2.2)、「自分の
  タスク」(担当・依頼)、カレンダー。
- 権限は共有のタスクと同じ (DM のメンバーが見る・直す。消すのは作った人・担当者・管理者)。

### 2.2 メッセージの下に状態を出す

- `MessageOut.tasks: [{id, kind, status, assignee_ids, due_on, owner_id}]` (そのメッセージから作られ、消されていないタスク。多くても
  数件)。無いときは空の配列。
- タスクの作成・状態・担当・期限の変更・削除で、元のメッセージの `updated_seq` を進め、`message.updated (change = "tasks")`
  を出す (回収 `collection` と同じ流れ、SYNC_PROTOCOL §6)。これで切断中の変化も差分 (§7.3) で届く。題名・メモだけの変更では
  出さない (メッセージの下には出ないため)。
- 端末はメッセージの下に 1 行のチップを出す: 「レビュー依頼 · 加納 · 依頼中 · 10/9 まで」(完了は「完了」で灰色、期限を過ぎた
  未完了は赤)。押すとタスクの詳細。依頼先なら詳細に「対応を始める」「完了にする」の大きなボタン。
- チップの言葉は種類で分ける (§7 の 3): `tasks.kind = review` は「レビュー依頼」、`task` (「タスクにする」で作ったもの) は「タスク」。

### 2.3 依頼の入口と一覧

- メッセージのメニューに「**レビューを依頼**」(「タスクにする」の隣)。作成フォームは「タスクにする」と同じで、題名は
  「レビュー: <本文の抜粋>」、担当者 (依頼先) の選択を先に出し、期限の欄は「希望日」。チャンネルでも DM でも使える。
- 「自分のタスク」に「**自分が依頼した**」を足す: 自分が作り、自分以外が担当のタスク (完了は最近 50 件)。
  `GET /tasks/mine` に `requested` を足す (今の `personal` / `assigned` と並べる)。
- 依頼先の側は今の「自分の担当」で足りる。並びは期限の近い順 (期限なしは後ろ)。

## 3. API の変更 (`/api/v1`)

- `POST /tasks` / `PATCH /tasks/{id}`: DM のメッセージからのタスクで `assignee_ids` を受け付ける (DM のメンバーに限る。
  それ以外は `400 task_invalid_assignee`)。
- `MessageOut.tasks` (§2.2)、`message.updated` の `change = "tasks"`。
- `GET /tasks/requested` (自分が依頼した。§8 で `GET /tasks/mine` の応答を変えない形にした)。
- 新しい表は無し。移行 0056 で `tasks.kind` (`task` / `review`、既定 `task`。`POST /tasks` で指定、`TaskOut.kind`) と、
  `MessageOut.tasks` のための索引 `(source_message_id) WHERE deleted_at IS NULL` を足す。`tasks.channel_id` に DM が入るように
  なる。

## 4. 通知

- 依頼先へ: 既存の割り当ての通知 (「〇〇 がタスクを割り当てました」) を、`kind = review` では「〇〇 がレビューを依頼しました:
  題名」にする。
- 依頼した人へ (`kind = review` だけ): 依頼先が**完了にしたとき**だけ「〇〇 がレビューを完了しました: 題名」(新しい通知。
  「対応中」では出さない)。
  プッシュの設定は「タスク」のオン/オフに従う。
- 希望日の通知は既存の期限の通知 (当日 8:00、担当者へ) のまま。

## 7. 決めたこと (2026-10-02、全部推奨の案)

| # | 項目 | 決めた案 | 採らなかった案 |

## 8. 実装で決めたこと (M63 サーバ)

- **`GET /tasks/requested`** を足した (設計は `GET /tasks/mine` の応答に足す案だったが、配列の応答の形を変えると古い端末が読めない)。
  自分が作り、自分以外の担当者がいる共有のタスク (DM を含む)。未完了は期限の近い順 (期限なしは後ろ)、完了は最近 50 件。
- **DM のタスク**: `channel_id = DM` で作れるのは、その DM のメッセージから作るときだけ (`source_message_id` 無しは
  `400 task_channel_unsupported`)。DM のボード (`GET /tasks?channel_id=DM`) は今までどおり 400。担当者は DM のメンバーだけ。DM の
  タスクも「自分の担当」・カレンダー (`/tasks/due`)・`requested` に出る (タスクが読む会話に DM を含めた)。
- **`kind = review` はメッセージから作るときだけ** (`400 task_invalid_source`)。`TaskOut.kind`、`task.assigned` の `kind`。
- **`MessageOut.tasks`**: そのメッセージから作られ、同じ会話にある (共有の) 生きたタスク、作った順。個人用 (自分のリスト) は
  載せない。作成・削除・状態・期限・担当の変更でメッセージの `updated_seq` を進めて `message.updated (change = "tasks")`。題名・
  メモ・並べ替えだけでは出さない。読み込みは既存の索引 `tasks_source_idx` で足りたので、移行 0056 は `tasks.kind` の列だけ。
- **プッシュ**: `kind = review` の割り当ては「〇〇 がレビューを依頼しました: 題名」。依頼先 (作った人以外) が完了にすると、作った
  人に `task.review_done` →「〇〇 がレビューを完了しました: 題名」(プッシュの kind は `task`、設定は「タスク」に従う)。作った人
  自身が完了にしたときは出さない。

## 9. 実装で決めたこと (M63 Desktop / Web)

- **入口**: ホバーのバーの「その他」 (⋯) と長押しのシートの「タスクにする」の次に「レビューを依頼」。出すのはその会話のタスクを足せるとき
  (チャンネルはボードの規則、DM・グループ DM はメンバーでアーカイブされていない)。送信前・送信中のメッセージには出さない。
- **作成フォーム** (TaskDialog を共用): 題名「レビュー: <1 行の抜粋>」(全体で 200 文字まで)、依頼先 (会話のメンバー。自分は出さない)
  を最初に、メモ、希望日。状態の切り替えと「追加先」は出さず、「<会話> で共有」と出す。依頼先が 0 人なら「依頼する」を押せない。
- **DM の「タスクにする」**: 「追加先」の代わりに担当者 (DM のメンバー) を出す。選べば `channel_id = DM` の共有、選ばなければ
  今までどおり自分のタスク (フォームにそう書く)。
- **チップ** (MessageTaskChips): `MessageOut.tasks` だけから作る (担当者の名前は rowsVersion で追う)。1 行は
  「種類 · 担当者 (3 人まで、残りは「他 N 人」) · 状態 · M/D まで (今日は「今日まで」、完了なら出さない)」。完了は灰色、期限切れの
  未完了は赤。押すと `GET /tasks/{id}` で読んでタスクの詳細。チャンネルに未参加で読むプレビューでは押せない。
- **詳細**: 担当者が自分で未完了の共有タスクなら上に大きく「対応を始める」(未着手のときだけ) と「完了にする」。押すと状態だけを
  送って閉じる。`kind = review` は状態を「依頼中 / 対応中 / 完了」、期限を「希望日」、担当者を「依頼先」と呼ぶ (ボードのカードの
  「進行中」の札も)。DM のタスクの所属は「<相手> との DM」。
- **「自分が依頼した」**: 「自分のタスク」の画面で「自分の担当」の次の節 (並びは期限の近い順、期限なしは後ろ、完了は「完了 (N)」に
  畳む)。カードに所属 (「#lab」・DM の相手) を出し、チェックは付けない (完了にするのは依頼先)。TaskHub に窓を足し、task.updated /
  task.deleted と再接続で更新する (`isRequestedByMe`: 自分が作った共有タスクで自分以外の担当者がいる)。`GET /tasks/requested` が
  無い古いサーバでは節を出さない。節の名前は今の「自分のタスク」「自分の担当」のまま (§5 の「個人用」への改名はしない)。
- **DM のタスクの居場所**: 「自分の担当」の DM の見出しは押せないラベル (ボードが無い)。カレンダーの一覧は DM の相手の名前
  (`taskPlace`)。通知から開くとき、DM のタスクは「タスク」の画面の上に詳細を開く (チャンネルの「タスク」タブには行かない)。
- **通知**: アプリを開いている間の task.assigned は `kind = review` なら「〇〇 がレビューを依頼しました: 題名」、新しい
  task.review_done は「〇〇 がレビューを完了しました: 題名」(どちらも DM なら「(#ch)」を付けない)。SYNC_PROTOCOL のイベント表に
  task.review_done を足した。
- 行の memo: 会話の状態 (アーカイブ・投稿制限) はメモ化した行の props に無いので、「レビューを依頼」の出し入れは行が描き直された
  ときに追いつく (サーバがもう一度確かめる)。チップの期限切れの赤も日付が変わった後の描き直しで付く。

## 10. 実装で決めたこと (M64 iOS)

- **`MessageOut.tasks`** は端末に保存するメッセージ (MessageState、SQLite の JSON) に持つ (回収 L6 と同じ)。無い・読めないときは空、
  読めない 1 件だけを落とす。`message.updated (change = "tasks")` はメッセージ全体の置き換えで反映される。
- **チップ**はメッセージの行 (MessageRow) の回収のチップの下に 1 件 1 行: 「レビュー依頼 · 加納 · 依頼中 · 10/9 まで」。担当者は
  2 人まで (「加納、佐藤 他 2 人」)、居なければ名前を省く。期限の当日は「今日まで」、完了なら期限を出さない。完了は灰色、期限を過ぎた
  未完了は赤。メッセージと一緒に届くので最初から最終の高さ (DEVELOPMENT.md §5)。押すとタスクの詳細 (シート。手元に無ければ
  `GET /tasks/{id}`)。
- **詳細**: 担当者 (自分) で未完了なら上に大きなボタン (未着手は「対応を始める」と「完了にする」、進行中は「完了にする」)。押すとすぐ
  `PATCH status`。`kind = review` では状態を 依頼中 / 対応中 / 完了、担当者を「依頼先」、期限を「希望日」と呼ぶ。
- **「レビューを依頼」**は「タスクにする」の次。出すのは依頼を共有できる会話 (追加できるボード、アーカイブされていない DM) だけ。
  フォームは依頼先 → 題名 (「レビュー: <抜粋>」、200 文字まで) → メモ → 希望日。追加先は元のメッセージの会話に固定、状態は出さない
  (依頼中で始まる)。**依頼先は 1 人以上必要** (「依頼先を選んでください」。依頼先の無い依頼は意味が無いため)。
- **DM の「タスクにする」**: 追加先の選択は出さず、担当者 (DM のメンバー) を選ぶとその DM の共有タスク、選ばなければ自分のタスク。
  DM のタスクは DM にいる間は変更できる (アーカイブ済みは不可)。DM のメンバーは手元の `dm_user_ids` から選ぶ。
- **「自分が依頼した」**は「タスク」画面の一番下 (「自分のタスク」「自分の担当」の後。今の並びを崩さない)。未完了は希望日の近い順
  (無しは後ろ)、完了は後ろ。行の下に「レビュー依頼 · #lab」、DM は相手の名前。イベント (task.updated / deleted) と再接続で更新し、
  `/tasks/requested` が無いサーバ (404) では節を出さない。「自分の担当」の DM の見出しは相手の名前で、押せない (ボードが無い)。
- **通知**: 開いている間の task.assigned は `kind = review` なら「〇〇 がレビューを依頼しました: 題名」、task.review_done は
  「〇〇 がレビューを完了しました: 題名」(DM は「(#…)」を付けない。プッシュと同じ)。DM のタスクのプッシュを押すと「タスク」画面で
  そのタスクを開く (DM にボードが無いため)。

## 11. 実装で決めたこと (M64 Android)

- **保存**: `MessageOut.tasks` はメッセージの行 (Room の `messages` の JSON) にそのまま入れる。回収 (`collection`) と同じで、表も Room の版も
  変えない (前に保存した行は空の配列で読む)。`message.updated (change = "tasks")` は既存の流れで行を置き換えるだけ。
- **長押しのメニュー**: 「タスクにする」の次に「レビューを依頼」。出すのは共有のタスクが作れる会話だけ (投稿できるボード、参加している DM)。
  フォームは既存のタスクのフォームのレビュー版: 見出し「レビューを依頼」、「依頼する場所」(その会話で固定、自分のタスクは選べない)、
  依頼先を先頭 (自分は出さない。1 対 1 の DM は相手を選んだ状態で開く)、依頼先が 0 人なら「依頼先を選んでください」、「希望日」、
  状態は 依頼中 / 対応中 / 完了。ボタンは「依頼」。
- **DM の「タスクにする」**: DM のメンバーを担当者に選べる。選べばその DM の共有タスク、選ばなければ今までどおり個人用 (追加先の表示が
  切り替わる)。DM のタスクは DM のメンバーなら直せる (投稿制限は DM には無い)。
- **チップ**: 「レビュー依頼 · 加納 · 依頼中 · 10/9 まで」。名前は 2 人まで、残りは「ほか N 人」。担当者がいなければ名前を省く。完了は
  日付を出さず灰色、期限を過ぎた未完了は赤 (今日は「今日まで」で通常の色)。押すとタスクの詳細 (どの窓にも無ければ `GET /tasks/{id}`)。
- **大きなボタン**: 共有タスクの担当者には詳細の上に「対応を始める」(未着手のときだけ) と「完了にする」。押すと状態を変えてフォームを
  保存して閉じる (ほかの欄を直していればそれも一緒に送る)。
- **自分のタスク**: 「自分のタスク」「自分の担当」の後に「自分が依頼した」(`GET /tasks/requested`、画面を開いている間の窓で、task.updated
  で出入りし、再接続で読み直す)。未完了は期限の近い順 (期限なしは後ろ)、完了は「完了 (N)」に畳む。カードには場所 (DM は相手の名前)
  と状態 (依頼中 など) を出す。「自分の担当」の DM のまとまりも相手の名前で、押すとその DM を開く。レビューのカードの日付は「希望日」。
- **通知**: アプリを開いている間の `task.assigned` (kind review) は「〇〇 がレビューを依頼しました」、DM は会話名を付けない。
  `task.review_done` は「〇〇 がレビューを完了しました: 題名」。DM のタスクの通知を押すと「タスク」(自分のタスク) を開いて詳細を重ねる
  (DM にはボードが無いため)。カレンダーの行の DM のタスクは「DM」と出す。
